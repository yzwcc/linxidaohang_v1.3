# 导航到达判定修复包部署说明

版本：1.0.2-20260906

## 一、上传与解压

将 `sparkrobot-lingxi-pnc-arrival-fix-1.0.2-20260906.tar.gz` 上传到机器人 `/home/agi/`，然后执行：

```bash
cd /home/agi
tar -xzf sparkrobot-lingxi-pnc-arrival-fix-1.0.2-20260906.tar.gz
cd sparkrobot-lingxi-pnc-arrival-fix-1.0.2-20260906
chmod +x install.sh control.sh
```

## 二、安装

```bash
sudo bash ./install.sh
```

安装会自动完成：

1. 检查 ARM64 和正式导航目录。
2. 检查两个补丁文件并执行 Python 语法检查。
3. 将原 `navigation_client.py` 备份到 `/var/lib/sparkrobot/lingxi-nav-pnc-arrival-fix/backups/时间戳/`。
4. 原子替换导航客户端和 PNC 解析文件。
5. 只调用导航专用脚本重启 bridge，不重启语音、Java Agent、地图或灵心服务。

如果现场正式导航目录不是默认目录：

```bash
sudo env NAV_DIR=/实际导航目录 bash ./install.sh
```

如果导航专用脚本不是默认路径：

```bash
sudo env NAV_CONTROL=/实际路径/robot_local_navigation_v3.sh bash ./install.sh
```

## 三、安装后检查

```bash
sudo bash ./control.sh status
sudo bash ./control.sh doctor
```

正常时应看到：

- `navigation_client.py` 和 `pnc_response.py` 正常。
- `PNC 回验订阅` 已启用，类型为 `aimdk_msgs/msg/CommonTaskResponse`。
- 导航 bridge 正在运行。

若 bridge 启动时 PNC 话题尚未出现，程序每 2 秒自动重试订阅，不会因此退出；在回验话题恢复前继续使用原有里程计判定。

## 四、查看实时日志

```bash
sudo bash ./control.sh logs
tail -F /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log
```

导航到点时应出现类似日志：

```text
PNC 到达回验已启用：topic=/aima/pnc/pnc_task_response, type=aimdk_msgs/msg/CommonTaskResponse
PNC 回验：task_id=..., state=1, disposition=completed
```

## 五、回滚

先列出备份：

```bash
sudo find /var/lib/sparkrobot/lingxi-nav-pnc-arrival-fix/backups -mindepth 1 -maxdepth 1 -type d -printf '%f\n'
```

再使用完整备份目录回滚：

```bash
sudo bash ./control.sh rollback /var/lib/sparkrobot/lingxi-nav-pnc-arrival-fix/backups/时间戳
```

## 六、现场验收

先不要用真实客户任务长时间运行，执行以下只读检查：

```bash
source /opt/ros/humble/setup.bash
[ -r /home/agi/aimdk/install/setup.bash ] && source /home/agi/aimdk/install/setup.bash
ros2 topic type /aima/pnc/pnc_task_response
ros2 topic info /aima/pnc/pnc_task_response -v
```

类型应为 `aimdk_msgs/msg/CommonTaskResponse`，并且有发布者。随后在网页启动一个已有点位的导航，观察到点后是否直接进入讲解，而不是等待 120 秒后报路线无法到达。

## 七、注意事项

- `state.value=1` 是完成；`state.value=4` 是超时，不能当成成功。
- 本包不扩大到达半径，不会掩盖真正的定位或路径规划失败。
- PNC 失败、超时、手动接管等终态会立即结束当前导航并返回失败事件，避免继续无意义等待。
- 现场没有 PNC 回验话题时，保留原里程计兜底行为；应同时检查 ROS_DOMAIN_ID、AIMDK 环境和底层导航状态。
