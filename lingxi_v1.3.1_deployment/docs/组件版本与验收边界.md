# 组件版本与验收边界

## 版本关系

`灵犀 v1.3.1` 是本次完整离线交付套件的产品版本，不覆盖内部组件自己的版本号：

| 组件 | 版本 |
| --- | --- |
| 完整交付套件 | `v1.3.1` |
| AIMDK | `aimdk v1.1.0-gfaf4c94` |
| 灵犀导航运行组件 | `1.1.0-20261024-r18` |
| 灵心 AgentSDK | `1.4.0`，已包含在导航运行组件中 |
| 目标系统 | Ubuntu 22.04 ARM64、ROS 2 Humble |

导航 TAR 内已经包含网页、ARM64 Node、JRE 17、Python 导航、Java Agent、地图服务、语音兼容网关和对应源码，不需要另外下载 Maven、Node 或 Java 安装包。

地图、点位、任务和全局路径安全参数全部通过机器人 `3000` 网页控制台配置。`8002`、`18082` 是后台服务通信端口，不是用户配置入口。

## R18 验证边界

R18 已在开发机完成 AIMDK v1.1.0 接口字段/QoS 对照、导航适配回归、构建及归档离线审计。此前版本在机器人上的验证记录不代表 AIMDK v1.1.0 已在目标机器人编译、替换或运行验收；本次没有声称完成 R18 机器人实机验收。

## 尚需目标机器人现场验收

地图和机器人实际环境相关，不能通过复制安装包代替现场验收：

- 选择底层当前实际地图。
- 录入起点和导航点。
- 确认 `/slam/lidar_odom` 持续有数据。
- 自动重定位后核对实际位置和朝向。
- 急停可用且有人看护时测试短距离导航。
- 验证现实语音问答、讲解开始/暂停/继续/停止、到点讲解/动作/表情。

没有录入点位时 `point_names=[]` 属于正常未配置状态。没有 `/slam/lidar_odom` 时不得反复下发重定位或真实导航。R18 还须在目标设备完成 AIMDK v1.1.0 编译/导入、PNC QoS 发现、3000 一键启动和低速受控路线验收。

## 已知 AIMDK 模块边界

本 AIMDK 不包含以下可选 Python 模块：

```text
aimdk.protocol.mm.relocalization_pb2
ros2_plugin_proto.srv
```

导航 `1.1.0-20261024-r18` 已使用兼容路径，不应另外把它们当作必装依赖。

## 1.1.0-R18 AIMDK 适配与路径安全

`1.1.0-20261024-r18` 基于 AIMDK `v1.1.0-gfaf4c94`，保持 V1.3.1 网页“一键开启全部服务”链路和全局路径净空保护，并针对新 SDK 调整 PNC 请求 QoS 为 `BEST_EFFORT + VOLATILE`、响应 QoS 为 `BEST_EFFORT + TRANSIENT_LOCAL`。START 的 `target_pose_radius` 最小设为 `0.25 m`；STOP 仍发送 `0.0`。SDK 的 `reference_line` 字段仍用于净空路径下发。

本 R18 包还保留并修复以下路径安全和新机部署能力：

- 安装和服务启动时自动校正 ROS 日志、Java 日志及 PID 目录权限。
- SOC2 私钥固定为 `run:run 0600`，避免 OpenSSH 拒绝加载私钥。
- 网页重启机器人本机语音与唤醒服务时使用 `run` 运维账号。
- bridge 脚本使用共享组可维护的 `umask 0007`，避免不同服务账号无法读取 PID 文件。
