# 讲解启动语音接管修复与验证

用户已确认 1.0.8 的导航提示修复有效，但讲解启动仍有底层提示。因此本版保留导航路径，重点修复讲解启动回复的时序。

## 代码中确认的缺口

1. 1.0.8 的默认讲解命令先调用 `/task/match`，再发 SDK 接管，查询期间尚未接管讲解回复。
2. SDK 回复流在 `/task/start` 返回后才关闭。任务启动延迟或异常时，底层仍可能处于等待回复的阶段。
3. 旧专项测试主要断言最终没有输出成功/失败文本，没有要求 SDK 流在任务副作用前完成。

这三项是源码和协议测试能够确认的问题；没有新的现场日志或实机录音，不能据此断言厂商独立语音进程只存在这一种发声原因。

## 修复

默认开始命令在通过既有质量、唤醒及讲解保护检查后，先接管 SDK，再发送唯一中性输入回执“收到”并结束回复流，随后匹配和提交任务。自定义命令和模型判定的讲解请求在意图确定后、任务提交前完成相同处理。中性回执不根据 accepted 成功/失败切换，不表示任务已执行成功。

回复帧独立处理传输异常，不因为接管/完成帧异常重发任务，也不追加 SDK `onError` 或错误语音。跨回调重复事件共享一次中性回执和已有的物理控制去重；讲解保护阶段不会提前打断灵创。机器人本地 TTS 不额外播放这一回执，避免双路播报和打断讲解正文。

## 验证范围

- 使用真实 AgentSDK 1.4.0 回调和实际打包 JAR，检查接管、文本、流完成与任务 HTTP 请求的先后顺序。
- 默认命令、自定义命令、模型判定意图，文本/兼容音频回调，两种 TTS 路由，接受/拒绝/忙碌/无效任务/畸形响应/HTTP 错误及 SDK 逐帧传输异常。
- 普通问答、否定/引用/说明性问题、跨回调重复、防止重复动作、导航静默、暂停/继续/停止及灵创保护。
- 对不可变旧 1.0.8 JAR 运行同一新专项，确认旧版存在任务提交早于 SDK 流完成的缺口。
- 最终压缩包的 Linux 安装/回滚、LF 换行、SHA256、Bash 语法、源码与运行字节码一致性。

具体通过数量和归档哈希见交付目录 `交付验证结果.json`。本次未部署机器人，未做真实声音或机械运动验收。
