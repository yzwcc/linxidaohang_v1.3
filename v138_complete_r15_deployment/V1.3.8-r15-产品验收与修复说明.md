# 灵犀 V1.3.8 r15 产品验收与修复说明

## 基线与兼容范围

严格以 r14 完整包为基线，基线 SHA-256 为 `ac7f93f20d1ed2155e394b4bf216d8717476925d571582632d84b4081d05f0b0`。产品保持 V1.3.8，内部版本 `1.0.19-20261017-r15`。

r15 原样复用 r14 Java JAR、Python 导航/讲解/动作实现、AIMDK 压缩组件和知识库组件。仅在已复现的服务管理、在线状态和安装流程处修改，避免为修补部署问题引入不匹配的业务逻辑。

## 本次复现与修复

| 问题 | 复现证据 | 修复后的判断与行为 |
| --- | --- | --- |
| 地图服务停止仍显示在线 | 缓存地图列表后让真实地图 HTTP 返回 503，旧版在线值仍为 true | 地图在线状态单独读取实时 `/api/config`；保留地图缓存用于显示，不能用缓存跳过恢复 |
| 语音桥重复启动中断会话 | 重复/并发 start，旧版会重启健康语音进程 | 操作互斥，健康进程重复 start 保持 PID；显式 restart 仍重启 |
| 过期语音 PID 误停进程 | PID 文件指向无关的存活进程，旧版 stop 将其终止 | 校验实际语音模块命令行；不终止无关进程 |
| 外部占端口误报语音就绪 | 无关监听器占用端口，旧版 start 能返回成功 | 检查归属，语音模块 PID 与 HTTP `/health` 同时满足才就绪 |
| 导航状态相信无关 PID | 地图退出后写入无关的存活 PID，旧版 status 仍成功 | 状态使用组件身份与真实 HTTP 接口检查 |
| AIMDK 模块存在但接口缺失 | 空 `aimdk_msgs.msg` 可被旧预检接受 | 明确导入导航、语音、动作所需消息及服务；可选 PNC 回验类型不强制要求 |
| AIMDK 切换失败丢失旧目录 | 模拟新目录 mv 失败，旧版已删除旧安装 | 切换前保留旧目录，切换或最终校验失败时恢复，成功后仍保留旧版备份 |

上述行为均先在旧逻辑复现失败，再验证修复。测试中的 ROS/动作/系统命令对端为隔离模拟，不向实际机器人发送指令。

## 保留的历史修复

保留 r11–r14 的 JAR/共享组权限、日志和 PID 目录权限、ROS source 的 nounset 兼容、网页启动预算与并发合并、部分网关离线处理、当前 Java PID 绑定的认证状态、连续导航及可选 PNC 兼容、讲解任务保存、取消/过期启动回执归属、知识库筛选、灵心 ASR 文本输入和模型故障恢复、唤醒门控与灵创保护。

普通动作保留模型优先、否定/转述保护、有限模型离线补偿；动作等待至少 15 秒。接受、拒绝、未确认三种结果分别处理，动作发出后缺少确认不自动重发。没有恢复强制 accepted 或吞掉真实错误的旧方案。

## 针对用户问题的验收

| 用户场景 | 自动化检查 | 实机仍需核对 |
| --- | --- | --- |
| 网页一键启动拉不起服务 | HTTP 超时、部分离线、失败重试、并发启动和真实 Linux 模拟进程启停 | 本机账号权限、SOC2 网络、厂家服务 |
| 无法与大模型交互 | 模型超时/故障恢复、文本请求、当前进程认证状态与旧状态拒绝 | APP 配套密钥、Ark 权限、实际平台连接 |
| 语音“带我去某地点”无执行 | 模型意图和已保存点名精确匹配的离线补偿、歧义/未知地点拒绝 | ASR 实际文本、地图/定位、底层路径规划 |
| 动作完成却播报失败 | 接受/非零拒绝/确认超时/延迟/不重发、否定与转述用语 | 当前厂家动作回执及肢体效果 |
| 任务保存/讲解时序 | 数据存储、兼容迁移、等待/打断/恢复、取消与执行权属；浏览器保存刷新 | 实机语音结束事件和现场连续任务 |
| 降噪和拒识 | 已有唤醒/会话/方向证据/语义策略与 Java SDK 打断事件绑定 | 麦克风阵列、AEC、实际噪声和正面方向识别 |

动作接受时不应播报 `motion=1003, area=2，机器人动作服务拒绝请求……`。真实拒绝仍会提示“这个动作请求暂未被接受，请稍后再试”；确认丢失则提示“暂未收到动作确认，请先观察机器人状态”。这些提示不等于物理动作已完成。

## 交付检查方式

最终完整包单独解压验证外层清单、导航组件清单和运行文件清单，检查 LF 换行、JAR 主类、ARM64 运行时和源码可重建产物。运行完整 TypeScript/Python/Java 回归、Linux 语音进程和 AIMDK 失败恢复场景，以及全新安装、r11–r14 更新、重复安装、回滚、客户配置/地图/任务保留验证。

浏览器使用隔离 HTTP 样例验证 320/390/1440 像素布局、图片、任务保存刷新、等待值范围和启动失败重试；另用真实 Node 路由与 Python HTTP 服务串联，核对 0/5/45/300 秒、讲解文字和命令词落盘后重新加载，错误点位/超范围等待不能覆盖已保存数据。该隔离存储检查不代替机器人账号的现场权限验收。最终数量、结果和归档 SHA 见外部《交付验证结果》及 JSON 记录。
