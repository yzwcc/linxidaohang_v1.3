# V1.3.8 r20 讲解首点修复增量部署说明

版本：`1.0.0-20261022`

## 1. 适用范围

本包针对“启动讲解任务时，概率性不去第一个启用点位，直接执行第二个点位”。
适用于已安装 V1.3.8 r20 完整包的机器人，release 为
`/opt/sparkrobot/lingxi-nav/releases/1.0.20-20261021-r20`。

安装器会核对当前 release、原 bridge、navigation_client、控制脚本及运行清单。
其他版本、未知现场修改或不一致清单会被拒绝，不会强行覆盖。
若现场并非 r20，请保留检查输出以匹配正确基线，不要修改安装器绕过检查。

本次未连接、部署或驱动现场机器人。已通过模拟事件和 r20 讲解流程回归，
现场首次使用仍需核对实际点位顺序。

## 2. 修复内容

1. 导航请求尚未受理时，原逻辑可能把当前点记为失败并进入下一点。现在重试当前点；
   重试用尽则暂停在当前点，网页可点击继续，不会把尚未出发当成走完首点。
2. 每次任务、步骤及导航尝试绑定独立代次；过期回调与返回值不会推进新任务。
3. 并发启动只允许一个请求占用任务状态，防止网页与语音同时启动相互覆盖。
4. 启用的步骤没有点位或引用失效点位时，明确拒绝启动，避免静默过滤首点。
5. 日志增加任务代次、步骤代次和导航会话，便于定位偶发问题。

真正已受理后发生的导航超时/不可达，仍遵循 r20 原有的继续后续步骤策略；
配置为禁用的步骤仍不执行。若只有这种真实失败，日志会记录 failed_steps，
不能仅凭“到了第二点”认定为首点被竞态跳过。

只更新 bridge Python 文件和对应运行清单；保留 r20 原有底层成功/失败播报抑制逻辑。
不重装或编译 AIMDK，不更新 Java、地图、点位、任务配置、密钥、知识库及灵创资源。

## 3. 上传和检查

将以下两个文件上传到机器人的 `/home/run/`：

- `sparkrobot-lingxi-v1.3.8-tour-first-step-fix-1.0.0-20261022.tar.gz`
- `sparkrobot-lingxi-v1.3.8-tour-first-step-fix-1.0.0-20261022.tar.gz.sha256`

在网页中停止讲解任务和导航，确保机器人静止。安装时不要同时操作网页或发起语音任务。
无需停止 Java/灵心服务。执行：

```bash
cd /home/run
sha256sum -c sparkrobot-lingxi-v1.3.8-tour-first-step-fix-1.0.0-20261022.tar.gz.sha256
tar -xzf sparkrobot-lingxi-v1.3.8-tour-first-step-fix-1.0.0-20261022.tar.gz
cd /home/run/sparkrobot-lingxi-v1.3.8-tour-first-step-fix-1.0.0-20261022
sudo bash ./install.sh --check
```

看到“检查通过”后安装；如果检查报错，请不要继续安装。

```bash
sudo bash ./install.sh
```

安装器自动备份、更新、校验并恢复安装前的导航服务运行状态。
如果安装前全部停止，安装后仍停止，可在网页点击一键启动。
部分服务运行、活动讲解任务或活动导航会阻止安装。
启动失败会尝试自动恢复本次备份；重复安装相同补丁不会再次重启。
若自动恢复也失败或发现其他程序同时修改文件，安装器会明确报错并保留备份，不会输出安装成功。
压缩包内外的校验清单、Shell 脚本均使用 LF 换行，不需要 sed 处理。

## 4. 安装后检查

```bash
sudo -u agi /opt/sparkrobot/lingxi-nav/current/scripts/navigation_control.sh status
sudo sparkrobot-lingxi-internal doctor
curl -fsS http://127.0.0.1:18082/nav/status | python3 -m json.tool
sudo python3 - <<'PY'
import json
from pathlib import Path
p = Path("/opt/sparkrobot/lingxi-nav/current/payload-manifest.json")
print("tour_first_step_fix=" + str(json.loads(p.read_text()).get("tour_first_step_fix")))
PY
```

清单版本应输出 `tour_first_step_fix=1.0.0-20261022`。
如果安装前服务停止，启动后再执行状态/doctor 检查。

任务顺序验收：

1. 页面确认第一点启用、点位有效，并保存任务。
2. 机器人位于离首点明显较远的位置，启动任务；首先应导航到第一启用点。
3. 完成首点讲解、等待后再到第二点。连续执行数次，分别用网页和语音启动。
4. 停止后重新开始，应从首点开始；暂停后继续，应继续当前点。
5. 若准备阶段服务临时忙，应该重试当前点，不应立刻进入第二点。

实时查看：

```bash
sudo tail -n 120 -F /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log
```

首条 `Tour task step starting` 应为 `step=1/总数`；
`Ignoring stale tour navigation callback` 表示旧回调被拦截；
`retrying same step` 表示仍在重试当前点。真正超时/不可达仍会记录失败步骤。

## 5. 回滚

安装成功会输出事务备份路径，例如：
`/var/lib/sparkrobot/lingxi-tour-first-step-fix/backups/时间-随机后缀`。

停止网页中的讲解任务与导航后，在本增量包目录运行下面的命令，
把路径替换为安装器实际输出的路径：

```bash
sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-tour-first-step-fix/backups/实际备份目录
```

回滚校验所有备份和当前文件，保留回滚前运行/停止状态。
如果之后又安装了其他补丁，本包拒绝覆盖后续变更；请按后装先退的顺序处理。
