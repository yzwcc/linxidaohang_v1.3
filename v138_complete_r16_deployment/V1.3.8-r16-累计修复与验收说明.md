## 2. 保留的 r15 及之前能力

- 灵心处理音频并以 ASR 文本交给模型；知识库检索、模型恢复、语音意图和自定义开始讲解命令词。
- 连续导航、既有到达判定与可选 PNC 回验类型兼容、地图/点位/讲解任务保存。
- 讲解等待按无人交流时间计时、打断后安静恢复、灵创期间语音保护及结束恢复。
- 普通预设动作、灵创动作/表情/舞蹈接入、否定/转述指令保护、动作不重复提交。
- 网页一键启动协调、地图在线状态实时检查、语音桥幂等启动、PID 身份与端口健康校验。
- Java JAR 和目录访问权限、共享组、日志/PID/SSH 文件权限、ROS source 的 nounset 兼容。
- AIMDK 必需接口预检、暂存编译与失败恢复、ARM64 Java/Node 运行时、知识库服务独立安装。

与 r15 相比，实际业务运行 payload 仅改变应用 JAR；网页、Python 导航、SDK、AIMDK、Node/Java 运行时和知识库组件保留原字节。源码、回归测试、版本元数据、教程和完整性清单同步更新。

本包保持 V1.3.8 产品逻辑，不加入 V1.3.9 的循环次数或拥挤场景导航策略。

## 3. 成功与失败的边界

去掉低层矛盾播报不等于把失败伪装成成功。未知地点、未配置任务、真实忙碌等业务结果仍按实际回执处理；HTTP 故障和未知回执仍记录错误，不补发已提交控制。

默认本机播报配置下，导航/讲解先完成 SDK 回复，再调用本机 TTS。动作保留原有中断策略；普通问答的模型处理和 TTS 文本回退不回退到 V1.3.1。

本次参考的是用户 V1.3.1 r7 包内知识库安装后实际生效的 JAR。同一组 204 项协议检查，在实际参考 JAR 全部通过、旧 1.0.4 有 70 项通道差异，1.0.5 全部通过。这是协议证据，不能仅凭 Java 日志断定现场独立 SOC2/云端“抱歉”声音全部消失。

## 5. 现场签收

按对应完整部署教程安装后：

1. 网页一键启动，核对六个业务端口及当前进程的灵心认证/机器人在线状态，重复启动不重启健康语音会话。
2. 保存任务后刷新页面，核对讲解文字、开始命令词和 0～300 秒等待值。
3. 唤醒后测试“带我去已保存点名”和自定义开始讲解命令，各执行一次，不追加“抱歉”或失败话术。
4. 检查握手、比心、打招呼，只下发一次；不存在低层动作拒绝播报；否定指令不执行。
5. 测试普通/知识库问答、唱歌跳舞，确认没有多余“唱歌关闭”“请给空间”、无关自我介绍或非预期问答失败播报。
6. 验证连续讲解、等待、打断后恢复及灵创保护；同时保存实际日志和对应复现时间。

本地协议和隔离安装通过不能替代实机、真实云端和现场声学验收。本次未远程部署，没有新增硬件 DOA、AEC 或 RNNoise。
