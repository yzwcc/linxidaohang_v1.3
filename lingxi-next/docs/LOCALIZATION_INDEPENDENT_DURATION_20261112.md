# 定位与建图分别设置会话时长

## 现场触发条件

地图“11.12”的上一轮定位于 2026-11-12 14:47:17 正常退场，原因是实时定位沿用了建图的 300 秒会话上限。终端报告显示 stopReceived=true、failures=[]、清理完成；这次结束不能作为队列故障处理，也不能据此声称用户后续 A→B 移动已被记录。

用户后来报告已到 B 点，距离约 3.15 米，朝向基本不变。该路程只有现场估计，没有有效的同期定位轨迹，不能用于通过比例或导航验收。当前初始位置不得再假定为 A。

## 配置与行为

ARM64 live 配置新增可选 `localizationMaxSeconds`，范围 5–3600 秒。缺省沿用 `maxSeconds`；建图 `maxSeconds` 的 300 秒上限保持原值。部署配置选择建图 300 秒、定位 3600 秒；定位父进程提前 10 秒发起有序停止，为子进程清理保留时间。

子进程、ROS 被动订阅和定位管理器使用相同的独立上限。2 秒进度看门狗、启动期限、用户停止、代际隔离和清理确认仍生效。有限时长到期仍会使定位失效，现场验证必须从开始持续记录运行 ID、地图绑定、代际、时间戳和位姿，不能依赖结束后已撤销的位姿。

## 验证范围

离线回归验证配置范围、旧配置兼容、父进程工厂时长、越过旧 300 秒边界、正常到期清理、长会话立即停止和现有定位终端核验。时长测试使用可控时钟与合成 ROS 协议，不声称已实测连续运行一小时。

部署后需核验版本、配置、服务与地图哈希，再取得可靠的当前初值进行 A→B 路线验证。`physicalScaleValidated` 和 `navigationReady` 保持 false，直到有实际验证依据。
