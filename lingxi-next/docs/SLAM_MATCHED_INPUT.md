# 相同实时输入的 ARM64 独立回放

日期：2026-10-29。完成一次请求 20 秒的实际被动订阅，以及另一个全新 ARM64
进程对同一份回调输入的离线回放。没有重跑历史录包矩阵，也没有修改冻结组件。
本轮没有要求现场人员移动机器人，未独立确认采样期间机器人严格静止，
因此不把这段数据称作静态标定或精度采样。

**这次证明相同当前输入在两条计算路径中得到相同帧域和接近的数值输出，
并复现相同告警；不是标定、地图几何、实时性能保证或导航验收。**
现有 0.1.19 产品仍使用原生 AIMDK 后端，网页、APK、部署服务、AIMDK、地图、
模式和输入源均未修改，没有发送运动命令。

## 对照方法

- 新诊断包从已校验的 live bundle 复制全部依赖，并增加独立记录/回放工具。
  旧运行器、输入快照、工作线程、原生库、参数、外参和时间假设逐文件保持不变。
- 实时子类在同一个串行回调中先将完整 PointCloud2/Imu 序列化为 CDR，
  按消息顺序和相对单调纳秒追加到私有文件，再调用原有 worker 接口。
  记录失败或消息拒绝时整个诊断失败，不允许拿部分成功记录充作对照。
- 文件有版本头、连续序号、逐条长度/摘要和全文件提交尾标；
  限制 20,000 条、每条 8 MiB、合计 512 MiB、相对时间 65 秒。
  未完成、超限或损坏文件拒绝回放；不使用 pickle。
  同步记录会给实时路径增加开销，不能将其当作完全无干扰的测量。
- 实时订阅由原包装器创建独立 Context 和 SingleThreadedExecutor；
  只订阅传感器，不创建应用运动、地图或 TF 发布器。
  ROS 自身仍可能产生发现与参数事件流量。
- 回放进程不初始化 ROS、不建节点、不订阅 DDS。Humble 只用于反序列化 CDR；
  复用原消息快照和 SensorStream，按记录的逻辑到达顺序处理。
  没有实时等待或工作队列，**不是回放时延/吞吐验收**。
- 回放前核对整份文件，只把实时 worker 确实完成的 FIFO 前缀送入引擎。
  停止清队列的尾部单独计数，并继续校验文件尾标。
  本次完成全部 4,144 条，因此没有排除尾部。

两次进程 PID 不同，实际加载库摘要相同；实时原生入口由单个非生产者线程拥有，
回放由单个离线线程拥有。两边引擎创建和关闭各一次，实时线程已 join，
全部队列与流缓冲释放；进程都退出 0。外部 timeout 限时仍只是诊断保护，
不能替代生产进程监督或原生挂起恢复验收。

## 实际结果

| 项目 | 实时记录 | 独立回放 |
|---|---:|---:|
| 接收 / 送入前缀消息 | 4,144 | 4,144 |
| 点云 / IMU | 197 / 3,947 | 197 / 3,947 |
| 处理扫描 / 初始化 / 有效位姿 | 196 / 31 / 165 | 196 / 31 / 165 |
| 开头缺 IMU 覆盖 / 结束缺覆盖 | 1 / 0 | 1 / 0 |
| 插入原生 IMU | 3,930 | 3,930 |
| 停止丢弃 / 拒绝 | 0 / 0 | 不另建工作队列 |

完整私有记录为 157,715,530 字节，包含全部原始 CDR，不只采样点。
独立导出用 rosbags 逐条反序列化全部 CDR header，与实时观测数组逐个对应；
不只比较消息总数。扫描 header、算法时刻、初始化域、预处理点数和边缘化计数
两边完全一致，没有按结果挑选帧或删除不利区间。

165 个位姿未经 ICP、首帧对齐或尺度拟合，直接同坐标比较：
位置差 P95 约 `1.56e-12`、最大 `1.70e-12` 原始单位，
位姿矩阵元素差最大约 `1.67e-12`。
这是固定同输入的运行间差异，不是对现场真值的定位误差。
本次沿用扫描起点诊断假设，没有用这些差值批准它或否定另一假设。

实时点云/IMU 回调频率约 10.00/200.26 Hz，
点云回调进入至帧结果 P95 约 73.65 ms、最大 109.16 ms；
最长工作队列年龄约 182.65 ms。
这些数值包含新增记录开销，不含雷达至 DDS 传输、全局建图、前端或语音。
进程 RSS 峰值实时/回放约 254.90/191.03 MiB。

序列化和追加的混合消息开销在运行器内部计量为 P95 约 1.52 ms、
最大 7.85 ms。原始逐条开销样本本轮没有持久化，公开证据明确标记
这是自计量摘要，不能声称已独立复算这些分位数。
完整回调及帧结果时延则从私有数组重新计算。

## 告警与结论边界

两次原生日志各有 2 次 IMU prediction 告警，偏置幅度告警均为 0。
累计检查窗口同为 64、128；打印的旋转/平移/速度更优比例同为
`0.78/0.00/0.02` 和 `0.80/0.00/0.01`。
告警语义仍以固定源码核对为准，见 `SLAM_CALIBRATION_AUDIT.md`。

本次不使用实时订阅的离线进程也复现相同告警，说明告警并不要求
实时 DDS 接收/工作队列这个条件。不能反推“DDS 在任何情况下都无影响”，
也没有定位到某一项时间偏移、外参、偏置或算法参数。
两边一致更不能说明两边都对现场真值准确。没有关闭告警或调参把它消掉。
