# 独立建图进程监督组件

日期：2026-10-29。本轮新增进程生命周期组件及本地合成子进程检查。
没有连接机器人、采集新数据、初始化 ROS、加载 GLIM 原生库、
发送运动命令或修改现有服务。此前冻结的输入组件和诊断运行器未修改。

**这是独立后端的进程边界组件，不是机器人运行验收或完整产品接入。**
现有 0.1.19 产品仍使用原生 AIMDK 后端，安装包和 APK 没有重建。

## 接口与状态

`robot-slam/lingxi_slam/process_supervisor.py` 提供单次使用的
`ProcessSupervisor`。启动参数必须来自可信的本地组合层：
绝对可执行文件路径、明确的参数列表、工作目录、显式环境字典和新私有日志路径。
不会启动 shell，也不会默认继承管理 API 进程的环境。
此接口不接收网页请求、模型输出、运动指令或任意 ROS 发布请求。

组件仅支持 Linux，依赖独立 session/process group 和 `/proc`。
启动时创建 mode-0600 的新 stderr 日志，拒绝覆盖现有文件。
原生日志未来可能包含设备或几何数据，不能放入公开交付包或 Git；
本组件尚未实现日志轮换或操作系统级磁盘/内存配额。

状态为：

```text
new -> starting -> running -> stopping -> stopped
                   \--------------------> failed
```

任何实例都不能重新启动。失败不会自动重试或恢复旧任务。
调用方需保存并显式停止当前 owner；替换实例会得到新的随机会话编号。
`running` 只表示工作进程已报告运行，不表示已经得到有效地图、定位或导航能力。
所有 snapshot 的 `mappingReady`、`localizationReady`、`navigationReady` 均为 false。

## 健康 IPC

`process_protocol.py` 的 `HealthEmitter` 可直接接收现有 `SensorWorker.snapshot()`。
输出仅包括版本、会话、连续序号、本机单调时刻、工作线程状态、
已处理消息/扫描/位姿计数和固定故障码。
没有点云、位姿矩阵、机器人地址、模型凭据或控制接口。
stdout 是专用 JSON 行通道，业务/原生日志必须走单独的 stderr 私有文件。

每条记录有严格字段集合、字节上限、整数计数范围和顺序检查。
旧会话、重复序号、计数回退、过期/未来时刻、截断或非协议输出会导致故障关闭。
健康时刻只适用于同机同单调时钟域，不是传感器时间同步协议。

心跳或工作线程仍在运行的声明不能重置处理进度时限：
只有已完成消息数真正增加才更新进度时刻。
停止后到达的活动状态单独退役计数，不会让 owner 返回运行状态。
该通道不输送地图/位姿结果，因此尚不能替代后续数据通道的会话校验。

## 超时与退出

默认策略是启动 10 秒、实际处理无进展 2 秒、正常关闭 4 秒，
TERM 等待 1 秒、KILL 等待 1 秒，监督循环间隔 50 ms。
这是可配置的组件策略，不是实测性能承诺，也没有批准为 X2 生产阈值。
操作系统进程创建本身可能不可及时中断，不在本机监督线程的硬时限保证内。

停止只向当前子进程的私有 stdin 写入 `stop`，不是机器人停止或急停命令。
子进程须关闭自己的工作线程/原生资源，报告 stopped，并正常退出。
单独收到 stopped 或看到父 PID 消失都不算完成。

启动/进度/关闭超时、协议错误或意外退出后，监督器会处理本实例通过
`start_new_session=True` 创建的独立进程组，先 TERM，必要时 KILL。
它不会向厂商服务的共享进程组发信号。
父进程退出但派生进程仍存活时也会清理并保留故障状态。
关闭确认包含 leader 回收、私有管道关闭、监督线程 join，
以及 `/proc` 中自有进程组没有可执行的存活成员。
不把待系统宿主回收的 Z/X 成员当作仍在执行的引擎。

最终仍需在真实部署的 systemd control group 下验证父监督器异常退出、
宿主回收、资源配额及磁盘故障。当前不宣称处理主动脱离自有 session 的子进程。

## 本轮验证

`tools/tests/fixtures/slam_process_child.py` 是明确标记的合成对端，
不导入 ROS 或真实 SLAM 引擎。
其中一组在真实子进程中运行原有 `SensorWorker`，输入仅为合成消息，
引擎则是内存中的测试替身。模拟阻塞不针对任何厂商崩溃或漏洞。

22 项新增检查覆盖：

- 健康协议字段、完整行、计数类型、序号及部分写入处理。
- 正常处理、私有停止确认、停止后的迟到状态和实例不可重启。
- 不处理输入但继续心跳、未完成启动、关闭卡住及忽略 TERM 后的 KILL。
- 非零退出、错误会话、过期状态、计数回退和固定失败码。
- 主进程退出后派生进程仍占用管道的清理。
- 不继承父环境、mode-0600 日志、已有文件保留和监督线程启动失败清理。
- 原有工作线程配合合成引擎正常处理，以及创建、处理、关闭阶段阻塞后的清理。
- 连续 10 个全新会话的描述符/监督线程释放，以及两个并发 owner 互不误杀。

这些检查不构成 ARM64 原生恢复、完整地图保存/损坏恢复、
长时运行、语音并发或实机导航验收。最终完整工具检查：
Linux 523 项全部通过、无跳过；Windows 220 项通过、303 项因环境依赖明确跳过。
Python 编译检查与 Git 空白检查通过。没有修改前端、Java 或 Android，
没有用工具测试替代这些产品构建和最终验收。

## 后续接入

后续应将独立原生后端及被动传感器入口放入专用子进程，
保留 stdout 健康通道，并在启动前校验实际库、配置和传感器 profile。
目前没有用合成对端代替真实后端，也没有给现有诊断运行器自动加装此监督器。
地图保存事务、输出新鲜度、故障后的地图不可用状态和人工重新开始流程，
仍需与管理 API 一起完成并验证。

现场静止对照及几何/标定确认仍待现场条件明确；
监督进程健康不能代替这些条件，更不能自动打开移动权限。
