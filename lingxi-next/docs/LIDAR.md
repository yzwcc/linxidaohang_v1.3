# 实时激光扫描视图

扫图页直接绘制激光采样点的 XY 俯视图：蓝灰点迹、机器人朝向、近期轨迹和米制比例尺。
没有使用栅格图生成点云，也不将保存地图的栅格渲染作为雷达数据替代。
地图管理和导航仍使用 AIMDK 保存的地图，点位坐标和原生导航流程保持独立。

## 现场配置

在机器人上确认实际话题，不能照搬其它机型或旧版的话题名：

```sh
ros2 topic list -t
ros2 topic type /现场雷达话题
ros2 topic hz /现场雷达话题
ros2 run tf2_ros tf2_echo map base_link
```

在 `/etc/lingxi-next/robot.env` 中设置以下一种来源：

- `AIMDK_SCAN_TOPIC`：`sensor_msgs/msg/LaserScan`。
- `AIMDK_POINTCLOUD_TOPIC`：`sensor_msgs/msg/PointCloud2`，XYZ 字段支持 FLOAT32/FLOAT64、
  大小端和有行填充的组织点云。两种来源都配置时优先 PointCloud2。

`AIMDK_LIDAR_FIXED_FRAME` 指定 SLAM 的固定坐标系，`AIMDK_BASE_FRAME` 指定机器人机体坐标系。
默认值 `map` / `base_link` 必须与现场 TF 树核对。已在固定坐标系下的点云无需重复变换。
`AIMDK_MAP_TOPIC` 仅用于总览/导航的可选栅格显示，不再是开始建图的必要条件。

## 数据与显示

桥接使用激光消息采样时刻查询 TF，最多等待 50ms 以容纳传感器与 TF 发布的轻微时序差，
执行完整三维刚体变换，网页显示 XY 俯视投影。
机器人箭头也使用同一时刻、同一坐标系的机体 TF，不把未经换算的里程计直接叠加到点云上。
缺 TF 时显示原始雷达坐标和明确提示，不累计不同坐标系的点迹；缺机体 TF 时不伪造机器人位置。
不进行扫描内部逐束去畸变；若厂商发布已去畸变/已配准点云，可直接订阅对应 PointCloud2。

支持放大、缩小、适应范围、拖动和清除累计点迹。近期累计仅在固定坐标系下启用，
保留最多15秒、50000点；每帧最多8000点，以固定间隔抽样控制传输与移动端内存。
建图开始、地图切换和桥接重启会重置点迹上下文。无效距离、NaN、Infinity、
过期采样和越界二进制布局会被过滤或拒绝。

雷达流独立使用已配对认证的 `/api/v1/lidar/events`，上限5Hz，只在扫图页打开时订阅。
管理状态保持原有独立通道；慢客户端丢弃中间帧，不积压历史点云。
连续2秒没有新扫描时清空显示并标注断流。演示模式使用独立模拟激光射线，与真实雷达明确区分。

客户端对断开、错误和无法解析的雷达消息统一处理，每个连接只安排一次重试。重试间隔
从500毫秒指数增长，最多15秒；连续连接30秒后恢复初始间隔。连接建立后连续2.5秒
没有雷达流消息，也会关闭静默连接并重试；服务端明确发送的“暂无新数据”仍是有效消息，
不会误判为断网。离开扫图页或断开机器人后清理 socket 和重试/检测计时器，旧 socket
的迟到消息不再进入画布。恢复连接仍沿用配对会话；会话到期时必须重新配对。

## 实机验收

使用外置遥控器短距离移动并转向，核对当前帧、墙面点迹、机体箭头和轨迹方向一致。
停止雷达发布/断开桥接后确认2秒内提示断流；恢复后只显示新数据。
建图启动与地图切换后确认旧点迹被清除；切换不同坐标系时不得把旧点迹叠加回来。
最后执行保存、AIMDK 查询和地图重载。当前工作站验证使用模拟雷达，尚未替代这些实机检查。

地图 TF 尚未就绪，没有执行上述移动或建图验收。话题、字段布局、状态 QoS 与依赖
检查见 TARGET_INSPECTION.md，不能把该静止采样当成端到端扫图验收。
