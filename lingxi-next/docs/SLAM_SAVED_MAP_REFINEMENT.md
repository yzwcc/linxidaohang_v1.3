# 保存地图的独立全局优化验证

日期：2026-10-31。范围为电脑端、普通用户、无 ROS 的离线验证。
本轮没有连接机器人、读取实时传感器、启动新采集或发送运动指令。
现场地图、配置、坐标、轨迹、图片和完整日志均留在忽略入库的私有目录。
源码摘要、私有报告摘要与匿名统计见 `slam-saved-refinement-evidence.json`。

## 为什么做这一步

当前实机调试建图适配器 `tools/glim-mapping/mapping.cpp` 使用
`SubMappingPassthrough` 与 `GlobalMappingPoseGraph`，是短序列保存/重载验证版，
不是已经验证的生产建图后端。其配置的回环最小行程为 50 个原始坐标单位，
适配器在抵达此边界时主动停止，防止进入未观察的异步回环搜索。
不能把 50 当作已经校准的米数，也不能通过删除边界检查来宣称回环适配完成。

近期现场保存地图有 8 个子图，但序列化的匹配代价因子数为 0。
页面的高度筛选和主体视口能改善显示，不能证明几何误差已修复。
因此先独立评估上游完整全局优化器，不改写旧适配器、旧报告或实机地图。

## 实现

`tools/glim-refine/refine.cpp` 调用固定版本 GLIM 的官方 `GlobalMapping`：

1. 独立进程只读加载源地图，关闭优化，导出完整点云，与已保存点云比较。
2. 新进程加载源地图，开启官方 CPU VGICP 优化，调用
   `find_overlapping_submaps(0.5)`，保存到独立新目录并导出点云。
3. 第三个新进程关闭优化，加载新地图，检查导出点云的逐点保存往返。

源码版本为 `koide3/glim` 的
`1a197c999e4865f5cab7c9cd25474128413ebbca`，CPU 配置来自该版本的干净工作树。
0.5 是实验前声明的重叠阈值，不是根据哪张图更好看而选择的参数。
不启用 GPU；对原有 pose-only 图不虚构全局 IMU 输入；不抽样掉源子图点。
只读重载关闭优化，避免将再次优化的结果当成序列化往返。

`tools/refine_saved_map.py` 负责配置、构建、三个进程和报告：

- 仅接受有界完整地图、编号子图、有限且时间递增的完整轨迹。
- 输出必须为 `.local/` 或用户缓存中的全新目录，不能覆盖源目录。
- 可提供 `--receipt`，将地图目录、完整点云、帧/子图/点数和原始配置
  与 schema v2 保存收据绑定。不提供时明确标记为未绑定的离线样本。
- 同时保存原始配置与有效配置摘要；构建绑定原生源码、Python 调用链、
  可执行文件、固定核心构建报告与库文件，并在实验后复核。
- 检查原图、源点云、配置、收据和实现没有变化；错误或自动恢复图的日志
  不能视为干净的保存/重载成功。
- 输出每阶段耗时、Linux 原生进程峰值 RSS、点云/日志摘要和 raw 位移统计。
  这些数字不表示真实地图精度或机器人实时处理性能。

## 实际验证结果

| 项目 | 较早录制样本 | 近期现场保存地图 |
| --- | --- | --- |
| 子图 / 保存帧 | 7 / 1,190 | 8 / 2,064 |
| 完整点数 | 90,103 | 83,911 |
| 优化前后子图、帧和点数 | 保持完整 | 保持完整 |
| 新的非相邻子图匹配约束 | 4 | 7 |
| 源图重载逐点最大误差，raw | 1.37e-6 | 1.45e-6 |
| 优化图新进程重载逐点最大误差，raw | 0 | 0 |
| 位移 P50 / P95 / Max，raw | 0.0240 / 0.0755 / 0.1560 | 0.0303 / 0.0732 / 0.3265 |
| 与现场保存收据绑定 | 否，保留此限制 | 是 |

点云位移是优化改变了多少，不是误差减少了多少。匹配因子的数量也不是
真实物理回环正确性的证明。两份样本在重复运行中的优化点云摘要保持一致；
保存目录清单可能包含不同的配置路径，不能据此要求所有输出文件逐字节一致。

## 固定视角对照

`--render-comparison --z-range 0.3 1.5` 生成四格私有图片。左右严格使用
源点云 X/Y 的 1%–99% 视口加相同留白、相同轴范围、比例、颜色和点大小。
上排均显示全部高度，下排均显示相同的显式 raw Z 区间，不独立缩放结果图。
全部点仍保留在地图和二进制导出中；图片是俯视点云，不是栅格地图。
区间仅为诊断显示，不是经过地面标定的米制障碍层。

此次固定视角复核中，优化改变了局部轮廓，但散点和重影仍明显存在。
不能据此批准用户要求的地图效果，也不能把全局优化当成充分修复。
本工具只调整子图位姿，不重新运行每帧 LIO、去畸变或子图内的局部估计。
缺少独立现场尺寸和已确认的返回起点信息，目前无法确认具体误差来源。

## 复现方式

在已有固定 CPU 核心和干净 GLIM 源码的普通用户 Linux 环境中执行。
`PYTHON` 应指向隔离的科学计算环境，含 NumPy、SciPy、json5；绘图另需
Matplotlib。下面的路径变量均由操作者明确提供，不从机器人读取。

```sh
"$PYTHON" tools/refine_saved_map.py build \
  --work "$CPU_CORE" --output "$NEW_BUILD"

"$PYTHON" tools/refine_saved_map.py run \
  --work "$CPU_CORE" --adapter "$NEW_BUILD" --upstream "$GLIM_SOURCE" \
  --config "$SOURCE_CONFIG" --map "$SOURCE_MAP" --points "$SOURCE_POINTS" \
  --receipt "$SOURCE_RECEIPT" --overlap 0.5 \
  --render-comparison --z-range 0.3 1.5 --output "$NEW_PRIVATE_OUTPUT"
```

只读重载的误差阈值沿用既有 `1e-4 raw` 序列化标准，未放宽为地图精度标准。
原生程序的时间包括地图 I/O；Windows 挂载盘与 Linux 缓存目录差异明显。
不能将电脑上单次秒级结果外推为 ARM64 实时性能保证。

本轮新增 14 项工具测试，并运行既有 GLIM 配置/保存/回放 45 项和受控建图
30 项回归。配置回归最初指向已有改动的旧上游目录而失败；保留该目录不动，
显式设置 `LINGXI_GLIM_UPSTREAM_ROOT` 指向已核验干净目录后通过。
这些测试与两份实际保存地图验证的范围不同，不能相互代替实机验收。

## 决策与未完成项

保留官方完整 CPU 全局优化器作为下一版后端候选，不将本离线脚本直接
接到机器人服务，也不把新地图替换进当前目录。下一步以新的适配器验证
完整全局映射的增量输入、约束更新、保存/重载及计算开销，保留现有证据版本。
需要通过录制数据再处理和 ARM64 适配，之后才安排有尺寸参照的现场扫描。

现场采集需有已测单程距离、起点与朝向标记、简单可复述的路线、一个独立
环境尺寸，以及姿态/动态物体变化记录。仍由现场人员使用外置遥控器移动。
新的实时页面与采集链路未确认可用前，不要求用户开始扫描。

物理尺度、外参/时间假设、地图几何精度、真实回环、移动定位、导航、
避障、Android 和整套交付验收均未因此通过；本轮没有重建或部署实机包。
