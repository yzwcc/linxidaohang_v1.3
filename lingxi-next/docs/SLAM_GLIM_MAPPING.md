# GLIM 真实点云地图持久化验证

日期：2026-10-28。结论：**本机四轮真实数据的非空点云地图保存及新进程
CPU 重载通过；不是地图精度、回环、重定位、ARM64 实时运行或导航验收。**
本轮没有连接机器人、发出移动指令、更改模式/输入源或部署软件。
现有 AIMDK、步态控制器、0.1.18/0.1.19 安装包及 APK 保持不变。
现场无需为该阶段再次行走。

## 验证链路

继续使用已经核对完整性的 353 帧静止和 1,232 帧行走记录，
以及 `SLAM_GLIM_OFFLINE.md` 中两种明确未批准的扫描时间假设。
SI 单位、外参、同步、IMU 噪声的限制全部保留，不按本轮结果调参或批准标定。

- `run_glim_offline_trial.py` 仅增加可注入的原生工厂及关闭回调，
  原有解码、完整性、IMU 覆盖和初始化检查共用，不复制另一套 bag 解析。
- `glim-mapping/mapping.cpp` 接入官方 `on_marginalized_frames`，
  只送入最终固定滞后帧；ID、时间戳严格递增，重复或遗漏会失败。
  EOF 时里程计 `get_remaining_frames()` 自带回调，不把其返回值再次送入。
- 官方 `SubMappingPassthrough` 合并关键帧，官方 CPU
  `GlobalMappingPoseGraph` 构建并保存全局图和编号子图。
  末尾子图只 flush 一次；保存帧数必须等于全部有效估计帧数。
- 该 pose-graph 模块的 `export_points()` 在固定源码中返回空点云。
  保存前对照点由其实际子图及最终全局位姿导出，不调用空实现冒充成功。
- 完成保存后关闭原实例并移除回调、等待上游线程退出。
  独立 Python 进程重新加载扩展，以官方 `GlobalMapping::load`
  读取图/数值/子图，用真实 `export_points()` 导出完整点云。
  加载器显式禁用 GPU 和新的 IMU 融合，加载的是已保存的 pose-only 图。
  CPU 体素相关配置使用上游默认值；参数缺项警告保留，不当作标定。
- 重载前后对地图全部文件的名称、长度和内容哈希复核；
  核对所有保存轨迹的帧数、有限数值与时间顺序，
  核对加载后的子图/图因子/节点数量，按完整点序逐点比较。

`SubMap::save` 将点和协方差压缩为 float32，并以文本保存部分姿态；
因此使用**运行前固定**的 1e-4 原始坐标单位序列化容差，不要求逐位相等，
也不把该容差称为物理定位误差。没有最近邻重配对或筛选有利点。
原生日志和重载日志另外检查错误、图恢复或损坏提示。

## 实际结果

| 数据与时间假设 | 有效帧 | 子图 | 点数 | 保存文件数 / 字节 | 最大重载位移，原始单位 |
|---|---:|---:|---:|---:|---:|

四轮各自的录制帧数、跳过帧、初始化帧及有效帧均完整记账。
静止起点/终点分别跳过 10 / 11 帧、初始化 30 / 31 帧；
行走分别跳过 11 / 12 帧、初始化各 31 帧，不补造早于记录起点的 IMU。
所有有效帧恰好进入已保存子图一次，新进程加载后点数不变，
保存目录没有被重载程序改写。

四轮在本机 x86_64 / Ubuntu 24.04 / Python 3.12.3 隔离环境顺序运行，
不与语音作并发验收。总墙钟约 12.23 / 11.16 / 33.92 / 36.94 秒，
含完整性检查、离线回放、保存、独立进程重载；**不是机器人实时帧率**。
不得把此前仅里程计的耗时与本轮含子图的调用耗时直接排名。

当前默认回环候选最小子图行程为 50 原始单位，
两轮行走的子图中心累计步长仅约 2.65 / 4.29，
没有满足回环候选条件，图中只有初始约束与相邻里程计因子。
子图中心行程也不等于机器人完整轨迹长度。
该专用短序列工具会在达到回环行程边界时停止并报错，
不能用它代替未来长序列的回环验证程序。

两种假设的点数和子图数明显不同，仍须核查驱动的扫描基准与同步，
再验证地图墙面、尺寸、重影和一致性；不能据点数多或文件更大选定时间配置。
还没有共同有效时段精度对照、已知尺寸参照、地图重定位/失定位恢复、
Humble 封装、ARM64 实机加载/性能、语音并发、急停或实际导航。
不会将这些实验地图自动替换已有地图或点位。

## 隐私与来源

本机 `~/.cache/lingxi-next/glim-map-{static,dynamic}-{start,end}-20261028-a/`。

`export_glim_mapping_evidence.py` 重新计算四轮地图清单及全部点的往返差异，
核对原生库、源码快照、回放/重载报告和日志哈希，
通过嵌套字段白名单导出 `slam-glim-mapping-evidence.json`，
不导出坐标、原始序列或实际外参。公开证据不包含实际地图。
历史五轮里程计证据保持原样，历史来源检查改为固定的旧运行器 SHA
及其私有源快照，不拿后续运行器修改重写过去的结论。

构建及回放分别通过 `run_glim_mapping_trial.py build` 和 `run`；
后者新增 `--mapping-adapter`，其余显式路径和时间假设沿用
`SLAM_GLIM_OFFLINE.md` 的参数，输出必须是新目录。
`reload` 只供新进程读取本工具生成、已核对完整性的本机私有地图，
不构成通用外部地图文件导入或地图真实性校验。
固定上游源码提交、许可和核心构建来源沿用 `SLAM_CPU_BUILD.md`。
