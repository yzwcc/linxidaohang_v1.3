# 0.1.48 地形故障诊断与离线验证

## 当前结论

0.1.47 的实机定位子进程在启用地形后退出，现有记录只有
`child_reported_failure`，还不足以确定根因。0.1.48 补齐父层诊断，
使下一次被动采集能定位故障发生在启动、编码、通信、结果校验、
定位数据输入还是退出清理。此版本不代表实机地形或自主导航验收通过。

用户已通知机器人没电，要求先推进离线开发。本轮验证不连接机器人。

## 改动

- 地形进程、异步地形通道、注册点云输入和 acquisition 健康检查在故障时，
  向原有私有 stderr 写入单行 JSON，事件名为 `lingxi_private_fault`。
- 记录固定阶段、内部故障码、异常类型、耗时及最多 12 层文件名/函数名/行号。
  不复制异常文本、局部变量、源码行、完整路径、点云或凭据。
- 日志写入失败不会替代原异常或中断清理；失败仍撤销旧地形结果，
  不重启旧任务、不放宽超时和导航准入。
- 模块使用 `runtime_fault.py` 命名，避免命中发布源码中 `private_*` 的排除规则。
  增加实际源码复制检查，并将该模块列为独立导航包必需文件。

  覆盖故障记录、地形通道、地形子进程传输、注册地形、实时 acquisition、
  定位观测、输入所有权及地形 ROS 适配；其中原生地形使用本地已校验的
  x86_64 Patchwork/OctoMap 构建，不接传感器。

- `git diff --check` 通过。

- 完整构建的三组 TypeScript 检查及 Web 构建通过；Vitest 为 771 项通过、
  26 项跳过；API Python 为 56 项执行，其中 1 项跳过，其余通过。
- 实际 ARM64 压缩包校验通过：13,243 个文件、89 项原生源码引用；Node/JRE
  的 ELF64 AArch64 架构、执行权限及逐文件 SHA256 均已核验。
- 从最终压缩包提取 376 个普通源码文件。六个相关生产 Python 文件与本轮

  旧地形结果撤销、清理完成，并生成 `terrain_process_exited` 私有故障记录。
  这是包内 Python 源码闭包验证，不是 ARM64 传感器吞吐或实机地形验收。

## 下一轮实机验证

1. 用户恢复供电并确认可测试后，再连接 3444 端口项目。重新确认机器人实际
   位置和胸口朝向；不能沿用断电前 A 点确认作为当前定位初值。
2. 安装验证包，核对 acquisition 的完整冻结输入 identity 和当前源码绑定；
   不将设置文件 SHA256 误作父子进程 identity。地图文件和收据保持原位。
3. 与 systemd 一致地使用服务用户及 `manager` 补充组，先完成被动定位及地形
   连续输入测量。使用运行目录中的 `private-child.log` 与地形子进程私有日志
   核对同次故障，避免只查看上层的汇总错误。
4. 地形稳定输出、地面坐标和通行支持通过后，才进入实际导航路线验证。

默认点云显示高度范围继续为 0.1–1.4 米。点云显示过滤与地面支持检测是不同
用途；不能用显示下限删除导航需要的地面回波。现场确认雷达到地面约 1 米，
可作为几何核验依据，仍不等于地形和尺度验收。
