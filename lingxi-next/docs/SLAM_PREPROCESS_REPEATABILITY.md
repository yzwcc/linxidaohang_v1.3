# 原生点云预处理的重复性诊断

日期：2026-10-28。**同一台电脑、同一原始输入和原双线程配置的重复运行，
已实测出现不同的采样点；单线程诊断对照的三轮完整输出逐位一致。**
这是运行重复性证据，不是地图精度、ARM64 一致性或生产配置验收。
此前 9 / 10 个子图的完整差异还未证明全部由此造成。

本轮不连接机器人，不运行里程计或建图，不初始化 ROS，不发布数据，
不更改 AIMDK、模式、输入源、服务、既有地图、产品后端或 APK。
现场无需重新行走。

## 实际执行

新 C ABI 只调用已构建的固定版本 `glim::CloudPreprocessor`，
没有复制或替换上游采样算法。复用此前 x86_64 隔离 CPU 核心及原配置文件，
配置内容摘要完整复核；主机 Python、NumPy 和 rosbags 沿用既有隔离环境。
新增适配库 SHA-256：
`48aea2595272b462e0eae7e223731c703fc9f94dc65970d2cdf1223ea6a22f73`。

原配置启用随机体素降采样：目标 10,000 点、体素分辨率 1.0、
距离范围 0.5 至 100、10 个邻居，预处理线程数为 2，OpenMP 后端。
所有距离数值仍是原始单位，不是新批准的物理标定。
两组条件仅在原生参数对象中显式指定 2 或 1 个预处理线程，
**没有改写配置文件**；单线程条件是事先声明的诊断对照，不是部署建议。

按静止/行走、双线程/单线程、每组 3 次，共预声明 12 轮；
全部为独立新进程，均退出 0，每子进程 240 秒上限。
只读原始 bag，以未批准的“header 是扫描终点”假设复现此前 IMU 时间覆盖筛选。
只读取 IMU 时间，不把姿态、加速度或陀螺数据送入算法。
静止 353 扫描中处理 342、跳过 11；行走 1,232 中处理 1,220、跳过 12。
不运行初始化器、不伪造机器人位姿。

每轮核对原始五个采集文件的 SHA-256、SQLite 检查及 topic 计数，前后相同。
每帧完整输出保存为 x/y/z/相对时间 float64 和 10 个邻居 int32 索引，
另存原始输入完整字节摘要、整数 header、算法时间和帧边界。
全序列约 4.1 GiB 私有输出留在隔离缓存，目录 700、文件 600，
不进入 Git、APK、交付包或外部云端。

## 完整输出对照

每组 3 轮全部两两比较，不选有利的一对。先核对输入坐标/时间字节摘要、
原始点数、完整整数 header 与算法时间均一致。
逐帧比较全部四列 float64 的精确位模式；
顺序不同时，再按四列位模式排序比较完整多重集，保留重复点，
不使用最近邻、距离容差或挑选样本。邻居索引只在有序点内容相同时比较。

| 数据/线程 | 三对比较中点多重集不同的帧数 | 三对比较中点数不同的帧数 |
|---|---|---|
| 静止/2 | 198、218、213 / 342 | 0、0、0 |
| 静止/1 | 0、0、0 / 342 | 0、0、0 |
| 行走/2 | 677、688、669 / 1,220 | 7、11、8 |
| 行走/1 | 0、0、0 / 1,220 | 0、0、0 |

本轮没有出现“点多重集相同、只是顺序不同”的差异帧。
在有序点内容相同的帧中，邻居索引序列也没有差异。
单线程两组各三轮的全部点、逐点时间和邻居索引逐位一致。
这只证明这两份记录在本机和本版本的三次观察，不是无限期或跨平台保证。

**所有**处理扫描均满足固定源码中的采样分支条件
`10000 / 原始点数 < 0.99`；并非只有此前那 11 帧进入随机采样。
静止每帧点数可以完全一致，而数百帧的实际采样点已不同，
说明此前只比较点数会低估输入内容变化。

与历史建图回放按完整相同有效域另作点数列对照：
静止所有轮与历史两端均相同；新的双线程行走三轮分别与历史电脑
有 11 / 10 / 12 帧不同，与历史机器人有 10 / 9 / 13 帧不同。
单线程行走三轮与历史电脑各有 23 帧、与历史机器人各有 20 帧不同。
因此也不能把“单线程稳定”解释为“还原了历史某一端的正确结果”。
历史未记录完整预处理点，不能补造该部分对照或重写既有建图证据。

## 源码解释与边界

固定 GLIM 使用持续存在的 `std::mt19937`，调用 gtsam_points 随机体素采样。
固定实现按线程派生随机发生器，以 OpenMP guided 块调度执行 `std::sample`，
之后再恢复原索引顺序并进行距离过滤。源码机制支持调度影响采样的解释；
本轮没有采集逐块线程分配日志，不能把机制推断写成完整调度因果追踪。
主结论来自实际完整输出重复比较，不来自只读源码的猜测。

已证明：即使不跨架构，原双线程预处理也会产生运行间点内容变化。
未证明：这是历史地图分歧的唯一原因，或单线程在 ARM64 上满足实时吞吐、
几何精度和语音并发要求。未校准的扫描时间语义、同步与外参限制不变。
没有因此批准参数、替换算法、切换生产后端或接通运动接口。

下一步应在机器人隔离环境核对相同诊断条件、完整点输出与实时开销，
再决定稳定预处理策略；地图几何、回环、重定位和导航仍需独立验收。
任何新移动、模式/输入源切换仍须现场确认。

## 复算

`run_glim_preprocess_trial.py build/run` 构建专用薄适配层并执行预声明轮次；
`export_glim_preprocess_evidence.py` 核对构建来源、全部报告/文件、完整点与邻居，
按白名单导出 `slam-preprocess-repeatability-evidence.json`。
公开文件只含计数、摘要及验收边界，不含点、轨迹、绝对时间或凭据。
原始采集及全部私有输出在导出时再次核对，未变。

```sh
rtk proxy python tools/export_glim_preprocess_evidence.py \
  --core "$PRIVATE_CPU_CORE" --adapter "$PRIVATE_PREPROCESS_BUILD" \
  --results "$PRIVATE_PREPROCESS_RESULTS" --data-root "$PRIVATE_RECORDINGS" \
  --host-cache "$PRIVATE_CACHE" --target-results "$PRIVATE_ARM64_MAP_RESULTS" \
  --output "$NEW_AGGREGATE_JSON"
```

所有输入显式指定；输出必须是新文件，不覆盖历史结果。
实际 12 轮观察与合成测试分开记录；本轮未修改前端、Java 或 Android。
