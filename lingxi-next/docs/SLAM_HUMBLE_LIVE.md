# ARM64 实际 Humble 被动订阅

日期：2026-10-28。在同一机器人普通用户的新独立目录中，完成两个各请求
20 秒的新进程：真实订阅原始胸前雷达与 IMU，并运行已冻结的 GLIM CPU 里程计。
**这次不是 bag 回放，但也不是全局建图、标定、重定位或导航验收。**

没有要求现场人员再次移动，也没有独立确认这两段输入为严格静止状态；
不把它们称作静态精度采样。两个时间假设接收的是先后不同的实时数据，
不能当成同一输入的精度对照或据此选择一种时间解释。
0.1.19 产品后端、网页、Android APK、部署服务、厂商 AIMDK、地图、
模式和输入源均未修改，没有发送运动命令。

## 方式与边界

- `prepare_glim_live_target.py` 复制已验证的 paced-worker bundle，新增实时运行器
  和原有 `passive_ros.py`。原生库、配置和历史工具逐文件校验，不重编、
  改尺度、调外参、换时间偏移或放宽输入限额。
- `run_glim_live_target.py` 经已有 SSH 主机密钥核对连接，凭据只在内存输入。
  新机器人用户目录与本机 `.local/` 目录均不覆盖已有试验。
- 每进程使用显式清空后重建的 Humble 环境、domain 0、Fast DDS 和现有厂商
  DDS 配置。只读该配置并核对前后摘要，不修改厂商配置。实际主程序和加载库
  都有摘要，目标为 AArch64 / Python 3.10.12 / NumPy 1.26.1。
- 原有包装器创建独立 Context 与 SingleThreadedExecutor，仅订阅指定的
  PointCloud2/Imu，BEST_EFFORT / VOLATILE，队列深度分别为 8/256。
  不创建应用运动、TF、地图发布器或服务客户端。标准 rclpy 仍可能产生
  discovery 和参数事件流量，不能宣称完全没有 ROS 发布或网络流量。
- 每轮外层限时 50 秒，超时 INT 后最多再等 10 秒强制结束整个诊断进程。
  Python 工作线程仍不能强杀挂住的原生调用；本轮没有实机注入原生挂起，
  不把限时配置当作生产监督/故障恢复验收。

扫描起点/终点仍只是诊断假设。输入快照、解码、缓冲、原生创建/调用/关闭
和超时限额均复用此前冻结组件。实时运行器新增的诊断子类只审计帧结果，
之后仍调用原有活动消费者门控，不让停止后的迟到结果进入活动消费者。
原生初始化失败或加载库校验失败时，新组合适配器也会尝试关闭已打开的引擎。

| 扫描终点假设 | 197 / 3,933 | 195 / 31 / 164 | 2 / 0 | 2 / 0 |

起点假设完成 3,839 条消息。终点假设完成 4,128 条，显式停止时丢弃队列内
2 条 IMU；没有把它们算作已处理或声称无丢弃。
两轮均满足 `接受 = 完成 + 停止丢弃`，回调无拒绝，流内无失败丢弃。
终点假设共完成 195 个原生帧结果，其中最后 1 个在停止后被原有门控退役，
实际活动消费者收到 194 个；起点假设活动消费者收到全部 182 个。

每轮原生引擎创建/关闭各一次，IMU/帧调用与流计数一致；
原生入口由同一个非生产者线程执行。两轮均退出 0，
线程已 join，回调队列与流缓冲释放。停止后没有保留待执行帧或自动恢复动作。

| 条件 | 点云 / IMU 回调频率 | 消息 / 点云队列峰值 | 最长队列年龄 | 回调至帧结果 P95 / 最大 |

| 终点假设 | 10.002 / 200.055 Hz | 34 / 2 | 153.32 ms | 69.03 / 115.25 ms |

原始排队 payload 峰值分别为 794,112 / 1,585,568 字节；
整个进程 RSS 峰值约为 249.66 / 254.58 MiB，二者不是同一种内存指标。
请求时长从初始化 ROS 前开始计，实际点云首末回调跨度约为 18.20 / 19.60 秒；
没有把发现阶段当作已经连续接收到数据。

首个有效位姿结果距本次诊断观测开始约 5.16 / 3.92 秒，
包括发现/引擎启动/惯性初始化等本次开销，不是地图重定位耗时。
帧结果 P95 的起点是 Python 点云回调进入，包含入队、等待与计算，
不包含雷达至 DDS 的传输、网页绘制、全局建图、模型或音频播放；
不能用于声称语音首响两秒通过。
原生预处理/里程计合计 P95 约为 67.47 / 64.84 ms。
这两次短时观察没有验证长时间运行、语音并发负载或最坏时延。

两轮原生日志各出现 2 次 IMU prediction 告警及对应外参/偏置提示。
这并不能单凭日志定位为某个唯一原因，但时间、外参、偏置和几何验证
都仍未通过；没有调参隐藏告警或用顺畅输出代替精度验收。

## 失败记录

此前 trial-a 保持原样，不算作通过。其工作线程已回收、引擎已关闭，
诊断进程退出 1：本次新诊断把“活动消费者收到的结果”错误地等同于“全部完成原生帧”：
停止时原有门控拦住最后一帧，出现 189 个原生帧、188 个观测帧，
新运行器因此失败关闭，没有启动该次矩阵的第二轮。

修正仅位于新增诊断子类：先记录完成帧，再经过原有门控，分别输出
活动消费者前缀与退役帧数。新增合成测试覆盖这一时序，
没有修改冻结的 worker、原生库或限额。通过的两轮都重新使用全新 trial-b
bundle、进程和输出目录，没有覆盖或修补 trial-a 的结果。
