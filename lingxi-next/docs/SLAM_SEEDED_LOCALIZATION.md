# 已保存点云地图上的初始定位与连续跟踪

日期：2026-10-30。本轮只在电脑隔离环境开发和验证，机器人保持断电。
新增代码不加载厂商导航、不发布 TF 或运动指令，也不修改既有地图、APK、
部署包或生产配置。

## 已完成的实现

`robot-slam/lingxi_slam/seeded_localization.py` 使用固定的
small-gicp 1.0.1，缓存地图及其搜索结构，执行有明确初始位姿的 GICP
扫描到地图配准。上游 `v1.0.1` 对应的源码提交为
`57c1106daf83c2c79ee0c58a9c7ed0032298ff4e`（MIT）；
`47630dd3d4bcfe468f6f5ca14d3298fc8dc97e56` 是该版本的附注标签对象，
不是源码提交。参考实现为 <https://github.com/koide3/small_gicp>。
首版使用单线程、有限点数及迭代次数，避免每帧重建地图索引。

输入位姿方向明确为 `map_from_sensor`。既有原生点云输出已经位于
`lingxi_glim_odom` 世界坐标，因此先以对应 `world_lidar_pose` 逆变换一次，
还原到传感器坐标，再执行扫描到地图配准，避免将世界点重复变换。
这里的位姿仍是传感器位姿，不能直接替代机器人底座位姿。

返回成功必须同时满足：刚性变换有效、原生匹配点数足够、扫描与地图重合率、
最近邻残差、相对初始位置和朝向的修正量，以及原生信息矩阵和独立几何可观测性。
单平面、直线、远处初始位置、大量离群点和超限修正均有拒绝测试。
任何质量拒绝均不返回可用位姿。

`localization_tracking.py` 将上述配准接成独立跟踪状态机：

- 显式提供初始位置；以 `map_from_odom @ odom_from_sensor` 预测后续初值。
- 默认连续三次匹配通过后才显示诊断跟踪位姿；确认数有上限。
- 输入过期、首帧或后续帧时间间隔过大、时间倒退、配准拒绝或异常均撤销位姿。
- 失定位后要求明确重新设定初始位置，不自动重试旧帧。
- 会话、初始位置代次、帧号和算法时间共同隔离旧回调；重复帧不刷新期限。
- 停止或重新设定初始位置后，旧配准的结果及异常都不能覆盖新状态。
- 单线程所有权及输出副本防止跨线程使用和外部修改内部位姿。

该模块消费调用者已校验会话和模式的点云包；它没有自行连接输入管道。
`tracking` 只是诊断状态，`localization_ready` 和 `navigation_ready` 始终为 false。
迭代次数有界不等于原生调用具有硬超时，后续运行接入仍须保留进程监督和终止能力。

## 真实录制数据诊断

`tools/run_seeded_localization_trial.py` 校验已有保存收据、地图文件清单、
点云摘要及有界数值 NPZ。它拒绝 pickle、额外字段、非法位姿和不正确的帧时间，
保留既有输出，并在运行前后检查输入未变化。输出仅含聚合、版本和摘要，
不导出点坐标、位姿或私有路径。

最终新运行 b 的聚合见 `slam-seeded-localization-evidence.json`。
此前运行 a 保留在电脑私有缓存，不覆盖为新结果。

| 项目 | 本次实际观察 |
|---|---|
| 平台 | WSL Linux x86_64，Python 3.12.3 |
| 依赖 | small-gicp 1.0.1、NumPy 2.5.4、SciPy 1.16.3 |
| 地图 | 已验证保存/独立进程重载的 1 个子图，2,655 点，165 帧 |
| 扫描 | 原记录的首末两帧，分别 7,606 和 7,602 点 |
| 录制位姿初值 | 两帧均通过诊断质量门槛 |
| 扰动初值 | 平移 `[0.2, -0.15, 0.1]` 原始单位和 5 度偏航；两帧均通过 |
| 负样本 | 平移额外增加 `[100, 100, 100]` 原始单位；两帧均拒绝 |
| 有效匹配 | 重合率 1.0，最近邻 RMS 约 0.112–0.113 原始单位 |
| 本次单次调用 | 六次约 13.0–20.3 ms，包括正负样本；非持续吞吐或 ARM64 指标 |

负样本的重要观察：原生结果在 **0 个匹配点** 时仍返回 `converged=true`。
仅检查收敛标志会误报成功，本实现额外检查匹配数量、残差、重合率和几何信息，
因此两次均拒绝，且没有暴露可用位姿。

这些扫描可能来自建图所用的同一段数据，且初值使用了该记录的位姿。
本次是坐标方向、局部配准和拒绝逻辑的诊断，**不是独立定位精度、
全局重定位、动态持续跟踪或失定位后自主恢复的证据**。
RMS 是扫描与地图的最近邻残差，不能称为对真实位置的测量误差，
也不能未经标定将“原始单位”改写为米或厘米精度。

## 离线检查和复现

新增测试使用实际 small-gicp，覆盖已知刚体变换、噪声及部分点云、
无重合与退化几何、错误原生成功结果、质量门槛和连续跟踪失效边界。
录制数据测试另覆盖输入摘要、收据、NPZ 结构、输出保留和脱敏结果。
连续移动测试使用合成房间及已知传感器运动；没有把两帧真实样本重复计为连续跟踪。

独立试验依赖列于
`robot-slam/requirements-localization-trial-x64-py312.txt`，仅用于本次
x64/Python 3.12 隔离试验，不是 ARM64 交付依赖锁或完整供应链审计。
在已有隔离科学计算环境内运行：

```sh
python -m unittest discover -s tools/tests -p test_slam_seeded_localization.py -v
python -m unittest discover -s tools/tests -p test_slam_localization_tracking.py -v
python tools/run_seeded_localization_trial.py \
  --saved-map /private/existing-saved-map \
  --scan /private/existing-first-points.npz \
  --scan /private/existing-latest-points.npz \
  --acknowledge-recording-reuse \
  --output /private/new-trial-report.json
```

现有 saved-map 必须包含原来的 `map-ready.json`、`map/` 和
`private-saved-points.f64`。输入缺失或完整性不符就失败，不自动生成假地图或初值。
本轮检查结果：

- Linux 工具套件 880 项，876 项通过、4 项明确跳过。跳过项为需要显式指定
  Linux Node 和已编译 consumer 的既有独立消费进程测试，非新增定位测试。
- 新增 18 项配准/录制输入测试和 13 项跟踪测试均实际执行通过。
- Windows 工具套件 880 项，432 项通过、448 项因平台或可选依赖明确跳过。
- 机器人 API Python 测试 39 项通过。

首次 Linux 全套执行使用了没有安装 NumPy 的解释器；父进程通过
`PYTHONPATH` 找到 NumPy，但使用独立环境的子进程无法导入，
导致 4 项失败、1 项错误。保留这一失败记录；换用已安装依赖的科学计算
隔离环境后得到上面的最终结果，没有放宽检查。

配准及跟踪本身不依赖 JSON5；录制输入诊断复用 Linux 地图清单工具。
Windows 缺少原生依赖或 Linux 工具时明确跳过对应测试，不能算作测试通过。
实际原生执行使用准备好的隔离 Linux 环境。
