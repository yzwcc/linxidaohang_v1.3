## 离线输入核查

`tools/slam_bag_audit.py` 使用已有 rosbag2 读取器和标准消息反序列化，
不调用 `rclpy.init()`，不创建 ROS 节点、服务客户端或运动发布端。
逐条读取已完成的 SQLite3 数据包，只输出聚合统计，
不输出原始点坐标、轨迹坐标或原始 IMU 样本。
它复用被动预检的字段、有限值和时间候选检查，
显式使用 bag 接收时间，而非核查程序运行速度计算频率。

在机器人已有 ROS 环境中，分别读取两段已有数据的离线检查已通过：

- 五个话题均非空；点云布局解析无错误，分散采样点的 XYZ 均有限。
- 两段点云、IMU 和里程计的 header 时间戳均未出现无效值或倒退。
- 动态段记录接收频率约为点云 10.08 Hz、IMU 200.09 Hz、里程计 169.97 Hz。
  接收频率、header 间隔和传感器真实采样频率不能混为一谈。
- 动态段点云最大 header 间隔约 0.1155 秒，IMU 约 0.0398 秒；
  没有传感器序列号逐包对照，不能据此宣称零丢帧。
- 1,232 帧动态点云的采样时间均支持帧相对纳秒解释，
  采样跨度约 0.094502–0.094849 秒。仍不是完整扫描端点或动态同步证明。
- 观察到雷达到雷达 IMU 的静态 TF 路径，不代表外参精度已验证。
- 动态里程计报告的累积位置步长约 9.38 原始单位，首末距离约 0.705 原始单位。
  这是带噪估计，不是外部测量的路线长度、回环误差或 SLAM 精度。

### 尚需核实的现象

静止段角速度模长约 0.0703–0.0741，单位仍须依据厂商定义核实。
不能将这段读数直接当作已标定的 rad/s，也不能未经审核就扣除常量。
姿态四元数模长恒为 1 仍不证明其包含真实姿态信息。

点云 bag 接收时间与 header 的绝对差最大约为静止段 1.050 秒、
动态段 1.096 秒。应先区分发现/启动缓存和稳态分布，再评估排队与时钟语义；
该最大值不是可直接填写的 IMU 时间偏移。
本工具不做自动外参、时钟偏移或 IMU 零偏批准。

## 复现

副本完整性检查不需要 ROS，只读取文件和 SQLite 数据库：

```sh
python3 tools/verify_slam_capture.py \
  --manifest docs/slam-capture-evidence.json \
  --data-root "$HOME/.cache/lingxi-next/slam-datasets-20261028-a"
```

工具逐块计算哈希，拒绝间接路径、未知文件及 WAL/SHM 旁文件，
以只读 immutable 连接检查已收尾数据库，不生成副本、轨迹或数据库日志。
清单内的文件哈希必须先独立从机器人原文件取得；
校验成功只证明传输完整，不批准标定或导航。

在有 ROS 2 Humble、`rosbag2_py` 和相应标准消息包的离线环境中执行：

```sh
python3 tools/slam_bag_audit.py /path/to/finalized-static-bag
python3 tools/slam_bag_audit.py /path/to/finalized-dynamic-bag
```

此工具不会回放话题或运行 SLAM。接下来的 GLIM/KISS-ICP 对照仍需准备隔离
ROS 构建环境，并完成输入语义审核；任何导航测试须另行确认现场条件。
