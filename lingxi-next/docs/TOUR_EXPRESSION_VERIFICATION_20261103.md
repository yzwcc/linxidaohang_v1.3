# 讲解表情的撤销与恢复验证

日期：2026-11-03。范围是 `lingxi-next/` 的讲解任务与表情下发链路，
不是实机动作、导航、定位或完整产品验收。没有连接机器人或调用业务云端。

## 修复内容

表情下发前的状态查询是异步的。旧实现只检查任务仍存在，人工暂停或新一轮
语音交互没有使这个检查失效。因此暂停/打断后，迟到的状态查询仍可能触发表情。
新组合回归先在旧实现复现这两个失败，再实施修复。

`JobManager` 现在为每次表情尝试捕获交互代次，并在实际写请求前确认：

- 当前任务、任务代次仍一致，且未停止或故障停留。
- 没有人工暂停，没有未结束的对话，交互代次没有变化。
- 产品层原有建图、定位、导航、动作占用检查仍然通过。

`ActionAuthorizationRevoked` 仅表示本地已知的下发前撤销。讲解任务只对这个
本地类型等待恢复并重新尝试：人工暂停必须显式继续；语音打断必须等待对话结束
及既有的 5 秒安静窗口。普通错误、HTTP 错误文本、丢失或无效回执都不能进入
这个重新尝试分支。已写请求随后收到有效回执时，也不会因中间暂停而重发。

`HttpActionsBackend` 在状态查询前和实际写请求前检查授权；产品适配器在异步
前置检查后再次确认。原生 AIMDK 和演示适配器同样遵守可选授权回调，建图包装层
转发原回调，避免其身份信息丢失。未添加新的运动或资源播放权限。

新增回环 HTTP 组合测试实际使用 `JobManager`、`ProductActionsAdapter`、
`mappingGuard`、`PhysicalNavigationAdapter` 和 `HttpActionsBackend`。
只有动作 HTTP 响应、导航状态及地图身份是明确的合成夹具，不调用 ROS 或硬件。
该组合的 6 项检查覆盖：

1. 查询期间人工暂停，零写请求；人工继续后仅写一次并完成播报。
2. 查询期间语音打断，对话和安静窗口结束前零写请求；随后只写一次。
3. 停止后迟到查询不写请求，替换任务不重放旧代次。
4. 已写请求的无效回执使任务停留，不播报、不推进，也不自动重发；需人工恢复。
5. 写请求后、有效回执前发生暂停/继续，不重复写入同一表情。
6. 远端返回与本地撤销相同的错误文本，不被误当作可重新尝试的本地撤销。

组合 HTTP 夹具使用 80ms 安静时间以缩短离线回归周期，不冒充生产 5 秒验证。
另有 `jobs.test.ts` 的确定性时钟检查：交互结束后 4,990ms 仍未下发，跨过
5 秒后只下发一次且无失败记录。生产默认 `quietResumeMs=5000` 未改变。

## 定位期间表情复核

随后核对了 AIMDK v1.1.0 的 `PlayEmoji.srv` 与 [官方 X2 屏幕控制文档](https://x2-aimdk.agibot.com/zh-cn/dev/Interface/interactor/screen.html)：
该服务只接收表情 ID、播放模式和显示优先级，控制脸屏表情显示，不是关节或底盘接口。
因此产品层现允许讲解点位上的脸屏表情与稳定定位并行，不开放实体动作。

允许条件是定位 runtime 处于 `running`、未清理/关闭，读取 worker 前后的 runtime 身份、
进程代次不变，worker 正在运行且状态为 `tracking`，地图与回执身份一致，并且没有建图、导航活动、
动作不确定或讲解交互撤销。状态查询失败、定位启动/停止清理中、跟踪丢失/暂停或身份变化仍拒绝。
表情服务和定位/Nav2 现在共享操作租约；建图保留独占租约，因此跨进程建图仍能在 ROS
服务写入前挡住表情。导航活动仍由产品 API 另行拒绝。
进程代次与 worker 的重定位代次是两个独立计数器，不直接比较它们；正常重定位后仍能使用表情。

这轮只验证合成状态、HTTP 夹具和 Linux 文件锁语义，不证明机器人实机显示、定位质量、
讲解到点行为或 SDK 服务在线。之前“定位运行期间拒绝表情”的记录由本段实现更新取代。

后续复核结果：

| 构建 | Windows/Linux 前端、API、runtime 类型检查与 Vite 生产构建，另有 Linux SLAM bundle 构建通过 |
| 发布范围 | Python 7/7；没有重新生成或部署安装包 |

新定位策略测试覆盖读取前后 runtime 更换、地图/回执/输入模式不符、不稳定或不一致
worker 状态以及读取失败，全部拒绝；worker 重定位代次与进程代次不同的 tracking 状态可接受。
配对 HTTPS 的实际产品组合也验证了这一正向路径。原有 6 项讲解撤销组合用例改在
“合成定位仍运行且允许表情”的条件下重跑。ROS 类型、导航状态和几何仍是合成夹具。

Linux 源码快照与当前改动逐文件比较，只允许 CRLF/LF 不同；其依赖锁文件也与复用的
Linux 依赖一致。第一次 Linux 文件锁测试缺少成功路径的模拟 `PlayEmoji.Request` 字段，
补齐后重跑。首次完整四套 Python 调用还缺少测试目录导入路径及历史 Git 只读环境，
修正调用环境后 123 项无跳过通过；没有因此放宽生产逻辑。通用 Python 环境缺少
numpy/scipy 的跳过结果不算入这次 123/123，也没有把无限制 Python 全量重新标为通过。
