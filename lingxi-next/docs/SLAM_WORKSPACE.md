## 运行组成

- `managed_slam.py` 使用已有进程管理器监督一个共享 Python 服务及一个 API。
  复用原有启动期限、父输入 EOF、进程组清理和孤立子进程回收逻辑。
- `slam_service.py` 在一个进程中承载建图与按需定位两个管理器，
  使用不同的私有 Unix socket，以及同一保存地图目录中的共享运行锁。
  不新增另一套建图、配准或导航算法。
- `slam-main.ts` 显式启用统一模式，不因同时设置两个环境变量就开放混合模式。
  原有独立建图和固定地图定位入口保持兼容。
- `--maps` 是独立、已存在、当前普通用户所有的 0700 持久目录。
  `--output` 每次为新的运行目录，与地图和冻结的 SDK/原生输入目录互不包含。
  服务重启复用保存地图，但不复用上次的 serviceId、runId、控制代次或进程。
- 工作区服务可以持续运行，不要求每小时重启；原生 live 会话的已核验时长限制
  没有取消。达到会话上限仍需确认退出并明确新建，不自动续期或恢复旧操作。

API 不接入厂商运动适配器、语音和云端模型。
业务写接口继续关闭；定位/导航就绪标志保持 false。
建图和定位冲突由实际工作进程继承的 Linux 锁最终裁决，API 和按钮状态只做前置检查。
定位服务无法确认资源槽位时，建图不可启动。

## 启动前提

只在普通用户 Linux、与既有核验配置匹配的独立 Python/原生库环境运行。
ARM64/Humble 继续要求既有匹配的 Python 3.10 与配置；x64 只接受录制输入。
不可把合成测试夹具当作机器人运行入口。

先构建网页与工作区 API：

```sh
npm run build
npm run build:slam-runtime
```

为进程提供受限权限的 `LINGXI_TLS_KEY`、`LINGXI_TLS_CERT`、
`LINGXI_PAIRING_CODE_SHA256`，以及指向已构建网页的 `LINGXI_WEB_ROOT`。
可设置 `LINGXI_HOST` 与 `LINGXI_PORT`；统一模式默认 HTTPS 3443，
明确拒绝 3000，避免触碰原控制台。绑定失败就退出，不关闭或覆盖占用端口的进程。
客户端需先信任当前证书，再配对；不向浏览器或 APK 分发私钥。

```sh
<verified-python> -B robot-runtime/python/managed_slam.py \
  --config <absolute-verified-config.json> \
  --maps <absolute-private-saved-maps> \
  --output <absolute-new-private-run> \
  --node <absolute-verified-node> --node-sha256 <sha256> \
  --api-bundle <absolute-slam-main.mjs> --api-sha256 <sha256>
```

不传 `--seconds` 时服务持续到信号或子进程故障；联调时可显式限制为 5–3600 秒。
配置中的原生会话上限独立生效。启动命令与哈希必须对应实际部署的文件，
不是任意下载版本；不会安装或覆盖现有 AIMDK/ROS。

关闭时先撤销两个管理器的请求接纳，停止并回收工作进程，再关闭 API。
服务与 API 任一异常退出都会结束整个组合，不自动重启或重发旧命令。
`owner-report.json` 与私有日志位于运行目录；清理失败为失败结果，不能当作正常关闭。

## 验证与剩余工作

本地流程通过实际 HTTPS、Unix socket、进程监督器及共享锁运行；
只有传感器、地图几何和工作线程协议来自明确标注的合成夹具。
验证包括网页保存后选图启动定位、关闭后重新建图、持久目录跨重启保留地图、
两个模式互斥、对端故障及管理进程被终止后的回收。
1440×900 和 844×390 网页无水平溢出或面板重叠。

仍需完成：

- 实际 ARM64 统一工作区运行、带初值实时跟踪、物理标定和移动地图精度验收。
- Nav2/X2 行走接口、局部避障及恢复策略、导航/讲解/语音与该入口的整合。
- 完整产品安装器、空间和日志保留、健康诊断及 APK 更新。
  独立工作区已有另行验证的用户服务安装/回滚，尚未整合完整产品。
- 现有点位/讲解迁移及业务配置持久化。此入口的轻量 API store 目前在
  新运行目录的 `data/`，不能当作完整业务数据迁移或持久配置方案。
