# 被动传感器订阅与算法工作线程

日期：2026-10-28。新增回调到算法的有界传输和 Humble 被动订阅封装，
并完成原现场记录的完整消息等价检查。
**本轮没有联系机器人、启动实际 ROS 节点或在工作线程中运行真实 GLIM。**
现有 0.1.19 产品后端、AIMDK、服务、模式/输入源、地图和 APK 均未改变。

## 组件

- `robot-slam/lingxi_slam/messages.py`：按显式帧名和相对纳秒时间假设
  保存完整点云二进制副本、布局和 IMU 数值。不猜测传感器帧、时间单位或外参，
  不使用驱动的占位姿态代替惯性初始化，不生成缺失的逐点时间。
- `worker.py`：回调只校验和快照输入；单个工作线程创建注入的引擎，
  解码、调用既有 `SensorStream`、处理结果并关闭引擎。
  回调不会持有算法调用所用的锁，也不从多个回调并发调用原生库。
- `passive_ros.py`：显式提供传感器话题、profile、时间假设和引擎工厂，
  才能运行最多 300 秒的诊断会话。不自动发现或加载算法，不注册为服务，
  不切换网页后端，不保存/激活地图。

点云保留全部点和逐点时间，支持大小端、组织点云及行填充；
非有限点不静默过滤，而是令本次会话失败。
单帧超限同样拒绝，不通过裁剪远处点或伪造图像来适应容量。
IMU 保留加速度和角速度的原始数值，不自动改尺度、减偏置或修正时钟。
这些仍是诊断假设，不是标定批准。

## 限额与停止

| 边界 | 当前诊断默认值 |
|---|---:|
| 回调队列总消息数 / 点云数 | 4,096 / 16 |
| 排队原始 payload 总量 | 64 MiB |
| 单帧原始点云 payload | 8 MiB |
| 最长回调队列等待 | 0.5 秒 |
| 工作线程进度间隔 | 0.75 秒 |
| 空闲 tick 周期 | 0.05 秒 |
| 原生引擎启动等待 | 2 秒 |
| 停止 join 等待 | 3 秒 |

既有 `SensorStream` 的单独缓冲限额仍有效。
上表的字节数仅计保存的原始 payload，不是进程 RSS 上限；
DDS 历史、Python 对象、解码数组、流核心缓冲和原生算法内存另计，
并受各自消息数量/单帧/队列限制。当前限额没有通过现场生产验收。

时间以本机单调时钟计量。空闲时即使没有回调，也周期检查缺失传感器。
排队超时、数量/内存超限、错误帧、时间异常、原生或结果处理异常均锁定失败，
清空待处理队列，不重启同一对象、不补跑积压数据。
停止也立即丢弃队列；已进入的原生调用只能等其返回，迟到结果不再交给消费者。
引擎的关闭与计算仍由同一工作线程执行，不跨线程强行关闭。

如果原生调用挂起，查询状态或停止会报告失败及 `threadAlive=true`，
不会假称线程已终止。Python 无法强制安全终止原生线程；
在生产部署前仍需进程隔离、外部监督和实机异常退出验证。
结果消费者也必须有界，不应在该线程阻塞等待网页、网络或云端模型。

## Humble 范围

封装使用独立 Context 和 `SingleThreadedExecutor`，
不接受进程全局 ROS 重映射或参数覆盖；关闭 rosout 和参数服务。
两类订阅均为 `KEEP_LAST / BEST_EFFORT / VOLATILE`，
深度分别为点云 8、IMU 256。这些是待实测的显式诊断选择，不是交付 QoS。
不创建应用层 TF、地图、速度、动作发布器或服务/动作客户端。
标准 rclpy 节点本身仍会创建参数事件发布器等基础设施，
所以不能把“被动订阅”写成“零网络流量或没有任何 ROS 发布端”。

回调时间只代表消息进入串行回调队列时的本机时刻，
不能测出 DDS 内已等待多久、实际传感器采样时间或端到端延迟；
BEST_EFFORT 也不保证完整交付。真实 DDS 丢失/积压、启动发现、
长时运行和与语音并发的表现仍要单独测量。

本轮查阅 ROS 2 官方 rclpy `humble` 源码，
参考提交 `eb711390d1fd8d76f6fc700d137fd370c4cdf625`：
`node.py` 的节点选项/参数事件行为及 `context.py` 的幂等关闭。
该提交仅为 API 参考，不替代机器人实际安装版本的核对，
不把合成替身测试当作真实 rclpy 或 DDS 执行。

## 原记录消息比对

`tools/check_slam_message_adapter.py` 在隔离 Linux 环境读取原始混合消息顺序，
将新快照/解码输出与冻结的离线 `cloud_arrays`、IMU 解析逐项比较，
不启动工作线程、原生算法或 ROS。
完整输入在前后复验，执行源码快照和报告保存到全新的私有忽略目录。
公开聚合不含坐标、轨迹、绝对采样时刻、外参、设备地址或凭据。

| 数据 | 全部点云 / IMU | 完整点数 | 最大原始 payload |
|---|---|---:|---:|
| 静止 | 353 / 6,880 | 8,999,917 | 816,960 字节 |
| 行走 | 1,232 / 24,446 | 31,270,824 | 828,000 字节 |

所有坐标、逐点时间、整数 header 和 IMU 数值均完全一致；无点被丢弃。
这只能说明消息适配保持原数据，不能证明旧解码的时间解释已标定、
地图精度正确、在线性能达标或导航可用。

```sh
rtk proxy python tools/check_slam_message_adapter.py \
  --data-root "$PRIVATE_RECORDINGS" --output "$NEW_PRIVATE_MESSAGE_CHECK"
```

输出须在本项目 `.local/` 内全新目录，已有报告和采集不覆盖。
`docs/slam-message-adapter-evidence.json` 是本轮安全聚合报告的生成副本，
测试核对当前源码摘要与完整采集数量；完整原始消息仍保留私有。
