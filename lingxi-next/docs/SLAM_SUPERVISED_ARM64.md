# ARM64 原生录制回放监督验证

日期：2026-10-29。此次在真实机器人执行了准备阶段的 ARM64/Humble
监督入口，不是用电脑端结果或合成测试推断通过。
**独立 SLAM 仍未接入产品管理 API，网页/APK 与 0.1.19 归档没有切换后端。**

## 执行范围

现场人员先确认机器人静止、有人看护、坐在凳子上处于泄力状态，
随后明确确认急停按钮可随手操作。此次没有要求移动机器人。

新增 `tools/run_glim_supervised_target.py` 只负责一次验证协调：

- 使用显式地址和账号，经已保存的机器人主机密钥核对 SSH 身份。
- 凭据交互输入，仅存在内存，不写入源码、命令参数、报告或包。
- 将源码上传到全新普通用户私有目录，并逐文件回读校验摘要。
- 保持原 ARM64 core、matched-input bundle、完整 live 参考及配置不变。
- 显式选择 `header_is_scan_start` 时间假设和 `1.0` 回放速率。
- 使用清空继承环境的 Humble 解码绑定；不初始化 ROS、不创建 DDS 节点。
- 沿用原工作线程、健康 IPC、监督器与全部时限；原生子进程 nice 值为 10。
- 只请求本次自有进程的退出，不更改厂商服务或其他进程。

本次不是安装服务，不修改 SDK、厂商地图、语音配置或现有部署。
时间假设仅为原录制的诊断条件，并未被此次执行批准为正确标定。

## 实际结果

完整回调 journal 的 SHA256：

```text
492a5b33f04edfc85b5e5c18fbf5e9e0e5005b68480c6e3cfd191927d7d98bf8
```

- 4,144 次回调全部完成：197 帧点云、3,947 条 IMU。
- 拒收、丢弃和退出时队列残留均为 0。
- 196 个原生扫描结果：31 个初始化结果、165 个位姿结果。
- 首个 IMU 之前的 1 帧扫描单独计账，不伪造位姿。
- 原生创建、关闭各 1 次；3,930 次原生 IMU 调用。
- 原生实例由同一个非主线程创建、调用和关闭。
- 原生库实际加载摘要与原 ARM64 参考一致。
- 自有子进程、监督线程、工作线程及进程组正常退出，无强制终止。
- 另一次只读检查确认该子 PID 及 session/进程组已不存在。
- 原始清单、参考报告、完整录制摘要在执行后再次核对未变。

这次短回放的最大观测队列年龄约 99.421 ms，原生整帧墙钟 P95 约
63.634 ms、最大约 99.951 ms，工作段墙钟约 19.937 s。
这些值分别来自回放队列及原生调用，不是雷达到网页的延迟，
更不是语音首响、真实 DDS 长期运行或产品资源验收。

日志仍有 2 次 IMU prediction 告警，窗口为 64 和 128；
还存在使用默认 IMU 噪声参数的提示。没有隐藏、消除或更改这些提示，
也没有据此自动修改时间偏移、外参、噪声参数或初始化窗口。
本次结果不解决已有标定、几何真值和预测告警的验收缺口。
