## 已实现的可测试功能

- React/TypeScript 中文网页、同源 Capacitor 横屏 Android 工程、机器人地址与配对入口。
- 本机 HTTPS、仅内存会话、写入式凭据、受限文件、局域网 WebSocket 状态与地图。
- AIMDK v1.1.0 消息类型桥接、建图预检、停止保存后服务确认、地图重定位后状态确认、点位与朝向编辑。
- 只读查询厂商 `map.db` 地图登记，兼容 INTEGER 与规范十进制 TEXT ID，按数值排序，保留大于 32 位且不超安全整数的地图 ID；依据 `grid_map_info.txt` 把重定位位置从米转换为像素，再等待 SLAM 状态转换和新的 map 坐标定位数据。
- 扫图页直接绘制 LaserScan/PointCloud2 激光采样点的俯视投影，不从栅格图生成或伪造点云；按采样时刻 TF 显示机器人朝向；独立鉴权通道、缩放拖动、有限点迹累计和断流清空。栅格显示仅用于总览/地图管理。
- 导航与讲解状态机、多轮与等待、人工暂停、对话后安静五秒恢复、一次明确失败重试与跳点记录、普通导航无交互返航。
- 暂停/继续未获原生确认时保持故障任务；迟到到达事件不能推进讲解、下一点或返航，建图/切图互锁保留，需显式停止确认后才能解除。不将该门控视作原生导航已停止的证明。
- AIMDK v1.1.0 预设动作/表情白名单、动作状态轮询、实时灵创资源清单与版本绑定 ID；超时不重发，动作状态不确定时阻止后续导航。
- 灵创执行结果明确记为服务接受，不伪称播放完成；仅允许配置在单轮讲解最后一步。
- 真实唤醒状态门控、事件去重、白名单命令、低置信追问、Retriever 签名检索、模型超时和流式输出。
- 按 AgentSDK `vad_status` EOS 与同一对话 `tts_status.playing` 事件关联计算 VAD 至 SDK 播放态延迟；缺少 VAD 或匹配事件时不伪造样本。
- 现场位置与服务问题（附近/周边、厕所、饮水、餐饮等）必须走知识库检索；缺少达到阈值的依据时固定拒答，不交由通用模型猜地点。
- 语音事件入口先同步撤销旧轮次，再读取机器人状态；过期/乱序的唤醒、识别和结束事件不得替换当前轮次，导航/暂停下发前重验会话。Agent 断线时关闭被动回复，取消先于播报到达时保留取消墓碑，禁止迟到问答退化成独立播报；TTS 状态要求匹配唯一会话/条目、时间顺序和真实播放结束。
- 官方 AgentSDK 1.5.0-SNAPSHOT JAR 校验固定、Java 编译、被动回调、匹配 TTS 状态确认。预览 Function Call / Arbiter / 遥操不使用。

## 实机前必须解决的事项

1. 确认目标机器的 ROS setup、已编译 AIMDK setup、ROS_DOMAIN_ID、地图目录、激光话题与 TF 坐标树；实时栅格为可选。缺失时保持未就绪，不猜测，参见 LIDAR.md。
   当次只读检查已收到真实雷达点云和 BEST_EFFORT 任务状态；未发现 v1.1.0 的建图命令接收端、重定位接收端与按名称查图服务，未取得地图定位和完整 TF，不能开始建图/导航。
   已使用厂商实际 DDS 配置复核，结果不变。运行配置与图中内部 Proto RPC 不等同于公开 SDK 协议；
   需确认原生固件/兼容层启用条件，而非重命名旧接口、盲目重启或覆盖厂商系统。
   后续已在 `auto_integrated` 与 `map_manager` 启动日志确认组件因授权校验失败而未正常启动
   （`SignatureInvalid(5)`）。需由厂商恢复有效官方授权并确认版本配套，见 VENDOR_HANDOFF.md；
   进程存在、`Business` 模式或 SDK 已编译均不能替代接口就绪检查。
2. 目标机器必须同时报告真实 `listening_status`（含时间与事件 ID）、ASR `confidence` 数值。官方通用 ASR 参数没有保证该字段，缺失时 Java 会拒绝路由并报告 `asr_confidence_unavailable`；非数字、非有限或超出 0–1 范围则报告 `asr_confidence_invalid`。需用真实回调核对或接入厂商有依据的拒识/置信度接口，禁止字符串强制转换或默认 1.0 绕过。乱序与断线语义通过模拟事件验证，不代替目标设备验收。
3. 确认 `tts_status.item_id/event_id` 与 SDK 被动回复/任务流请求关联。没有匹配 playing+finished 状态时不报告播完。任务流 execute_ack 的成功不能证明播完，厂商文档说明超时也可能成功。
4. AIMDK 动作服务已按 v1.1.0 压缩包的 `.srv/.msg` 与官方示例实现，但仍需现场确认 X2 当前服务是否上线、输入源注册权限、预设动作姿态要求、真实资源清单和成功/失败消息。`GetMcPresetMotionState` 的成功状态用于确认预设动作结束；`PlayEmoji.success` 只确认表情服务接受；灵创 `ExecuteActionResource` 只有执行服务回包，没有播放完成回执，因此页面/任务只记录“已接受”，并保持导航/建图互锁，需操作员现场检查并确认动作停止后才能解除。该互锁会持久化，服务重启不会自行清除。不能把模拟资源名称当作实机资源。
5. 初始位姿接口已对照官方文档和附件实现，不再返回未适配。必须现场核对 `map.db` 的 `map_id/map_name` 字段、三行 `grid_map_info.txt` 格式与朝向语义；无参数从建图原点定位，有参数按填写的世界坐标/ROS yaw 定位。异常格式或超界坐标拒绝发送。等待原生 SLAM 重定位→定位状态转换，并要求位姿发送后的新地图坐标里程计；单独收到旧定位或仅发布命令均不算完成。见 COORDINATES.md。
6. 用户配好灵心应用、绑定智能体 ID、Retriever Agent Code 与模型配置后，再做云端调用验收。应用凭据与 Retriever 共用受限文件；修改后重启 Java 服务。
7. 已在 Linux 隔离文件系统运行真实安装/升级/回滚脚本，替换 systemd、架构、健康响应和运行时入口；验证文件、用户组、证书、备份、权限及失败流程。仍须完成目标 Linux ARM64 的真实服务启动和 Android 实机证书导入验收。
8. 旧服务停止与资源占用切换应由现场人员在备份后执行。本安装器不擅自停止旧版本服务；旧版绑定 3000 端口时先安排切换窗口。
9. 地图切换超时后保持导航阻塞；现场核对原生定位状态后才能重启本项目 AIMDK 桥接。没有通过重试绕过未确认的地图切换。桥接进程需要原地图目录的读取权限，安装器不修改厂商地图权限。

## 0.1.11 横屏扫图界面验证

Windows 浏览器使用隔离的本机演示 API 与模拟 LaserScan 进行检查，不连接真实机器人。
在 844×390 横屏视口中，激光回波点迹 Canvas 检测到持续绘制像素，画布约 452×185，
准备检查和采集控制位于画布右侧；1440×960 桌面视口也确认显示墙面点迹、机器人朝向和米制比例尺。
该验证只确认 UI 与模拟数据的渲染，不代表实际 X2 雷达话题、TF、SLAM 或实机扫描效果已验收。

管理台分开展示 API 入站至 SDK 播放态、VAD EOS 至 SDK 播放态两种 P95，并展示实际样本数。第二项仅纳入 Java 适配器收到 `vad_status.state=eos` 后，能与本轮 ASR/SDK 播放事件对应的样本；不完整或过期的 VAD 证据不会计入。`tts_status.state=playing` 表明 SDK 报告进入播放状态，不等于声学上已经可听。最终 ≤2 秒验收仍须在目标 X2 上同步记录 VAD EOS 和扬声器声学回录首音，覆盖失败/未播报样本并达到约定样本量；管理台 SDK P95 仅用于定位链路延迟，不能代替该验收。
