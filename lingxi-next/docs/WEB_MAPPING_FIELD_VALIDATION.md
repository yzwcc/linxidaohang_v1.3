# Web 建图现场验证

## 当前边界

本阶段先验收 Web 真实点云采集、显示、保存和重新查看，不把点云能够
显示等同于建图准确率或导航验收通过。现场移动使用外置遥控器，网页
不发送行走、关节或动作命令。Android 验证暂后置。

2026-10-31 的隔离实机 Web 会话已观察到实时 GLIM 点云更新，扫描计数
持续增长，并通过网页停止、保存和重新查看了静止采集地图。该地图仅
用于检查显示链路；没有完成移动建图、真实尺度标定或实际导航验收。
现场点云、配对码、证书私钥和运行配置不进入 Git。

## 现场流程

1. 使用已经配对的机器人 Web 页面，确认“实时建图”和“地图管理”可见。
2. 确认现场已准备好，再开始新的采集；先观察静止时点云与计数更新。
3. 现场人员使用外置遥控器，缓慢行进并转向，沿有重叠观测的路线返回。
   首轮只采集 2–3 分钟，并始终在本轮配置的单次采集限额内停止并保存。
   当前 r9 实机验证配置为 300 秒；更新后的页面从后端读取实际限额，
   不把 300 秒当成所有设备的默认值。
4. 检查墙体、转角等固定结构是否连续，转向后是否明显重影，返回起点
   是否出现重复轮廓。记录操作者估计的实际行进距离，不用原始坐标读数
   代替物理测量。
5. 输入地图名并“停止并保存”。收到目录校验确认后，使用“查看点云”
   打开同一会话保存的地图，检查轮廓是否保留。停止采集后没有实时点云
   属于正常空闲状态，不应作为传感器断线提示。
6. 建图质量经现场确认后，再做坐标标定、地图定位与短距离导航验证。
   在此之前不开放自动导航。

## 本地界面回归

```powershell
rtk npm test
rtk npm run build
rtk proxy node tools/check-mapping-lifecycle-ui.mjs
rtk proxy node tools/check-mapping-lifecycle-ui.mjs live
```

后两条命令启动限时、仅本机可访问的合成测试 API 与 Vite 页面，使用
独立浏览器会话，结束后关闭测试服务。它不连接机器人、不运行原生 SLAM，
也不能证明物理精度。报告和截图输出到被忽略的 `.local/` 唯一目录。

覆盖未开始时不建立点云订阅、保存后关闭实时订阅、保存结果的会话与
名称匹配、一次点击打开对应地图点云、放弃时不显示保存成功，以及桌面
1440×900 和横屏 844×390 布局。保存确认不依赖短时 toast，长地图名
正常换行，原始坐标仍明确标注未标定。
横屏和窄屏打开点云时优先展示预览，并检查画布至少 80% 的高度位于
当前视口，避免只有 DOM 中存在画布但用户实际看不到地图。

2026-10-31 本地回归：409 项通过，14 项按当前平台条件跳过；类型检查、
生产构建和六阶段浏览器流程通过。此 Web 改进尚未替换正在展示的 r9
实机包，不宣称已在机器人上部署新代码。

## 采集限额提示

实时 GLIM 后端将已验证配置中的 `maxSeconds` 作为可选状态字段传递给
API 和页面，在开始前及采集中显示“本轮采集上限”。只接受 5–300 秒的
有限数值；旧后端没有该字段、后端断开或使用录制回放时，不猜测限额。
该提示不增加客户端倒计时，不修改原生超时策略，也不会自动保存或重启采集。

2026-10-31 本轮回归：422 项 Vitest 测试通过，14 项按平台条件跳过；
全部 TypeScript 检查和生产构建通过。建图服务在 Windows 上 17 项通过、
3 项 Linux 专用测试跳过，在普通用户 Linux 环境中 20 项全部通过。
回放和实时模式各自通过六阶段浏览器流程，检查 1440×900 桌面和
844×390 横屏布局、真实画布像素及已保存地图身份匹配。实时合成夹具使用
120 秒，确认页面显示后端值而非硬编码 300 秒；未连接机器人或运行原生 SLAM。
本轮限额字段和提示尚未部署到正在展示的 r9 会话，也不在下述已冻结的 r10 包内。
