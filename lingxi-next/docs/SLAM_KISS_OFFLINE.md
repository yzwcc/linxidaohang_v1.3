# KISS-ICP 真实数据离线诊断

日期：2026-10-28。只在本机处理已完成采集并校验的静止/遥控环路数据。
**所有记录点云处理完成不等于轨迹正确；本轮不批准建图导航后端接入。**
本页记录的是较早的 KISS-only 里程碑，当时未执行 GLIM。
其后已完成 GLIM 的真实惯性里程计诊断，见 `SLAM_GLIM_OFFLINE.md`；
仍不是共同有效时段对齐、完整建图及目标机器人验收均通过的算法评比。

## 实际环境与依赖

本机 WSL Ubuntu 24.04 / x86_64，Python 3.12.3。
独立普通用户环境位于 `~/.cache/lingxi-next/kiss-env-20261028-b`；
最初 `-a` 环境缺少 ensurepip，原样保留，未为此安装系统包。
随后使用 `venv --without-pip` 创建新环境，由系统 pip 的 `--python` 选项
仅向该环境安装。从 PyPI 下载 24 个 wheel，安装时使用 `--no-index` 的本地缓存，
`pip check` 通过，没有安装 ROS、Open3D 或可视化程序。

| 直接依赖 | 版本 | 本轮实际 wheel SHA-256 |
|---|---|---|
| KISS-ICP | 1.3.0 / cp312 x86_64 | `762d319c26870af2ba190edf61e22390244305b27ba958fdb3b84a73a9916a5b` |
| rosbags | 0.11.9 / py3-none-any | `010c5a48b326e4dad6a79183db243c7b59188121d37b629d8c166ecaed3fc890` |
| NumPy | 2.5.4 / cp312 x86_64 | 见完整 wheel 清单 |

24 个本地 wheel 的文件名、哈希与安装版本记录在
`slam-kiss-offline-evidence.json`。完整安装报告保留在环境目录的
`install-report.json`。这是本轮 x86_64 / Python 3.12 的诊断环境，
**不是机器人 ARM64 / Humble 的运行依赖或部署包**。
本轮使用官方发布 wheel，未自行编译 KISS-ICP；
源码评估基线仍是 `slam-candidates.json` 中的固定提交，
不能声称发布二进制已证明与该提交逐字节对应。
操作系统、内嵌 C++ 依赖与许可证/SBOM 的完整发布锁仍未完成。

## 回放工具与配置

`tools/run_kiss_offline_trial.py` 使用 rosbags 的 `AnyReader`
和 Humble 标准消息定义读取已有 SQLite3 数据包，不启动 ROS、DDS 或运动接口。
回放前重新校验全部 5 个采集文件的哈希、数据库和话题数，
核对直接包版本及两个已固定 wheel 的哈希。
输出目录必须新建且不在数据目录中；目录权限 700，报告与私有数组文件 600。

点云转换支持大小端、组织点云行填充；要求本轮实际的
x/y/z FLOAT32、timestamp FLOAT64 布局。逐点值按**帧相对纳秒候选**
转成秒，检查非零跨度和有限值；KISS-ICP 自身在去畸变中按帧时间范围归一化。
坐标过滤与逐点时间共用掩码，不丢开一边后错配；不缺省生成伪时间。
全量点的布局/时间检查通过，仍不能批准扫描参考时刻、IMU 同步或外参。

两份明确标为诊断的配置均不声明标定/导航通过：

- `kiss-offline-profile.json`：范围 0.5–30 原始坐标单位、体素 0.3、
  每体素最多 20 点、迭代上限 500、收敛阈值 0.0001、线程上限 2、去畸变开启。
- `kiss-offline-no-deskew-profile.json`：仅将去畸变关闭，其余参数完全相同。

首份配置在第一次真实回放前确定，没有根据期望精度反复筛选参数。
关闭去畸变是在发现行走统计异常后增加的诊断消融，
不是独立测试集上的模型/参数选优，也不能据此单独归因。
初始开发回放 `static-a` / `dynamic-a` 保留；
补充运行器哈希、逐帧耗时及步长统计后，用同配置复跑至 `static-b` / `dynamic-b`。
所有轮次均登记，不隐去较慢或不理想的结果。

私有 `private-trajectory.npz` 保存轨迹、header 时间戳和逐帧耗时/配准点数，
仅留在本机受限目录，不进入 Git、APK、通用包或云服务。
公开 JSON 只从已完成报告白名单导出聚合值与校验和，并核对输入/运行器来源；
没有输出坐标序列或环境点云。

## 复现

先准备与本轮匹配的隔离环境和本地 wheel 缓存，再执行：

```sh
python tools/run_kiss_offline_trial.py \
  --manifest docs/slam-capture-evidence.json \
  --data-root "$HOME/.cache/lingxi-next/slam-datasets-20261028-a" \
  --dataset dynamic \
  --profile docs/kiss-offline-profile.json \
  --wheel-cache "$HOME/.cache/lingxi-next/kiss-wheels-20261028-a" \
  --output "$HOME/.cache/lingxi-next/new-kiss-diagnostic"
```

用 `--dataset static` 检查静止段，换另一份 profile 检查关闭去畸变的动态段。
本轮均以 nice 10、`OMP_NUM_THREADS=2`、`OPENBLAS_NUM_THREADS=2` 顺序运行。
入口没有机器人地址参数，不连接实机，也不替换产品中的厂商导航适配器。

## 结果与限制

真实结果登记于 `slam-kiss-offline-evidence.json`，不是合成输入跑分。
353 帧静止点云与 1,232 帧动态点云均完整处理，
分别传入约 900 万和 3,127 万个有限坐标点，没有非有限坐标被丢弃。
三维里程计仅给出有限的刚体变换，不代表每帧 ICP 都正确收敛；
本轮接口未提供可据以批准定位质量的逐帧置信度。

实际汇总如下，位移均为估计值/原始坐标单位，非外部真值：

| 轮次 | 帧数 | 配准 P95 / 最大毫秒 | 累计位置步长 | 首末距离 | 总处理墙钟秒 |
|---|---:|---:|---:|---:|---:|
| 静止初始 a，开启去畸变 | 353 | 8.00 / 9.12 | 0.65969 | 0.00209 | 2.982 |
| 动态初始 a，开启去畸变 | 1,232 | 141.71 / 440.67 | 66.20737 | 5.09566 | 56.883 |
| 静止复跑 b，开启去畸变 | 353 | 7.99 / 13.96 | 0.65969 | 0.00209 | 3.005 |
| 动态复跑 b，开启去畸变 | 1,232 | 129.60 / 390.77 | 66.20737 | 5.09566 | 52.138 |
| 动态消融，关闭去畸变 | 1,232 | 88.37 / 365.84 | 30.69767 | 4.85001 | 38.200 |

复跑 b 动态段有 116 帧配准耗时超过 100 毫秒，关闭去畸变仍有 44 帧超过；
两者最大相邻帧位置步长约 1.94 / 1.33 原始单位，
最大相邻帧旋转约 18.03 / 14.97 度。它们是待排查现象，不是正确运动证明。
同一数据的腿部里程计累计步长约 9.38、首末约 0.705 原始单位；
它也不是外部真值，但与激光估计的巨大差异不能忽略。
静止段短时统计较稳不能抵消动态段的一致性疑点。
关闭去畸变改善部分统计，却没有消除首末不一致；
尚不能据此确定是输入参考时刻、去畸变模型、场景几何还是里程计本身的问题。
**当前不接受 KISS-ICP 单独作为这台步行平台的交付定位/导航后端。**

本阶段未找到距离单位的明确来源；后续 GLIM 阶段已核对到 SDK 声明为米，
但物理尺度仍未实测标定，因此本页保留原始单位的历史结果，不将其改写成实测精度。
不能把累计带噪位移等同于实际走过的长度，
也不能把首末估计距离当成已测得的闭环精度。
包接收时长与 header 首末跨度不同，仍需区分启动缓存与时间语义。

耗时包含全部帧（含首帧），分别记录解码/转换和
`register_frame`（含去畸变、体素化、配准、本地地图更新）耗时。
总体处理墙钟包含读取与轨迹检查，不含前置文件校验/导入/算法构造。
离线按最快速度读取，不是在机器人上按真实节奏运行，
其 P95、平均倍速或内存不能作为 ARM64 实时性/语音并发保证。

三轮最终运行器都记录同一源码 SHA-256；两个初始开发轮次当时未记录该字段，
其原始报告及缺失状态均保留，不事后伪造来源哈希。
公开聚合文件由 `tools/export_kiss_trial_evidence.py` 从五份真实报告生成，
逐一核对完成状态、帧数、配置、运行环境、输入哈希和最终运行器哈希，
拒绝覆盖已有汇总；没有手工抄写数值或按好坏筛选保留轮次。

本阶段缺少外部轨迹真值，也尚未核对 IMU 单位、偏置、动态对齐和外参精度；
无回环优化、地图持久化/重载定位、失定位恢复或导航安全验收。
当前产品仍未接入开源导航后端，原 0.1.18/0.1.19 归档/APK 不变。

本轮检查：隔离 Linux 环境 113 项适配工具测试全部通过；
Windows 103 项通过，10 项 Linux/NumPy 专用测试明确跳过。
全部回放进程已结束；回放后再次核对原始副本的哈希、数据库和话题数一致，
未增加 WAL/SHM 文件。没有为产品前端、Java、Android 或目标机器人补写通过记录。
