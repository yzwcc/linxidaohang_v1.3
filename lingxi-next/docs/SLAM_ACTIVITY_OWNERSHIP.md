# 建图与定位共享运行锁

日期：2026-10-31。本轮只完成共享运行资源的接纳与进程生命周期管理，
没有连接机器人、启动实际 GLIM、发送运动指令或更新安装包/APK。

## 接入范围

`mapping_service.py` 与 `localization_service.py` 的命令行入口现在均使用
其 `--maps` 目录中的 `.slam-activity.lock`。同一保存地图目录、同一普通用户
启动的两项服务之间，只允许一项持有建图/定位运行资源。
冲突同步返回固定码 `slam_activity_busy`（409），不启动子进程；
定位服务被拒绝的请求不改变 service/run/generation，也不进入地图解析。

保存地图目录必须是直接的、当前普通用户所有的私有目录（0700）。
锁文件为 0600 普通文件，必须保持原位。不可在服务运行期间删除锁文件、
替换其 inode 或更换整个目录；升级/备份工具不能将它作为临时文件清理。

该锁不是机器人范围的全局租约：不同地图目录、未传入 `activity_gate` 的
嵌入式管理器、旧固定地图入口、独立诊断脚本及厂商进程不受它约束。
这不是允许手工并发运行这些入口的声明。后续统一所有者必须只开放经此接纳的
两项服务，并统一目录和退出流程，才能作为自动编排产品部署。

## 生命周期

- 在地图解析、命令构造和原生进程启动之前占锁；清理未确认时保持占用。
- `ProcessSupervisor` 只把租约文件描述符传给自己的工作进程，
  不把其他即使标记可继承的描述符传入；调用者不能从环境覆盖租约描述符。
- 管理进程异常退出不会主动解锁仍存活的工作进程。Linux 只有在同一打开文件
  描述的最后一个文件描述符关闭后才释放锁，代码不执行显式 `LOCK_UN`。
- 建图保存中的独立新进程地图重载，通过 `inherited_activity_fds()` 继续持锁；
  中间进程退出不代表重载进程退出。
- 正常停止、启动前失败及无子进程的地图解析失败会释放租约。
  工作进程或其进程组的退出无法确认时，不凭超时、线程结束或页面关闭释放。
- 管理器只在监督器确认清理且进程/监控线程均不存活时回收自身持有的租约。
  监督器可在已确认实际进程组退出后关闭自身描述符；该时刻不再占用传感器。

## 本地验证

测试在普通用户 Linux 中运行，不使用 ROS、机器人或原生算法来制造进程状态。

- `test_slam_activity_lease.py`：独立进程竞争、最终描述符释放、稳定 inode、
  管理进程被终止但工作进程仍存活、独立重载转交、启动失败、正常停止、
  不确定清理与文件/环境约束。
- `test_localization_service.py`：两服务双向切换、同时发起只接受一个请求、
  解析期间占用、取消、构造/启动/线程失败释放，以及清理未确认持续拒绝建图。
- `test_mapping_service.py`：清理确认前持续占用，仍存活的进程不能靠
  `cleanupComplete` 单个标志放行，以及服务关闭后释放。

这些结果不证明地图精度、实际传感器独占、实时定位恢复或导航避障可用。
定位与导航就绪标志继续为 false；live 单次有界时长保持不变。
