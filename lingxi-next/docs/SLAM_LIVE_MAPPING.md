# 独立实时建图网页实机联调

日期：2026-10-30。使用已有隔离 ARM64 GLIM 依赖和新建管理服务，实际订阅
Humble 雷达/IMU，完成 HTTPS/WSS 开始采集、点云重连、命名保存、全新进程重载、
放弃采集和真实网页操作。不依赖选配厂商 SLAM，没有发布运动指令。

## 产品变更

- 网页根据实际输入模式区分实时采集和录制回放，不再把实时 GLIM 显示为录制验证。
- 状态 API 与网页展示工作线程实际消息、扫描和位姿计数；缺失计数不补成零。
- 独立地图保存后的提示不再错误宣称由 AIMDK 确认。
- 失败状态统一为“建图未完成”，避免把启动或输入失败误写成保存失败。

本轮仅更新 `lingxi-next/`。没有替换 AIMDK、修改原有 3000 端口服务、安装
常驻服务或重建 APK。管理组合仍是受限的独立建图联调入口，不提供导航或语音。

## 实际流程

`tools/check-live-mapping.mjs` 在普通用户 AArch64 环境调用原有
`managed_mapping.py`，使用独立临时 TLS 与配对会话，验证真实 HTTPS 和 WSS。
同一管理服务先保存一张地图，再开始新会话放弃采集。两次均断开并重连点云客户端。
浏览器测试另启独立管理实例，没有使用模拟 API 或合成点云。

## 失败与边界

第一次网页采集尝试在 25 秒内未观察到点云，服务日志记录
`child_reported_failure`。当时没有完整的子进程最终报告，现有日志不足以确定原因。
该次管理服务仍正常清理退出；保留私有失败记录，没有将其计入成功次数。
随后新管理实例完成上述真实网页显示和保存。这说明实时完整流程能够运行，
但**启动成功率和长时间稳定性仍未验收**，不能用后一轮成功抹去前一次失败。

网页准备检查中的雷达项曾未与新点流健康状态联动，导致画布已有实时点云时
仍显示等待输入。该显示限制已由下述补充验证修复；它不是新增的传感器断流证据。

扫描基准假设仍为 `header_is_scan_start`，未据此批准硬件时间语义。
物理比例、重力方向、传感器到基座标定、现场地图关联、移动时的几何精度、
回环、独立定位恢复、Nav2 局部避障和自主行走均未验收。
原生 IMU 参数缺省警告仍存在。所有定位/导航就绪标志继续为 false。

## 复现

先按现有建图平台约束准备显式实时配置、已校验原生依赖、配套 Node 和编译资产。
以下仅在目标普通用户环境执行，不安装依赖或服务：

```sh
/private/verified-node/bin/node tools/check-live-mapping.mjs \
  --config /private/live-mapping.json --python /usr/bin/python3 \
  --api /private/build/api/main.mjs --web /private/build/web \
  --output /private/short-new-output --seconds 12
```

输出目录必须不存在，路径需满足 Unix socket 长度约束。每轮观察时间可选
10–30 秒，原生实时输入时限须保留至少 15 秒余量。该命令会真实订阅传感器、
生成一张测试地图后结束进程，不应在已有建图任务并行运行。

初次实时网页联调 `npm run build` 通过，Vitest 264 项通过、9 项明确跳过。
两份 Node 检查脚本均通过语法检查并实际执行；失败记录如上单独保留。

## 实时雷达状态补充验证

同日新增当前会话点流健康判断，仅用于隔离建图控制台，不覆盖厂商雷达状态。
需要同时满足实时输入、运行中、有效会话、当前会话的非空实时 SLAM 点云及
最近 2 秒内接收；接收时钟仅允许最多 50 毫秒的负偏差。断流超时、停止、
后台失效、会话更换或点管道不可用均撤销就绪，录制/合成点云不作为实时证据。
这只说明管理端正在接收实时点云，不代表几何质量、标定或导航就绪。

复用原有 ARM64 原生依赖和专用 `mapping-main.mjs`，通过 HTTPS 状态 API
及 WSS 实机复核两轮。每轮在点云重连后继续观察 10 秒：

| 检查 | 保存轮 | 放弃轮 |
| --- | --- | --- |
| 实时点云独立帧 | 54 | 54 |
| 采集中雷达就绪 / 停止后撤销 | 均通过 | 均通过 |
| 最终完整处理消息 | 2,965 | 2,980 |
| 已接纳消息拒绝 / 丢弃 | 0 / 0 | 0 / 0 |
| 点云重连 | 通过 | 通过 |

保存轮得到 110 帧、1 子图、2,515 点；放弃轮未增加地图。原生线程结束，
管理服务/API 均退出 0，无强制终止、残留子进程或进程组。没有运动指令，
没有新常驻部署，也没有改变原有 3000 端口服务。本轮未重跑浏览器或 Android。

辅助验证准备阶段的错误不计作成功：一次误选运行时被散列校验阻止；
一次误用普通 API 构建入口，父进程启动超时并终止 API，报告无残留子进程；
一次缺少新增散列清单中的源码文件，在启动管理进程前退出。修正私有辅助
脚本后使用新目录完成上述两轮。失败记录保留，不改变前文尚未验收启动可靠性的结论。

## 启动与失败诊断补充

同日补充管理服务、状态 API 和网页之间的故障信息传递。服务仅公开固定白名单
故障码，包括进程启动失败/超时、输入处理进度超时、退出超时和子进程状态异常。
未知故障归为通用建图失败；原始异常、私有路径和日志内容不下发到网页。
状态服务不可用时显示“无法确认建图服务状态”，不推断采集已经结束。

失败原因和清理状态分别报告。只有后台明确确认清理完成，网页才显示“进程已清理”；
清理未确认时不允许开启重叠采集。新会话不继承上一会话的失败信息。
运行提示使用实际消息、有效扫描和位姿计数区分等待输入、等待扫描和初始化阶段，
缺失计数不当成零；只有当前实时雷达就绪才提示实时点云持续接收。

本次验证仅在本机执行，没有部署到机器人或新增实机启动测试：

- Vitest 302 项通过、9 项跳过；建图服务 Python 测试 13 项通过、1 项因需普通用户
  Linux Unix socket 环境而跳过。
- `npm run build`、`npm run build:mapping-runtime` 和差异空白检查通过。
- 独立本地合成失败状态下，浏览器 1440 x 900 与 844 x 390 均正确显示
  “建图进程启动超时；进程清理尚未确认”，提示文字未截断，页面无横向溢出。
  该浏览器验证不是实机点云、Android APK 或启动可靠性验收。

前述首次启动失败原因仍未确定，物理标定、移动建图、定位恢复和自主导航的验收
