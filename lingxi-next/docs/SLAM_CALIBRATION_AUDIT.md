# 出厂标定、时刻 TF 与 IMU 告警核对

本轮核对沿用已冻结的原始录包、诊断 profile 和原生日志，
没有重新运行历史里程计/建图矩阵，也没有拟合或应用新标定。
另通过核对过主机密钥的普通用户 SFTP，只读获取了 SDK 指定的出厂标定文件。
机器人上没有写文件、改权限、运行新进程/ROS 节点、切换模式或发送运动命令。
现有 0.1.19 后端、AIMDK、地图、服务、安装包和 APK 均未改动。

## 出厂文件的实际范围

随附 AIMDK v1.1.0 压缩包中的英文坐标系文档明确区分：
URDF 是同型号的名义运动学模型；出厂文件记录每台机器人的传感器标定。
文档给出的路径是
`/agibot/data/param/protected/factory_calib/factory_calibration_params.yml`。
不能用网上其他版本的文件路径或同型号另一台机器人的参数代替。

`read_robot_calibration.py` 仅通过 SFTP 读取这一个文件，不执行远程命令。
限制为普通文件、最大 2 MiB，不接受文件符号链接；连续两次完整读取内容、
大小与修改时间均一致。原始副本和读取报告仅在忽略的 `.local/` 中保存。
没有改变原文件或其权限。

实际文件只有 `chest_lidar`、`head_rear_rgb`、`head_rgbd_rgb`、
`stereo_left`、`stereo_right` 五段，没有 `chest_imu`、
`waist_imu` 或 `lidar_imu_chest_front` 段。
胸部雷达旋转矩阵满足本次文件精度检查，但这不是物理标定精度验收。
**只有 base→LiDAR 参数，不能推导出 LiDAR→内置 IMU 外参。**
也不能把另一颗胸部/腰部 IMU 当成雷达 IMU。

两份原始录包里的 `lidar_chest_front → lidar_imu_chest_front` 静态变换
在全部记录中一致，并与已冻结 profile 一致。按 TF 的子坐标到父坐标语义，
它与 GLIM `T_lidar_imu` 的使用方向相符；这只排除了本轮发现的配置不一致，
没有证明安装精度、偏置或时间同步已合格。

## 机身到雷达不是静态链

两段录包中完整链均为：

```text
base_link -> pelvis -> waist_yaw_link -> waist_pitch_link
          -> torso_link -> lidar_chest_front
```

中间三条腰部边为动态 TF。对全部扫描分别查询两个预先声明的时间假设：
起点假设使用 header；终点假设使用 header 减本帧实测最大逐点偏移。
先按整数纳秒相减，不把 epoch 转浮点再减，也不固定减去猜测的 0.1 秒。
平移做线性插值，旋转使用 SciPy Slerp；动态样本间隔上限预先固定为 50 ms。
这是本次诊断限制，不是已经批准的生产/导航阈值。
没有外推、使用最新 TF 冒充采样时刻，或在缺边时补单位矩阵。

| 数据 / 假设 | 扫描 | 时刻 TF 可插值 | 未覆盖，不外推 | 实际使用最大动态间隔 |
|---|---:|---:|---:|---:|
| 静止录包 / 起点 | 353 | 341 | 12 | 22.05 ms |
| 静止录包 / 终点 | 353 | 340 | 13 | 22.05 ms |
| 行走录包 / 起点 | 1,232 | 1,222 | 10 | 43.99 ms |
| 行走录包 / 终点 | 1,232 | 1,221 | 11 | 43.99 ms |

在有覆盖的行走时刻，base→LiDAR 相对首个可用时刻的旋转最大变化
约 12.17° / 12.09°，平移变化约 3.41 / 3.56 cm。
这是运动学 TF 链的变化，不是外部测量的轨迹误差。
因此不能用单个出厂 base→LiDAR 变换覆盖整段行走，也不能把雷达位姿
直接改名成机身位姿。

后续独立后端必须在与里程计输出相同的有效时刻进行组合：
`T_map_base(t) = T_map_lidar(t) · inverse(T_base_lidar(t))`。
扫描 header 和算法所用的有效时刻必须分别保留；
地图坐标与重力方向也需明确，不能直接把某个原始轴当作平面导航竖直轴。
本轮没有把任何这类诊断转换发布到机器人 TF 或产品导航。

报告保留了出厂矩阵按字面/取逆两种解释与运动学链的数值对照，
没有选择较小者作为合格依据。静止录包的字面对照约为 3.69°、6.31 mm，
取逆对照接近 179°；不同参考姿态、名义模型和实测标定的关系尚未解决。
**这些差值不是已测出的标定误差，不能据此自动修正或批准外参。**

## 告警实际说明什么

核对的是构建时固定的 GLIM 提交
`1a197c999e4865f5cab7c9cd25474128413ebbca`，
`src/glim/common/imu_validation.cpp` 保持干净。
源码以优化后的状态作为比较参考，比较 IMU 预测和恒速预测，
不是与外部真值比较：

- 优化后速度小于 0.1 m/s 时跳过预测检查；该速度仍是估计值。
- 每累计 64 次有效检查输出一次统计。
- 旋转、平移、速度的 IMU 更优比例需分别严格大于 0.7、0.4、0.5。
- 独立的偏置幅度检查产生另一条告警；不能混同。

四个已发布的 paced-worker 日志没有预测告警；
两个实际实时订阅日志各有 2 次，累计窗口为 64、128。
实时两轮的旋转更优比例约为 0.80–0.88，平移为 0，
速度约为 0–0.02。六个日志都没有偏置幅度告警。
每份日志与其已发布报告摘要核对，不只搜索未验证的任意文本。

日志比例只保留两位小数，不能拿其舍入值重建严格阈值边界。
没有告警也不代表标定通过。实时输入和原录包不同，
本轮未定位这种差异的原因，更不能把它直接归因于 DDS、某一项外参或偏置。
没有关闭检查、调参数隐藏告警，或把“引擎有输出”当作精度证明。
