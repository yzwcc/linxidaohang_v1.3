# V1.3.8 r14 功能审查和验收说明

## 基线与历史核对

本版只以已经交付的 r13 完整包为运行基线，产品名保持 V1.3.8。基线 SHA-256：`c283bb8ca867e533e098443281aba93c6d5e8a8bac45b7c67081cf3d8cc5e7ed`。AIMDK、知识库组件、机器人底层导航算法和客户地图资源不替换。

已核对“V1.3.8 灵犀导航特殊版本”的历史记录。此前短期采用的强制 accepted、吞掉错误播报等方案已经撤回，本版不重新引入。动作服务 header.code=0 作为接收确认，非零 code 仍保留拒绝；接收确认不等于动作物理完成。

## 本次修复

| 功能 | 确认的问题或风险 | r14 行为 |
| --- | --- | --- |
| 网页一键启动 | 网页命令 20 秒超时短于脚本启动等待预算 | 调整命令与页面等待预算，最终仍检查真实服务状态 |
| 重复启动 | 并发请求重复启动，补语音也重启导航 | 同一后台共享启动操作；脚本加锁，仅补启动未就绪组件 |
| 网关部分离线 | voice 离线时网关返回 503，导航正常状态也丢失 | 只对有效的 degraded 健康响应保留各服务结果，语音离线仍继续启动 |
| 网关健康等待 | 两个上游各检查 2 秒，网页只等 1.8 秒 | 网关健康读取允许 5 秒，导航启动检查使用网关转发的导航接口 |
| 服务缓存 | 强制刷新紧接已完成请求仍可能拿到旧 inFlight | 先清理完成状态，再向调用方交付结果，保留并发合并和失效保护 |
| 灵心连接状态 | SDK 认证/上线回调可能早于启动日志，日志顺序判断误报离线 | Java 原子写入当前 PID 的连接状态；读取时校验运行状态和 PID |
| SOC2 语音恢复 | 按循环次数等待在 SSH 故障时远超设定等待时间 | 使用实际时间截止并增加 SSH 保活检测 |
| 动作误报失败 | Java 默认 5 秒，但动作桥允许等待 6 秒确认 | 动作单独至少等 15 秒，明确区分接受、拒绝、确认未知 |
| 不确定回执 | 动作已发出后，结果异常触发自动重发 | 丢失确认不重发动作，保留诊断日志并提示观察实际状态 |
| 动作指令 | 本地关键词先于模型，否定句可能误命中 | 常规流程先模型识别；增加否定/转述保护，保留有限离线补偿 |
| 语音带路 | 模型暂不可用即丧失明确的本地点名控制 | 对明确带路前缀和已保存点名作唯一精确匹配，不匹配则不执行 |
| 启动诊断 | 本机部署仍依赖 SSH 端口诊断、只检查端口/PID | 本机诊断验证本机账号命令；导航检查真实 HTTP 接口和进程标识 |
| 遗留 PID | 过期 PID 文件可能指向其他进程 | 操作前核对对应模块命令行，避免误停不相关进程 |

## 继承的修复

保留 r11-r13 已合并的 Java 运行权限、PID/日志目录、已编译 AIMDK 环境加载、连续导航、PNC 可选回验兼容、讲解任务保存、共享组元数据、启动阶段取消、旧启动回执归属、知识库筛选和文本模型输入、唤醒与会话窗口、灵创保护等逻辑。V1.3.9 的循环次数及其导航策略不混入 V1.3.8。

## 验证范围

候选代码已通过网页/服务、Python 导航讲解、Java 语音意图/模型异常恢复/动作传输、当前进程连接状态及 Linux 进程启动模拟。最终归档还需通过双层 SHA 校验、源码和运行文件对照、JAR 入口与类检查、Bash 语法、全新安装/重复安装/保留客户数据/升级/回滚验证；对应结果随外部交付验证报告提供，报告绑定最终归档 SHA-256。

测试使用本机 HTTP 对端和模拟 ROS 回执，没有将未执行的实机测试记为通过。未直接连接或部署机器人；未验证实际平台账号、麦克风阵列、底盘绕障或肢体完成回调。声学拒识测试验证现有元数据策略，不证明硬件已有 DOA/AEC/RNNoise。

## 现场比对

动作接受时不应再播报 `motion=1003, area=2，机器人动作服务拒绝请求……`；原始协议仍进入日志。真正非零拒绝会提示“这个动作请求暂未被接受，请稍后再试”；确认丢失或超时会提示“暂未收到动作确认，请先观察机器人状态”。本版没有把拒绝或超时伪装成物理成功。

网页启动完成前保持等待，结束时必须同时确认导航、地图、兼容网关、本机语音桥、Java 进程、灵心认证及机器人回调。只看到 systemd active、端口监听或命令退出 0，都不足以验收语音交互。

详细首次部署、已编译 AIMDK 检查、现场语音带路/动作验收和日志命令，见同目录《V1.3.8-r14-完整部署说明》。
