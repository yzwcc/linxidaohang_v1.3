# 灵犀 V1.3.8 r14 完整部署说明

产品版本仍为 V1.3.8，内部运行版本为 `1.0.19-20261017-r14`。这是独立完整包，可以直接在新机器安装，不需要预先安装 r11、r12、r13 或任何增量包。

本说明的主流程适用于 ARM64 机器人 SOC1、Ubuntu 22.04、ROS Humble，且 AIMDK 已编译到 `/home/agi/aimdk/install`。厂家底层软件、SOC2 内部网络及地图能力应正常。本包包含原有 AIMDK 压缩组件，但主流程复用已编译产物，不重新编译或覆盖 AIMDK。

## 1. 准备安装文件和账号

将以下两个文件上传到机器人 `/home/run`：

- `lingxi-v1.3.8-complete-20261017-r14-deployment.tar.gz`
- `lingxi-v1.3.8-complete-20261017-r14-deployment.tar.gz.sha256`

以 `run` 账号登录 SOC1。准备灵心 APP ID、AppKey、AppSecret、豆包 Ark API Key、模型标识、知识库智能体 `AI_AGENT_...`，以及 SOC2 的 run 密码。不同平台的应用配置必须配套，不直接沿用其他机器的密钥。

```bash
whoami
uname -m
id run
id agi
sudo -v
timedatectl status
sudo test -r /opt/ros/humble/setup.bash
sudo test -r /home/agi/aimdk/install/setup.bash
sudo test -d /agibot/data/var/MapManagerModule
```

当前用户应是 run，架构应是 aarch64/arm64，两个厂家账号应存在，系统时间应正确。若 run 无 sudo 权限，需要由设备管理员提供本机安装权限。

已安装必要工具时可跳过 apt：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl openssh-client python3 iproute2 util-linux nano
command -v python3 curl ssh ssh-keygen ssh-copy-id tar ss flock sudo
```

包内已提供 ARM64 Node 和 Java 运行时，无需另装 Node、Java。机器人本机模式的网页运维直接以配置账号执行命令；SOC2 仍通过 SSH 管理。

## 2. 校验并解压完整包

```bash
cd /home/run
sha256sum -c lingxi-v1.3.8-complete-20261017-r14-deployment.tar.gz.sha256
tar -xzf lingxi-v1.3.8-complete-20261017-r14-deployment.tar.gz
cd /home/run/lingxi-v1.3.8-complete-20261017-r14-deployment
sha256sum -c SHA256SUMS.txt
```

必须全部显示 OK。校验失败应重新上传原文件，不编辑脚本或重算清单绕过校验。本包的校验清单使用 Linux LF 换行。

```bash
sudo -u agi env -i \
  HOME=/home/agi USER=agi LOGNAME=agi SHELL=/bin/bash \
  PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
  LANG=C.UTF-8 bash --noprofile --norc <<'BASH'
set -e
set +u
source /opt/ros/humble/setup.bash
source /home/agi/aimdk/install/setup.bash
set -u
python3 - <<'PY'
```

若失败，先修复已编译产物的路径或读取权限。仅在当前终端 source 其他 AIMDK 路径，不能代替安装器的固定路径检查。`PncTaskResponse` 是可选回验类型，缺失时仍使用既有到达判定。

**已经编译 AIMDK 的机器不要执行 `prepare` 或 `01-replace-aimdk.sh`。** 只有确实缺少 AIMDK 的新机，才走包内 `prepare` 和 AIMDK 编译流程。

## 4. 首次完整安装

先查看端口占用；其他程序占用时先核实归属，不直接 kill。

```bash
sudo ss -ltnp | grep -E ':(3000|8002|18080|18082|18083|18084) ' || true
```

仍以 run 执行完整安装：

```bash
cd /home/run/lingxi-v1.3.8-complete-20261017-r14-deployment
read -r -p "请输入知识库智能体 Code（AI_AGENT_...）: " LINGXI_AGENT_CODE
bash ./install_all.sh install --agent-code "$LINGXI_AGENT_CODE"
unset LINGXI_AGENT_CODE
```

依次填写灵心 APP ID、AppKey、AppSecret、Ark API Key、豆包模型、机器人名称、SOC2 地址。默认模型为 `doubao-seed-2-0-mini-260428`，需要该账号有相应权限；默认 SOC2 地址为 `10.0.1.42`。

随后根据提示输入 SOC2 的 run 密码，用于安装 SSH 公钥和配置受限的语音服务重启权限。首次安装不添加 `--skip-soc2-setup`。

安装包含导航、地图网页、Java 语音 Agent、普通动作与灵创接入代码、知识库服务、运行权限及 systemd 服务。无需再执行 `install-navigation`、`install-addons` 或旧版增量安装脚本。实际动作、表情、灵创资源依赖机器已有的厂家资源。

安装成功应输出“灵犀 V1.3.8 完整产品已安装”。安装器不会自动让机器人走动；业务服务还需要下一步启动和验收。

## 5. 一键启动和服务验收

```bash
bash ./install_all.sh preflight
hostname -I
```

打开 `http://机器人局域网IP:3000/console/`，点击“一键启动全部服务”，等待完成。重复点击会共享同一次启动操作。修复语音时，已正常的导航、地图和兼容网关会保持运行。

也可在终端启动：

```bash
sudo sparkrobot-lingxi-internal start
sudo sparkrobot-lingxi-internal status
bash ./scripts/03-verify-after-web-start.sh
bash ./install_all.sh doctor
```

检查实际版本和当前 Java 进程状态：

```bash
sudo readlink -f /opt/sparkrobot/lingxi-nav/current
sudo systemctl show lingxi-java-agent-robot.service \
  -p User -p ActiveState -p SubState -p ExecMainStatus -p NRestarts
sudo bash /opt/sparkrobot/lingxi-nav/current/scripts/java_agent_control.sh status
sudo ss -ltnp | grep -E ':(3000|8002|18080|18082|18083|18084) ' || true
```

current 应指向 `/opt/sparkrobot/lingxi-nav/releases/1.0.19-20261017-r14`。Java 状态应为 `running=true`、`lingxi_connected=true`、`robot_online=true`，且 NRestarts 不持续增加。`active` 只表示进程存在，不等于平台和语音回调已经连通。

## 6. 功能验收

1. 在网页选择实际地图，完成现场重定位，确认定位数据持续更新。
2. 新建或编辑一个讲解任务，保存后刷新，确认步骤、等待时间、动作和命令词仍在。
3. 唤醒后询问一个普通问题，再询问知识库中明确存在的问题，确认针对提问作答，无无限复读。
4. 唤醒后说“带我去网页中已有的点位名称”，核对目标并观察导航状态。测试停止、连续导航、开始/暂停/继续/结束讲解。
5. 站稳后说“能不能跟我握一下手”“给我比个心”，确认动作只发送一次。说“不要握手”，应不执行动作。
6. 执行灵创动作时验证保护和结束后语音恢复；验证讲解可打断、交流结束后的自动恢复与等待步骤的无人交流计时。

动作接口返回接受，只证明指令被接受，不证明肢体已经完成动作。若语音提示“暂未收到动作确认，请先观察机器人状态”，先观察动作和日志，避免立即连续重发。

大模型正常时负责灵活意图识别。大模型暂不可用时，仅对明确的普通动作命令和“带我去/导航去 + 已保存点名”的精确匹配提供本地控制补偿；不猜测地点，不代替问答服务。

降噪拒识沿用已有的唤醒、会话时限、方向/质量元数据和语义过滤策略。本更新不凭软件包新增麦克风阵列 DOA、AEC 或 RNNoise 硬件链路。必须结合现场真实音频验证，不能把模拟元数据测试当作实测降噪效果。

## 7. 旧版安装和 r11/r12/r13 快速更新

本教程第 1 至 6 节就是完整首次安装流程，不依赖任何旧版本。

已经完整部署 r11、r12、r13 且知识库服务正常时，可保留现有平台密钥和 SOC2 配置快速更新：

```bash
cd /home/run/lingxi-v1.3.8-complete-20261017-r14-deployment
bash ./install_all.sh upgrade
```

更新后按第 5、6 节启动和验收。AIMDK 不重装，地图、点位、讲解任务、知识库配置和灵创资源保留。此快捷命令只接受明确列出的内部运行版本，避免将不兼容的旧包混用。

r10 或更早的 V1.3.8 使用第 4 节完整 install 流程，重新填写平台配置；安装器保留已有地图/任务数据。升级前先备份客户配置，不能直接混装旧增量。

```bash
LINGXI_BACKUP="/home/run/lingxi-before-r14-$(date +%Y%m%d-%H%M%S).tar.gz"
sudo tar -czf "$LINGXI_BACKUP" -C / \
  etc/sparkrobot/lingxi-nav \
  var/lib/sparkrobot/lingxi-nav \
  etc/sparkrobot/lingxi-kb
sudo chown run:run "$LINGXI_BACKUP"
chmod 0600 "$LINGXI_BACKUP"
unset LINGXI_BACKUP
```

备份含密钥，只留在受控位置。

## 8. 修改 APP ID 或豆包密钥

```bash
sudo cp -a /etc/sparkrobot/lingxi-nav/lingxi-nav.properties \
  /etc/sparkrobot/lingxi-nav/lingxi-nav.properties.bak.$(date +%Y%m%d-%H%M%S)
sudo nano /etc/sparkrobot/lingxi-nav/lingxi-nav.properties
```

修改 `lingxi.appId`、配套 `lingxi.appKey`、`lingxi.appSecret` 或 `doubao.apiKey`、`doubao.model`。保持 `lingxi.callbacks` 的当前有效配置，不为修复密钥随意切换回调类型。

```bash
sudo systemctl restart lingxi-java-agent-robot.service
sudo bash /opt/sparkrobot/lingxi-nav/current/scripts/java_agent_control.sh status
```

## 9. 日志与回滚

```bash
sudo tail -F \
  /var/log/sparkrobot/lingxi-nav/java-agent.log \
  /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log \
  /var/log/sparkrobot/lingxi-nav/voice_nav_gateway.log \
  /var/log/sparkrobot/lingxi-nav/robot_lingxi_bridge.log
```

按 Ctrl+C 退出监听。日志中将保留真实动作服务返回值及模型/桥接错误；发送日志前检查有无客户隐私或凭据。

从 r13 快捷更新后需要回退时，使用仍保留的 r13 运行目录和包内旧控制脚本：

```bash
cd /home/run/lingxi-v1.3.8-complete-20261017-r14-deployment
sudo sparkrobot-lingxi-internal stop
sudo sparkrobot-lingxi-internal rollback 1.0.19-20261017-r13
sudo install -m 0755 ./scripts/control-r13.sh /usr/local/sbin/sparkrobot-lingxi-complete
sudo sparkrobot-lingxi-internal start
sudo sparkrobot-lingxi-internal status
```

首次新机安装没有旧运行目录时不适用此回滚命令。从 r11/r12 更新的，回滚版本和 control-r11/control-r12 脚本必须配套。
