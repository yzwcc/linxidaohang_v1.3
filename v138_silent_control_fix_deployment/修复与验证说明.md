# V1.3.8 静默启动回执实现与验证

## 处理范围

本版将语音导航和开始讲解的控制回执从语音渠道移除，执行结果保留在 HTTP 回执、网页状态和日志中。静默不改变 `accepted` 的真实含义，未知回执不会当作成功，也不盲目重发非幂等指令。

SDK 在意图明确后、控制提交前发送 `onInterrupt(eventId, "chat", null)`，随后完成空回复流。无 `onSkill`、成功/失败文本、音频内容或控制失败 `onError`，SDK 接管消息发送异常也不会阻止本地控制或追加失败语音。该消息是协议接管请求，不代表 SDK 已确认原生全链路静音。

明确唯一的已保存点位指令直接路由；否定、引用、条件句及说明性问题继续遵循拒绝误执行规则。模型解析的导航与讲解意图也经过相同静默出口。

bridge 只对携带真实布尔 `silent_control_reply=true` 且带事件 ID 的会话静默导航失败提示。手动网页请求、其他会话和自动返航的提示不会因为一个语音事件被全局关闭。配置的到点讲解及任务正文正常播报。

## 累计修复

继承 1.0.0～1.0.7 的动作回执、重复控制防护、普通问答恢复、导航/讲解路由、静止近点到达、TTS 异步回执和有限优先级重试。没有补造 AIMDK `PncTaskResponse`；缺少该类型时继续使用改进的里程计判断。持续高优先级占用仍可能拒绝讲解正文 TTS。

## 验证方法

使用本包实际 JAR 注册真实 AgentSDK 回调，并接入本地 HTTP 模拟端。覆盖文本和兼容音频回调、两种播报模式、两种旧文本抑制配置、成功/忙碌/拒绝/无效任务/畸形 JSON/错误布尔/HTTP 503、重复回调及 SDK 发送异常，断言只执行一次、不产生回执语音、SDK 接管先于本地提交、流正常结束。

对不可变 1.0.7 JAR 运行同一新测试，确认旧版本确实不能满足静默需求。旧回归测试按本次明确变更更新启动回执的期望，其他动作、问答、急停与回执未知保护继续检查。

Python 测试覆盖任务和用户导航静默作用域、手动/自动返航策略及讲解正文保留。Linux 安装器测试覆盖原始版本、1.0.7 升级、重复安装、独立服务状态、失败回滚、权限、未知改动拦截和后续变更保护。

实际测试统计、归档 SHA256、源文件与运行字节码复现结果见旁边的 `交付验证结果.json`。

最终包已通过 17 组 Java 回归，其中静默回执专项为 3,648 个断言；183 项 Python 测试、48 项 Linux 安装及回滚测试通过；47 个编译类与包内 JAR 字节一致。使用同一静默专项检查旧 1.0.7 JAR，有 1,632 个断言失败，确认本次测试能够区分旧行为和新行为。校验文件及所有脚本、源码、文档均为 LF 换行。

本次未连接或部署机器人，未做真实麦克风、厂商原生进程播报和机械运动验收。不能声称零 bug 或保证厂商所有独立提示均已拦截。
