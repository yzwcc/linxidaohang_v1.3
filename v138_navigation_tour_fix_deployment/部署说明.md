# V1.3.8 导航与讲解语音修复 1.0.6

日期：2026-10-19。

适用于已安装 V1.3.8 r11 至 r16 的机器人，也支持已经安装控制回复修复 1.0.0 至 1.0.5 的上述版本。包含这些控制回复增量的累计功能，只需安装本包一次。V1.3.9 和无法识别的现场修改不在本包覆盖范围内，安装器会在写入前核验版本与文件指纹。

## 本次修改

1. 原来只有模型报错时才校验“带我去门口”等明确导航指令。现在模型正常返回但误判为聊天、握手或其他目的地时，也使用当前地图真实保存的唯一点位纠正，再提交导航请求。保留大模型对灵活表达的识别能力；不猜测不存在或歧义的目的地。
2. 补充“开始一下讲解任务”“执行讲解任务”“开启讲解”“开始导览”“讲解任务开始”等启动表达。网页自定义开始命令仍按服务端返回的任务 ID 执行。否定、转述和操作说明问题不通过新增规则触发任务。
3. 继续沿用前版的控制回复所有权、SDK 完成后本机播报、重复回调去重、动作错误播报处理和问答恢复逻辑。不将服务真实拒绝伪装成执行成功。

这次修复解决应用内的意图路由和错误回复来源。没有本次复现的原生 Agent/SOC2 日志，无法证明那句“抱歉，暂时没有学会这个动作”全部来自本应用，也没有把机器人独立原生播报拦截描述为已完成实机验证。若请求未到 Java 回调，需要依据同一时刻的原生日志继续定位，见文末。

## 安装前

先在网页结束讲解任务并停止机器人运动。将以下两个文件上传到机器人 `/home/run`，直接使用原始文件名：

- `sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.6-20261019.tar.gz`
- `sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.6-20261019.tar.gz.sha256`

上传文件不等于安装。不需要重装完整包、不需要重新编译 AIMDK。

## 校验与安装

下面整段可复制到机器人终端执行。每步成功才继续下一步，防止校验失败后在错误目录执行安装。

```bash
cd /home/run &&
sha256sum -c sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.6-20261019.tar.gz.sha256 &&
tar -xzf sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.6-20261019.tar.gz &&
cd sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.6-20261019 &&
sudo bash ./install.sh --check &&
sudo bash ./install.sh
```

看到“导航和讲解语音路由修复安装成功：1.0.6-20261019”才表示成功。记录安装器输出的事务备份路径。重复安装同一个包不会重复重启。

安装器只更新当前 release 内的应用 JAR 和对应运行清单；保留所有者、组与权限，并以 systemd 实际运行用户检查 JAR、SDK、配置及主类是否可读。校验 Java 实际加载路径，拒绝旧覆盖包。地图、讲解任务、模型密钥、知识库、唤醒设置、`lingxi.callbacks` 和 AIMDK 不变。

如果安装前 Java 正在运行，安装后会恢复并检查进程稳定性；原来已停止则保持停止。安装失败自动恢复本次备份。`--check` 检查版本、指纹、权限及加载路径，不发起导航或动作。

## 启动与现场验证

如果安装前服务已停止，请通过网页“一键启动全部服务”启动，或执行：

```bash
sudo sparkrobot-lingxi-internal start
sudo sparkrobot-lingxi-internal doctor
sudo systemctl show lingxi-java-agent-robot.service -p ActiveState -p SubState -p ExecMainStatus
```

确认当前地图包含点位“门口”，讲解任务已保存，并确认所在区域允许运动。先运行以下只读检查：

```bash
curl -fsS http://127.0.0.1:18082/points | python3 -m json.tool
```

随后开启日志，在另一终端或网页操作机器人：

```bash
sudo tail -n 100 -F /var/log/sparkrobot/lingxi-nav/java-agent.log
```

逐项验证，每项完成或主动停止后再测试下一项：

1. 唤醒后说“带我去门口”或“灵犀，请导航去门口”。导航服务接收后应只产生正常确认“收到，正在前往门口。”，机器人开始导航。模型误判被纠正时日志出现 `Saved-point navigation intent corrected`。真实 busy/无定位等问题仍需处理，不能只以听到确认作为到达证明。
2. 唤醒后说“开始讲解任务”或“执行讲解任务”。应提交任务启动并收到正常确认，网页任务进度开始变化。
3. 使用网页保存的自定义开始命令，确认启动的是对应任务。
4. 再测普通问答、握手、暂停/继续任务，确认原有能力正常。同一条 ASR 的两个回调不会重复下发导航或讲解。

## 回滚

在增量包目录执行，把下面路径改成这次安装输出的真实备份路径：

```bash
sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-control-reply-fix/backups/本次安装输出的备份目录
```

仅恢复此次替换的 JAR 与运行清单；如果后续已经安装其他修改，安装器会拒绝覆盖它们。回滚保持回滚前 Java 服务的运行或停止状态。

## 如果仍听到原生“抱歉”

保留复现的准确时间，以及“是否收到正常确认、网页导航/任务状态是否变化”。先提取本机应用证据：

```bash
out="/home/run/lingxi-routing-$(date +%Y%m%d-%H%M%S)"
mkdir -m 0700 "$out"
sudo tail -n 1600 /var/log/sparkrobot/lingxi-nav/java-agent.log > "$out/java-agent.log"
sudo journalctl -u lingxi-java-agent-robot.service --since "15 minutes ago" --no-pager > "$out/java-journal.log"
sudo systemctl show lingxi-java-agent-robot.service -p ActiveState -p SubState -p ExecMainStatus -p NRestarts > "$out/java-state.txt"
readlink -f /opt/sparkrobot/lingxi-nav/current > "$out/release.txt"
sudo sha256sum /opt/sparkrobot/lingxi-nav/current/java/robot-local-navigation-java-all.jar > "$out/java-sha256.txt"
curl -fsS http://127.0.0.1:18082/points > "$out/points.json" 2> "$out/points-error.txt" || true
tar -czf "$out.tar.gz" -C "$(dirname "$out")" "$(basename "$out")"
printf '日志包：%s.tar.gz\n' "$out"
```

原生播报排查还需要相同时间段 SOC2 上 Agent/Interaction 服务的日志和实际加载的技能配置。仅靠 Java 日志不能证明原生失败播报的来源；不要为此关闭全局语音、安全提示、原生唱歌或跳舞。日志可能包含用户说话文本，按现场要求传递。
