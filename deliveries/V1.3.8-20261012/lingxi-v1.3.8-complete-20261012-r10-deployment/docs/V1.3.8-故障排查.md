# 灵犀 V1.3.8 故障排查

## 1. 先看总状态

```bash
sudo sparkrobot-lingxi-complete status
sudo sparkrobot-lingxi-complete doctor
```

如果只需要看服务是否存活：

```bash
systemctl is-active lingxi-nav-console.service
systemctl is-active lingxi-java-agent-robot.service
systemctl is-active sparkrobot-lingxi-kb.service
ss -ltn | grep -E ':(3000|8002|18080|18082|18083|18084) '
```

## 2. 动作不执行

确认机器人处于稳定站立状态，并查看：

```bash
sudo grep -E "STAND_DEFAULT|motion request|motion rejected|NOT_READY|SAFE|stable stand|input source" \
  /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log \
  /var/log/sparkrobot/lingxi-nav/java-agent.log | tail -n 200
```

正常路径应看到动作请求被接受，或者先看到 `STAND_DEFAULT` 恢复后再看到原动作请求。不要只根据 HTTP 200 判断动作完成，AIMDK 的响应只代表请求被接受，实际完成由动作状态和讲解流程控制。

## 3. 讲解到第二个点位不走

```bash
sudo tail -n 600 /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log
sudo grep -E "task_wait|interaction|next|PNC|completed|timeout|same_point|start navigation" \
  /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log | tail -n 300
```

重点确认：

- 到达事件是否被 PNC 或里程计确认。
- 等待是否从最后一次用户交互重新计时。
- 下一点位 ID 是否变化。
- 是否误把旧计时器回调当成当前任务回调。

## 4. 语音没有回答

```bash
sudo tail -n 0 -F /var/log/sparkrobot/lingxi-nav/java-agent.log | \
  grep --line-buffered -E "Robot online|Authentication|Wake|wake|quality gate|SOC2|Doubao|Audio2Tts|TTS|ignored"
```

无唤醒词时出现 `wake_required_or_session_expired` 属于预期拒识。正常唤醒后应出现唤醒证据、用户文本、模型/知识库请求和 TTS 输出。若出现网络错误，先检查机器人到灵心和豆包的网络，不要先改动作代码。

## 5. 网页无法一键启动

```bash
sudo sparkrobot-lingxi-complete repair-permissions
sudo systemctl daemon-reload
sudo systemctl restart lingxi-nav-console.service
curl -fsS http://127.0.0.1:3000/health
```

如果日志出现 `known_hosts` 或 PID 文件权限错误，确认：

```bash
sudo ls -ld /home/run/.ssh /var/lib/sparkrobot/lingxi-nav/pids /var/log/sparkrobot/lingxi-nav
sudo sparkrobot-lingxi-complete repair-permissions
```

## 6. 回滚原则

不要手工删除 `current`、`releases` 或 systemd drop-in。使用安装器生成的事务备份回滚，并保留失败日志。
