# V1.3.9 r5 功能复核报告

复核日期：2026-10-19。完整版本 `1.3.9-complete-20261019-r5`，导航主包 `1.0.23-20261019`。本报告覆盖软件功能、实际 HTTP 与本地文件链路；没有连接机器人进行运动、声学或云平台验收。

## 1. 对用户重点问题的结论

| 问题 | 修复后的行为 | 本地验证证据 |
|---|---|---|
| 任务能否保存 | 保存任务名称、编号、命令词、循环、点位顺序、讲解、等待、动作和表情；地图 JSON 原子替换，同服务并发保存串行处理 | 真实 Node 路由、RobotClient、Python HTTP 服务和 MapPointStore；22 次控制台请求；16 个并发任务写入均保留；替换失败保持旧文件 |
| 保存后能否开始 | 按指定任务编号启动，使用当前地图内保存的步骤；多个任务之间不会把“当前编辑任务”误当成指定执行任务 | 保存两个任务，再启动较早任务，收到正确首点 p2；新建存储对象并重载后仍能启动 |
| 禁用、空任务是否报底层错 | 明确拒绝执行，返回 no_task_steps；无效编号返回 invalid_task，不启动导航 | 复现并修复禁用任务分支少返回一个字段导致 HTTP 500 的错误 |
| 是否存在错误动作编号 | 已纠正比心从旧生成枚举 3004 改为现行文档 1007，其余 17 类普通动作与配对表核对 | 18 类动作及其区域测试；两种 SDK 请求结构字段测试 |
| 动作回执丢失会不会重复做 | 不自动重发；标记 confirmation_unknown 或 confirmation_timeout，不把未知当完成 | 7 项异常回执测试；旧代码有 4 项失败，修复后通过 |
| 是否去掉强制关闭唱歌 | Java 的“唱歌功能暂时关闭”分支已删除；原生唱歌命令不依赖模型或导航服务，不提交本地仿唱 | 实际 Asr2Llm、Asr2Tts 回调，robot/lingxi 两种播报路径；没有关闭提示、本地播放、技能重发或错误播报 |
| 是否去掉跳舞强制干预 | 不再先打断原生舞蹈，不再本地重复准备播报或提交另一份舞蹈资源 | 相同实际 SDK 回调测试，普通跳舞和太极均无 interrupt/本地媒体调用/重复 skill |
| 底层版本是否混装 | AIMDK、AgentSDK、ARM64 Node/JRE、知识库使用固定组件；新 Java 与 Python 按构建记录装入新包 | 构建前基线校验，包内源码与运行文件一致，doctor 校验实际 JRE/classpath/进程目录与 JAR 哈希 |

“请求已接受”只代表机器人接口确认收到请求，不能当成物理动作已经完成。原生唱跳保留也不能代替现场确认机器人已经安装对应资源且平台功能可用。

## 2. 任务编辑与执行

- 每张地图独立保存点位和多个讲解任务；任务包含名称、编号、启用状态、命令主题和自然启动短语。
- 循环次数 1～20，默认一轮；网页和后端检查范围，保存和重新读取保留该字段。
- 每步可以选择点位，设置讲解文本、无人交流等待 0～300 秒、到点动作、表情和已下载的灵创资源。
- 步骤可以继承点位默认动作，或显式覆盖/关闭动作和表情；任务讲解文本覆盖该步的点位讲解。
- 网页保存成功后清除相关数据缓存，重新读取磁盘数据；写入失败不会用半份 JSON 覆盖原任务。
- 支持按编号开始、暂停、继续和停止。导航途中暂停会取消当前导航；待导航停止后继续前往当前步骤。
- 人工暂停保持暂停。讲解中的有效语音交互暂停问答后，可按原有安静恢复策略恢复；安静等待会被后续交互重置。
- 灵创动作执行期间保留保护，普通暂停/问答不能随意穿插；显式结束任务仍有停止路径。
- 连续同点步骤只有在前一步真实到达时复用位置。失败跳过同点不能冒充已经到达。
- 导航失败按任务策略重试一次，仍失败则记录跳点并继续；这与普通动作回执不确定时“禁止重发”是两条独立流程。
- 删除点位后，持久化任务中的失效引用会被清理；切换地图后不能启动另一张地图的任务。
- 保存的是任务配置，服务重启后可重新选择启动；本次没有实现断电后自动续跑到中断步骤。

## 3. 导航与地图

支持地图列表、地图显示、点位增改删、别名、朝向及起点设置，地图页保留机器人位置显示和重定位入口。可通过网页或有效语音启动点位导航、取消导航和讲解任务。

保留密集人流配置：请求速度上限 0.30 m/s；点位本身更低的速度仍保留。到点位置容差 0.45 m，方向容差默认 30 度，需满足低速稳定条件。自动返航保留原有空闲等待策略。

受阻提醒依据里程计停滞检测，不识别人身份。持续停滞约 5 秒后请求礼貌提醒，之后每 5 秒最多一次；移动、转向或进入到达区后停止。

窄通道策略只对已识别的 A2 PNC app2.yaml 自动应用，其他机型明确拒绝；显式跳过会记录状态。厂商 footprint、碰撞检查和 failsafe 仍由原导航链路负责。现场避障、路径和到点效果需真机确认。

## 5. 唱歌和跳舞

r4 实际存在两个遗漏：唱歌被 Java 无条件拒绝；跳舞先给平台发送 action interrupt，再走本地资源和准备播报。r5 已移除这两种接管。

原生唱歌、普通跳舞和太极命令保持机器人平台的原有执行者。本地 Java 静默完成 SDK 回调，不额外播报“关闭”“准备”或“我做不到”，不调用本地唱跳 HTTP 接口，也不再次发送 skill。

语音桥保留了基线的旧本地媒体兼容接口，其中 sing_enabled 仅控制本地媒体模拟入口；r5 原生唱歌路径不读取这个开关。未通过打开“念歌词”模拟来冒充恢复原生唱歌。固件配置修复只禁用重复讲解映射，测试确认不会关闭原有 sing/dance 技能。

本机已有歌单、舞蹈、版权内容、下载资源和平台权限不会由此安装包凭空新增。是否真正唱出歌曲、跳出对应舞蹈以及能否正常停止，需要目标机器人验收。

## 6. 语音、模型与知识库

保留 Java/AgentSDK 接入、灵心绑定和豆包模型配置；默认 ASR 文本回调为 asr2tts，其他回调仍按原有配置启用。支持普通问答、知识库检索和本机 TTS 播报；知识库不可用时保留原有模型处理路径。

保留唤醒会话、SDK/SOC2 唤醒证据、DOA/SNR/AEC/VAD/ASR 质量元数据门控、播报回声过滤、重复回调抑制和灵创保护。实际录音降噪与声学效果不能由这些策略测试证明。

紧急停止不依赖模型、点位列表或任务匹配。“不要开始讲解”“如果继续讲解会怎样”等不能执行；“不要走”等明确停止表达仍有停止通路。缺失、字符串、矛盾或异常控制回执不宣称成功，不重发可能已收到的控制命令。

直播弹幕入口保留既有可选配置，默认不作为本次原生唱跳能力的验收入口。独立直播项目未修改。

## 7. 安装、版本与运维

包内含固定 AIMDK、ARM64 Node/JRE、Java Agent/AgentSDK、网页及依赖、Python 导航、知识库组件和运维脚本。机器人本机网页服务端口 3000，业务服务通过 loopback 对接本机；软件源安装和平台服务仍需要相应网络。

支持新机安装、保留业务配置升级、完整快照备份及回退。安装预检校验固件配置和技能 JSON；损坏备份在停服前拒绝恢复。doctor 核验当前发布、策略字段、精确 Java 参数和实际进程，降低旧 overrides JAR 混入的风险。

源代码、运行文件与归档通过逐文件 SHA-256 对应；最终结果见交付目录 archive-audit.json、extracted-validation.json 和《验证记录》。当前使用 r5 安装命令，不能混用 r4、V1.3.8 或主仓库历史部署路径。

## 8. 现场验收尚未替代

本次可确认上述本地软件链路通过测试，不能承诺“无任何底层错误”或“所有实机功能完美”。现场还需验证目标固件与 ARM64 进程启动、真实地图定位和运动、实体动作、原生唱跳资源、实际唤醒和扬声器、灵心/豆包/知识库鉴权，以及真实断电与磁盘故障后的恢复。

本次没有部署到机器人、重启机器人服务或发送真实动作。应在同一目标机器人完成这些验收后，再标记为现场可用版本。
