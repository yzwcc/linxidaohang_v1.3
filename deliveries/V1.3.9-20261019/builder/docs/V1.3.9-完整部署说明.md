# 灵犀导航 V1.3.9 完整部署说明

交付日期：2026-10-19。完整版本：`1.3.9-complete-20261019-r4`。导航主包：`1.0.22-20261019`。

本包把本地可追溯的 V1.3.9 增量功能合入完整部署流程。重新安装本包后，无需再安装旧循环次数、到点讲解、密集人流、任务保存、受阻提醒、窄通道增量包。语音仍使用原有 Java/AgentSDK、灵心平台和豆包模型方案，没有改为机器人标配普通模板。

r4 修复失败跳点后的错误到达复用、控制回执误判、非指令误触发、固件预检及备份恢复检查。详见 `V1.3.9-r4-修复与验收.md`。

## 1. 适用范围与准备

适用：厂商机器人系统恢复后，仍具备 Ubuntu ARM64、ROS 2 Humble、`run`/`agi` 账号以及 `/agibot` 底层软件的机器人。窄通道策略适用 A2 PNC `app2.yaml` 配置。

这是应用完整安装包，不是系统刷机镜像。它包含 AIMDK、ARM64 Node/JRE、网页依赖、Python 导航源码、Java Agent、AgentSDK、知识库服务及安装运维工具；环境依赖通过 `apt` 安装，需要可用的软件源。灵心连接、模型推理和知识库检索需要对应网络与平台权限。

现场需准备：

- 当前机器人实际 IP、SSH 访问和两个本地账号的操作权限；
- 灵心 App ID、AppKey、AppSecret、绑定当前机器人的 Agent Code；
- 豆包 Ark API Key 和该账号实际可用的模型 ID；
- SOC2 实际地址及 `run` 账号 SSH 配置权限；
- 厂商地图、点位、讲解任务、灵创资源的现场备份。完整包不包含某台机器的业务数据、真实密钥或灵创下载资源。

安装前结束正在运行的导航、讲解和动作，使机器人停稳。建议预留至少 4 GB 可用空间；保存旧 AIMDK、业务备份和多份解压包时需更多。

## 2. 文件与校验

机器人建议使用：

```text
lingxi-v1.3.9-complete-20261019-r4-deployment.tar.gz
lingxi-v1.3.9-complete-20261019-r4-deployment.tar.gz.sha256
```

ZIP 与 TAR 包内容相同，ZIP 适合 Windows 查看和传输；机器人安装优先使用 TAR。不要在文本编辑器中保存校验文件或脚本。

上传到机器人 `/home/run`，用 `run` 执行：

```bash
cd /home/run
sha256sum -c lingxi-v1.3.9-complete-20261019-r4-deployment.tar.gz.sha256
tar -xzf lingxi-v1.3.9-complete-20261019-r4-deployment.tar.gz
cd /home/run/lingxi-v1.3.9-complete-20261019-r4-deployment
sha256sum -c SHA256SUMS.txt
bash ./install_all.sh --help
```

两次校验均须通过。已存在同名解压目录时，先改名保留旧目录，再重新解压，避免新旧文件混杂。

## 3. 新机或系统恢复后的完整安装

### 3.1 使用 run 准备环境

```bash
cd /home/run/lingxi-v1.3.9-complete-20261019-r4-deployment
bash ./install_all.sh prepare
```

脚本安装构建依赖，并把 AIMDK 包及替换脚本放到 `/home/agi`。本步骤通过 `apt` 下载系统依赖，不会补装缺失的厂商固件或整个 ROS 系统。

### 3.2 使用 agi 安装 AIMDK

另开 SSH 会话，以 `agi` 登录并执行：

```bash
bash /home/agi/01-replace-aimdk.sh
```

脚本先核验 AIMDK、解压编译并检查 Python 消息接口，再把旧 `/home/agi/aimdk` 改名为 `aimdk-before-v139-时间戳.进程号`，最后切换新目录。记录实际备份路径。原始 7z 会保留。

不要在启用 `set -u` 的交互 shell 中直接 source ROS；包内脚本已经处理 ROS 环境变量兼容。

### 3.3 回到 run 安装全部应用

```bash
cd /home/run/lingxi-v1.3.9-complete-20261019-r4-deployment
bash ./install_all.sh install --agent-code AI_AGENT_替换为实际Code
```

按交互提示填写灵心、豆包、机器人显示名和 SOC2 配置。AppSecret 与 Ark Key 使用隐藏输入。模型默认值只是既有项目默认配置，必须确认当前账号可用；不能用示例 Agent Code。

安装器依次：

1. 校验完整包、ARM64、AIMDK 和 A2 PNC 配置路径；
2. 停止旧业务服务，生成完整配置和业务状态备份；
3. 安装合并导航主包，保留已有地图、点位、任务与问答数据；
4. 启用密集人流策略：速度上限 0.30 m/s，到达容差 0.45 m，讲解点失败重试一次后跳点；
5. 备份并移走旧 `20-wake-gate-*.conf`，使 Java 使用完整包 JAR；
6. 禁用存在的旧 `exhibit_commentary/start_fixed_line_intro` 重复技能映射；
7. 应用窄通道平衡参数，并调用现有 PNC watchdog 重启链路加载配置；
8. 安装知识库检索服务，复用刚配置的灵心应用凭据；
9. 安装统一运维命令、重启网页并检查网页及知识库健康接口。

默认会交互配置 SOC2 SSH 访问。如果已正确配置且验证可用，可加 `--skip-soc2-setup`。

如果机器不是 A2 PNC，本包会在应用安装前拒绝改参数。确实需要保留该机器的原厂避障参数时，可显式加 `--skip-pnc-policy`；其他合并功能仍会安装，安装记录会注明窄通道策略未应用。不要把 A2 参数写入其他机型。

安装器完成后，Java/导航业务需从网页启动。不能仅凭安装完成消息认定语音、定位或动作已经实机验收。

## 4. 已有 V1.3.9 的升级或重装

不需要为升级再次替换已经正确的 AIMDK。用 `run` 校验、解压后执行：

```bash
cd /home/run/lingxi-v1.3.9-complete-20261019-r4-deployment
bash ./install_all.sh preflight
bash ./install_all.sh install \
  --agent-code AI_AGENT_替换为当前Code \
  --keep-config \
  --skip-soc2-setup
```

`--keep-config` 保留现有灵心/豆包凭据、模型和 SOC2 地址；不会再次询问这些密钥。Agent Code 仍须显式指定，用于知识库。导航中的密集人流与失败恢复字段会更新为本发布定义的值，其余已有导航字段和地图任务数据保留。

`preflight` 是只读检查，包含实际固件配置和技能 JSON 验证。决定跳过非 A2 的 PNC 策略时，预检与安装均使用 `--skip-pnc-policy`，并在现场记录该选择。

同版本重新安装由安装器自动加 `--reinstall`；原发布目录放到 `/opt/sparkrobot/lingxi-nav/reinstall-backups/`。升级前的完整快照位于 `/var/backups/sparkrobot/lingxi-v139/时间戳目录`。记录安装输出中的路径。

如果不加 `--keep-config`，将重新进入凭据向导，但仍保留业务地图任务。系统已重刷、旧配置不存在时，不能使用 `--keep-config`。

## 5. 启动和无运动检查

手机或电脑与机器人在同一局域网，打开：

```text
http://机器人实际IP:3000/console/
```

网页点击“一键开启全部服务”，然后用 `run` 执行：

```bash
bash /home/run/03-verify-after-web-start.sh
sudo sparkrobot-lingxi-complete status
sudo sparkrobot-lingxi-complete doctor
```

`doctor` 会检查主包哈希、进程、端口、地图与任务接口、知识库服务、密集人流配置、固件策略及 Java 实际运行 JAR。检查本身不发送导航、重定位、TTS 或动作指令。手动改过运行文件后，哈希检查会失败，需要先确认变更来源。

r4 还逐项核对策略值和布尔类型、Java 的精确 JRE/classpath/主类/配置参数、`/proc` 命令行及工作目录，防止服务仍运行旧发布而检查误通过。通过检查仍不代表真实云端鉴权、导航运动或声学效果已验收。

常用命令：

```bash
sudo sparkrobot-lingxi-complete start
sudo sparkrobot-lingxi-complete stop
sudo sparkrobot-lingxi-complete restart
sudo sparkrobot-lingxi-complete verify
sudo sparkrobot-lingxi-complete repair-permissions
sudo sparkrobot-lingxi-complete logs console
sudo sparkrobot-lingxi-complete logs navigation
sudo sparkrobot-lingxi-complete logs voice
sudo sparkrobot-lingxi-complete logs knowledge
```

`start/restart` 会启动或重启语音与底层关联服务，但不自动开始路线讲解。`verify` 校验文件完整性，`doctor` 检查启动后的运行状态。默认控制台沿用现有局域网访问模式，应在受信任局域网使用。

## 6. 现场功能验收

先确认选对地图、定位有效、起点及目标点与现场一致。以下属于实机操作，需要现场人员观察并掌握急停。

| 验收项 | 操作与预期 |
|---|---|
| 任务保存 | 使用“开始讲解/办理业务”等合法命令词保存任务，不应再因宽泛禁词返回 400 |
| 循环次数 | 保存 2～20 次，刷新网页后次数不丢失；旧任务缺字段时按 1 次 |
| 多点讲解 | 连续至少两点；到点依配置讲解和动作，随后等待，再去下一点 |
| 安静等待 | 每点等待 0～300 秒；发生问答后，从交互结束重新计算完整安静时长 |
| 打断恢复 | 语音打断后安静 5 秒恢复；人工暂停保持暂停，直到主动继续 |
| 密集人流 | 状态中显示策略启用、上限 0.30 m/s、到点容差 0.45 m |
| 失败跳点 | 讲解点失败重试一次，仍失败则记录跳过并继续；不把普通导航改为讲解跳点 |
| 受阻提醒 | 目标外持续停滞约 5 秒提醒“请大家让让我”；持续受阻每 5 秒最多一次；移动、转向、到达区域停止 |
| 窄通道 | 检查应用的是 A2 balanced-narrow；先在空旷场地低速验证，再验证现场通道 |
| 语音/知识库 | 真实唤醒后询问有知识库答案的问题，检查回答及连接状态 |
| 灵创资源 | 确认已下载资源存在，再配置与验证；包本身不附现场资源文件 |

完整测试方式见 `V1.3.9-功能与验收说明.md`。

## 7. 备份与完整恢复

应用安装前自动生成完整快照，包含导航/知识库配置与状态、任务、问答库、服务单元、旧语音覆盖配置、两个 PNC YAML 和技能映射。快照含真实密钥，仅保存在机器人本地，不能作为交付包发送。

它不包含厂商原始地图目录 `/agibot/data/var/MapManagerModule`、灵创资源、大型历史日志和 AIMDK 本体。系统刷机前必须另外备份这些内容及旧发布目录，刷机清盘后不能依靠机器人本地快照恢复。

```bash
sudo sparkrobot-lingxi-complete backup
sudo sparkrobot-lingxi-complete backups
```

需要撤销整次应用安装时：

```bash
sudo sparkrobot-lingxi-complete restore \
  /var/backups/sparkrobot/lingxi-v139/替换为实际备份目录
```

`restore` 先只读验证备份哈希、归档路径和旧版本目标，验证通过后才停止业务、再次保存恢复前状态、恢复快照里的配置/任务/服务和原 `current` 指向。安装后的新任务会恢复为快照时的数据，因此先导出需保留的变更。旧发布目录必须仍存在。预检不能消除磁盘故障或恢复中断等运行时失败。

如果回退的是**同一个主包版本的覆盖重装**，原代码已被内部安装器放入 `reinstall-backups`，原 releases 路径现为重装后的代码。先停止业务，将该目录中的对应旧版本移回原路径，再执行 `restore`；快照本身不含运行代码：

```bash
sudo sparkrobot-lingxi-complete stop
# 下面的旧目录时间戳必须换成与本次重装对应的实际目录。
sudo mv /opt/sparkrobot/lingxi-nav/releases/1.0.22-20261019 \
  /opt/sparkrobot/lingxi-nav/releases/1.0.22-20261019-after-reinstall
sudo mv /opt/sparkrobot/lingxi-nav/reinstall-backups/1.0.22-20261019-实际时间戳 \
  /opt/sparkrobot/lingxi-nav/releases/1.0.22-20261019
```

新装后不存在旧发布版本时，恢复快照只撤销应用配置和版本链接，不能恢复一套原本不存在的业务服务。

恢复完成后，若本次安装应用过 PNC 参数，执行现有 watchdog 重启使原参数生效，再启动旧服务：

```bash
sudo bash /agibot/software/drp/bin/stop_record.sh
sudo systemctl daemon-reload
sudo systemctl restart lingxi-nav-console.service
sudo systemctl restart sparkrobot-lingxi-kb.service
sudo sparkrobot-lingxi-internal start
sudo sparkrobot-lingxi-internal doctor
```

旧安装没有知识库服务时，跳过知识库 restart。如果旧版本带有完整运维命令，优先按旧版本说明验收。

安装中途失败、统一命令尚未安装时，也可从解压包恢复：

```bash
cd /home/run/lingxi-v1.3.9-complete-20261019-r4-deployment
sudo python3 ./scripts/backup_state.py restore \
  /var/backups/sparkrobot/lingxi-v139/替换为实际备份目录
sudo systemctl daemon-reload
```

直接调用 Python 恢复前须自行停止 Java、网页、导航、语音 bridge 和知识库；完整安装失败可能已停部分服务，不能假定全部停止。

仅切换运行代码的命令为 `sudo sparkrobot-lingxi-internal rollback 旧版本号`，不使用 `--backup`；它不恢复 PNC、技能映射或业务数据。整次安装回退应使用上面的完整快照恢复。

AIMDK 回退是独立操作：以 `agi` 将当前 `/home/agi/aimdk` 改名保留，再把实际 `aimdk-before-v139-*` 备份移回原名。停止依赖 AIMDK 的业务后操作，随后重新验证 ROS 消息接口。

## 8. 排障与交付记录

| 现象 | 检查与处理 |
|---|---|
| 哈希失败或文件名有回车 | 重新二进制上传原始包和 `.sha256`；不要手工修改脚本或校验文件 |
| 页面打不开 | 同一局域网、实际 IP、3000 端口、`logs console` |
| 任务保存失败 | `repair-permissions` 后重启导航；确认地图和命令词冲突，不再安装旧保存补丁 |
| 已升级但行为仍旧 | 强制刷新网页；`doctor` 检查 current、静态资源及 Java ExecStart/实际进程 |
| 语音 Java active 但无回复 | 检查 18080 bridge、SOC2 地址/密钥、灵心鉴权和机器人在线记录；active 不代表平台在线 |
| 知识库没有答案 | 18084 `/health` 只表示服务存活；核对 Agent Code、知识库内容及实际检索权限 |
| 无法定位 | 用 agi 执行 `/home/agi/04-check-localization.sh` 检查实时里程计；不要把参数安装成功当定位成功 |
| PNC 策略预检失败 | 确认 A2 主配置和字段齐全；不兼容机型显式跳过策略，不能强制套用 |
| 安装失败 | 根据输出中的完整备份目录恢复；没有自动宣称整套事务已回退 |

交付时记录：包 SHA-256、完整/导航版本、机器人型号与 IP、地图名、任务数、PNC 是否跳过、完整备份路径、doctor 输出和现场验收结果。记录中不写 AppSecret、API Key 或 SSH 密码。
