## 核查范围

当前 r5 的可复现源码固定在 `deliveries/V1.3.9-20261019/source/`，不依赖主目录中较早的源代码或未提交工作树。r4 源码保存在 Git 提交 e899dcd。构建前逐项核对 r3 的组件哈希及内部文件校验，打包时生成 `source-provenance.json`，记录源码、Java 产物及基线组件哈希。没有把 V1.3.8 的运行文件直接覆盖到 V1.3.9。

## 避免的覆盖回归

受阻提醒包中的 bridge/client 来自较早代码，直接覆盖会退回旧任务状态机。新包保留 V1.3.9 循环、等待、暂停恢复、到点锁存、密集人流和失败跳点，在此基础上添加 detector/event/TTS。

循环保存增量之后，源码还增加了地图页机器人位置显示，本次一并保留。密集人流增量包含配置写入效果，本次并入内部安装器；没有仅复制 Python 文件却漏掉启用字段。

旧知识库组件内的 Java 接入不再覆盖导航主包 Java JAR。r5 从归档源码重新编译，仅允许 `LingxiNavAgentApp` 及其内部类发生字节码变化，修复控制回执、非指令误触发及原生唱跳接管；其他类必须与 r3 逐字节一致。新 JAR 哈希写入 `release-info.json` 和 `source-provenance.json`，SDK 哈希保持基线。构建器发现额外类变更会拒绝打包。

## 客户操作结果

r5 的任务落盘、禁用任务、比心编号及原生唱跳修复详见 `V1.3.9-r5-功能复核报告.md`。动作请求超时或回执丢失不会再次发送；导航失败按任务策略重试一次属于另一条流程。

新机只执行本完整包的环境、AIMDK、应用安装步骤。已有 V1.3.9 执行一次本完整包的保留配置升级步骤。安装后从网页启动服务并验收，不再追加上述旧增量包。

A2 PNC 不兼容时明确拒绝自动改参数；使用 `--skip-pnc-policy` 会记录策略跳过，不能宣称该机器已启用窄通道策略。地图、灵创资源和平台凭据仍属于各台机器的现场数据。
