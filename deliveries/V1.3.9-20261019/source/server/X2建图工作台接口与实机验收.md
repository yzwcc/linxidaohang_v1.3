# 灵犀 X2 建图工作台：接口边界与实机验收

## 当前交付能力

工作台运行在现有机器人本机导航控制台内，手机/电脑连接机器人同一现场局域网，访问 `http://机器人IP:3000/console/`。浏览器只访问控制台，SSH 和 ROS 2 命令均由服务端执行；本次只开放只读传感器诊断，建图启停/保存暂时禁用。

项目内可验证的 X2 传感器接口为：

- 胸前雷达点云：`/aima/hal/sensor/lidar_chest_front/lidar_pointcloud`
- 胸前雷达 IMU：`/aima/hal/sensor/lidar_chest_front/imu`
- 现有定位输出：`/slam/lidar_odom`
- 当前底层模块：`aima-hal_sensor-app-main`、`slam`、`map_manager`
- 灵犀导航地图格式：数字 ID 子目录，必须有 `occupancy_map.png` 和 `grid_map_info.txt`

只读诊断查看传感器进程、雷达/IMU/定位里程计发布者，并枚举机器人现场 ROS 图中名称含 `map`、`slam`、`lidar`、`imu` 的话题和服务。它不会切换机器人模式、启动节点、移动机器人或写地图。`/slam/lidar_odom` 是项目已确认的定位输出，不作为正在生成新地图的证据；不再用社区的 `/projected_map` 或 `map_saver_cli` 推断建图能力。

## 为什么尚不开放保存

项目现有 AIMDK SDK 手册、V1.3.9 导航接口和实机部署流程没有记录原厂“进入建图模式”“停止建图”“导出地图”的服务或 CLI。导航服务本身会扫描 `MapManagerModule` 下的数字 ID 目录，包含所需的 `occupancy_map.png` 与 `grid_map_info.txt` 即可发现地图；当前缺少的是如何从 X2 固件正在生成的地图可靠地产出这两个兼容文件，并分配不冲突的新 ID。无需另造未经证实的 MapManager“登记”API。

公开社区项目 [Nova-Valley/agibot-x2-navigation](https://github.com/Nova-Valley/agibot-x2-navigation) 提供一条不同的 ROS 2 工作流：X2 点云/IMU校正 → Spark FAST-LIO 输出 PCD → 分片合并 → OctoMap 输出 `/projected_map` → Nav2 `map_saver_cli` 保存 PGM/YAML。该仓库明确是社区建图/导航方案，不等于 X2 原厂固件接口，也未证明目标机器人已安装这些包。它生成的 ROS 栅格文件也不等同于本项目 `MapManagerModule` 的地图目录格式。

因此不能把 `/slam/lidar_odom`、存在一个地图话题、或 `map_saver_cli` 已安装包装成“建图成功”。也不允许直接把未经确认的 PGM/YAML/PCD 转换后写入厂商地图目录或覆盖现有地图。

## 开放建图前的实机验收

由厂商或负责该 X2 固件的工程师在目标机器人上确认并记录：

1. 原厂建图模式的启动、停止和状态接口，含服务/话题/CLI 名称、消息类型、必需参数、用户权限及失败恢复方式。
2. 建图所需真实点云与 IMU 话题、坐标系/时间戳要求、SLAM 节点状态，以及地图是否为二维占据栅格或三维 PCD。
3. 地图导出接口和文件格式、分辨率/原点/图像朝向、MapManager 数字 ID 分配方式、元数据登记方式。
4. 使用一张**新地图**完成端到端流程：启动建图 → 低速现场扫描 → 停止 → 保存 → 断电/服务重启 → 地图仍被发现 → Web 预览 → 选为导航图 → 安全区域定位验证。
5. 验证取消、超时、磁盘满、重复名称、写入失败和 SSH 中断时不会损坏已有地图，且能够明确报告恢复状态。
6. 完成硬件急停可达、现场观察员在位、机器人停稳条件、身份验证/局域网访问审查，并留下型号、固件版本、接口日志（脱敏）、地图 ID 与验收签字。

通过以上验收后，才把经过核验的固定 ROS2 service/action 或厂商 API 封装为白名单后端操作，并开放保存。不能把未经审查的环境变量 shell 字符串当成稳定产品接口。
