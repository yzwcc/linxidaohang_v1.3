# 灵犀 X2 建图工作台：接口边界与实机验收

## 当前交付能力

工作台部署在机器人本机。手机/电脑连接同一现场局域网，访问 `http://机器人IP:3000/console/`。机器人移动完全由外置遥控器负责；网页不发送底盘速度、导航目标或其他移动命令。网页只负责读取传感器、管理建图采集会话、展示采集状态并保存新地图。浏览器只访问控制台，ROS 2 命令由机器人本机服务端在其受控系统权限下执行；当前只开放只读传感器诊断，采集启停和地图保存暂时禁用。

项目内可验证的 X2 传感器接口为：

- 胸前雷达点云：`/aima/hal/sensor/lidar_chest_front/lidar_pointcloud`
- 胸前雷达 IMU：`/aima/hal/sensor/lidar_chest_front/imu`
- 现有定位输出：`/slam/lidar_odom`
- 当前底层模块：`aima-hal_sensor-app-main`、`slam`、`map_manager`
- 灵犀导航地图格式：数字 ID 子目录，必须有 `occupancy_map.png` 和 `grid_map_info.txt`

只读诊断查看传感器进程、雷达/IMU/定位里程计发布者，并枚举机器人现场 ROS 图中名称含 `map`、`slam`、`lidar`、`imu` 的话题和服务。还会检查 `py_examples` 校正包、Spark FAST-LIO、Open3D、OctoMap 与 Nav2 map saver 是否安装。它不会切换机器人模式、启动节点、移动机器人或写地图。外置遥控器移动时，网页必须通过真实建图后端记录相应传感器数据并完成 SLAM/地图导出；仅保存点云/IMU 原始录制文件不等于生成导航地图。`/slam/lidar_odom` 是项目已确认的定位输出，不作为正在生成新地图的证据；不再用社区的 `/projected_map` 或 `map_saver_cli` 推断建图能力。

## 为什么尚不开放保存

项目现有 AIMDK SDK 手册、V1.3.9 导航接口和实机部署流程没有记录原厂“进入建图模式”“停止建图”“导出地图”的服务或 CLI。导航服务本身会扫描 `MapManagerModule` 下的数字 ID 目录，包含所需的 `occupancy_map.png` 与 `grid_map_info.txt` 即可发现地图；当前缺少的是如何从 X2 固件正在生成的地图可靠地产出这两个兼容文件，并分配不冲突的新 ID。无需另造未经证实的 MapManager“登记”API。

公开社区项目 [Nova-Valley/agibot-x2-navigation](https://github.com/Nova-Valley/agibot-x2-navigation) 提供一条可供单独部署/验证的 ROS 2 工作流：原始胸前点云 → `pcl_rectifier` → `/lidar/points_rectified`；原始 IMU → `imu_rectifier` → `/imu/rectified`；静态 `map -> odom`；`spark_fast_lio` 写出 `scans_*.pcd`；Open3D 合并成 `map_merged.pcd`；OctoMap 投影为 Nav2 地图；最后 `map_saver_cli` 保存 PGM/YAML。社区 README 的校正角度、时间戳比例、FAST-LIO 外参均为固定示例，必须按目标机器人硬件实测，不应直接作为 X2 旗舰版生产参数。该仓库 README 还指出合并脚本在仓库中为空占位，首次部署需自己提供脚本。

这是一套社区 ROS 2 工作流，不等于 X2 原厂固件建图接口，也未证明目标机器人安装了这些包或有算力/磁盘余量。Nav2 saver 输出的 PGM/YAML 也不等同于本项目 `MapManagerModule` 格式；把三维 PCD 投影成二维图时，尚需明确像素方向、占用/未知灰度语义、分辨率和像素原点，再生成灵犀要求的 `occupancy_map.png` 与 `grid_map_info.txt`。当前工作台依赖预检只用于确定下一步环境缺口，并不声称建图后端已可用。

服务端纯转换器 `src/mapFormat.ts` 已支持 Nav2 `trinary`、`negate: 0`、yaw 为零的 P2/P5 PGM → 8-bit grayscale PNG，并根据 YAML 分辨率和左下角原点推导灵犀像素原点。它保留 Nav2 的黑色占用、205 未知、254 空闲灰度；不猜测 `scale/raw`、反色或旋转地图。转换器目前只产生内存中的 PNG/元数据并有单元测试，尚未接入机器人写盘或开放保存；实机仍需通过 Web 地图列表/预览与像素-世界坐标回验。

因此不能把 `/slam/lidar_odom`、存在一个地图话题、或 `map_saver_cli` 已安装包装成“建图成功”。也不允许直接把未经确认的 PGM/YAML/PCD 转换后写入厂商地图目录或覆盖现有地图。

## 开放建图前的实机验收

由厂商或负责该 X2 固件的工程师在目标机器人上确认并记录：

1. 经确认的地图采集/建图后端启动、停止和状态接口，含服务/话题/CLI 名称、消息类型、必需参数、机器人本机运行用户、资源限制及失败恢复方式。明确区分传感器原始录制与能够产出二维导航占据栅格的 SLAM 建图。
2. 建图所需真实点云与 IMU 话题、坐标系/时间戳要求、SLAM 节点状态，以及地图是否为二维占据栅格或三维 PCD。
3. 地图导出接口和文件格式、分辨率/原点/图像朝向、MapManager 数字 ID 分配方式、元数据登记方式。
4. 由现场人员通过外置遥控器移动机器人，网页完成端到端流程：启动采集 → 遥控扫描 → 查看采集/建图状态 → 停止 → 导出并保存新地图 → 断电/服务重启 → 地图仍被发现 → Web 预览 → 选为导航图 → 在外置遥控/现场监护下完成安全区域定位验证。全过程确认网页没有发布底盘或导航运动命令。
5. 验证取消、超时、磁盘满、重复名称、写入失败和 SSH 中断时不会损坏已有地图，且能够明确报告恢复状态。
6. 完成硬件急停可达、现场观察员在位、机器人停稳条件、身份验证/局域网访问审查，并留下型号、固件版本、接口日志（脱敏）、地图 ID 与验收签字。

通过以上验收后，才部署经过硬件标定、固定版本和资源约束的白名单 ROS launch/节点编排适配器；网页适配器仅控制采集/SLAM 后端，绝不接管移动。状态、取消、超时和日志必须由后端托管，不能把任意环境变量 shell 字符串当成稳定产品接口。保存阶段先在 MapManager 同级新建临时目录，验证图像可解码、尺寸与元数据一致、无冲突 ID 后再原子提交新数字 ID 目录；绝不覆盖现存目录。首次输出还必须经过导航页面预览、像素/世界坐标往返测试和受控定位验证，方可开放用户保存。
