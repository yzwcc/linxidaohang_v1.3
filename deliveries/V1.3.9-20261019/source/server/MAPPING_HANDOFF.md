# 灵犀 X2 建图工作台交接说明

本目录包含建图工作台当前版本。工作台集成在灵犀导航控制台中，按机器人本机部署：服务端监听 `0.0.0.0:3000`，同事手机/电脑连接机器人同一现场 Wi-Fi/LAN，访问 `http://<机器人IP>:3000/console/`。机器人移动由外置遥控器负责；网页不得调用底盘速度或导航运动命令，仅由机器人本机服务端读取 ROS 传感器并控制经验证的采集/建图后端、保存地图。浏览器不直接连 SSH。

本交接归档是源码、已构建控制台、测试与接口清单，不是可直接执行的机器人安装器，也不包含机器人的 ROS 配置。工作台网页本身随现有完整控制台发行包安装到机器人；机器人端采集/SLAM 接口适配和现场验收完成后，须把适配后的服务端源码纳入项目完整部署构建/审计流程，再使用对应完整发行包安装。

## 当前包含

- 响应式“建图”工作区，读取雷达点云、IMU、SLAM 里程计实时帧状态，并显示 ROS 话题、服务和社区工作流依赖预检。
- `src/mapFormat.ts`：严格支持 Nav2 `trinary`、`negate: 0`、零 yaw 的 P2/P5 PGM/YAML 转灵犀灰度 PNG 与 `grid_map_info.txt`。
- `src/mapPersistence.ts`：把已通过格式校验的 Nav2 trinary 输出排他写入全新数字 ID 目录，校验 PNG chunks/CRC/灰度像素流/尺寸及元数据后再发布导航发现所需文件；拒绝覆盖旧地图。该模块尚未连接建图 API。
- 受保护的建图 start/save API：在机器人后端接口通过实机验证前返回 409，不执行模式切换、SLAM 启停或地图写盘。
- 源码、测试以及本文档；不包含密钥、SSH 私钥或机器人现场地图。

## 验证

在具备 Node.js 22 的开发机或集成工作区执行：

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run build
```

当前版本验证记录：15 个测试文件、91 项测试通过，TypeScript 构建通过。该结果是软件离线验证，不代表已在目标 X2 上启动/保存地图。

## 部署和访问

1. 在机器人上部署项目对应的完整、已审计导航发行包；不要把本源码交接 ZIP 当成安装器执行。
2. 确认机器人端控制台 systemd 服务运行，监听 `0.0.0.0:3000`，本机检查 `curl http://127.0.0.1:3000/health` 成功。
3. 同事手机/电脑连接同一个现场局域网，浏览器打开 `http://<机器人局域网IP>:3000/console/`，进入“现场地图采集”。
4. 外置遥控器由现场人员独立操作机器人移动。网页不承担移动控制，只负责查看传感器状态、与本机已验证的采集后端协作和保存地图。
5. 当前建图接口尚未接入；在后端完成并验收前，界面按钮会保持禁用/API 返回 409。不要为“先扫起来”而绕过保护或直接向 MapManager 写文件。

本机运行环境、服务管理和回滚按 `builder/docs/V1.3.9-完整部署说明.md` 执行。完整发行包必须在接口接入后重新构建与审计；这里的交接包只用于开发联调。

## 同事部署/接入前必须提供的现场证据

请按 `X2建图工作台接口与实机验收.md` 记录以下内容，并通过安全渠道回传脱敏材料：

1. 机器人准确型号、固件/软件版本，以及 ROS 2 发行版和工作区加载方式。
2. 原厂或经批准的建图启动、状态、停止与导出命令/API，含 ROS 名称和类型、参数、系统用户、正常/异常返回、取消及恢复步骤。
3. 实际点云、IMU、TF/坐标系与时间戳要求；运行时每个话题需能收到单帧数据，而不只是看到 publisher。外置遥控移动时，后端如何同步输入并生成地图也需确认。
4. 导出文件样例及地图语义：栅格方向、灰度含义、分辨率、原点/yaw、地图 ID 生成规则、MapManager 发现要求。
5. 使用外置遥控器移动，网页完成采集/状态显示/停止/导出/保存新地图，再经服务重启后发现、Web 预览、导航图选择和受控定位闭环的日志与结果；确认网页没有发送移动指令。
6. 急停/现场监护确认，以及取消、磁盘满、重复名称、写入失败和 SSH 中断的恢复验证。

交接包的 `server/scripts/x2-mapping-preflight.sh` 是只读预检脚本。机器人维护人员可先检查脚本后通过 SSH 执行，例如：

```bash
ssh agi@<机器人IP> 'bash -s' < x2-mapping-preflight.sh > x2-mapping-preflight.txt 2>&1
```

它会记录 ROS/系统版本、目标话题类型与单帧接收情况、建图相关 topic/service、相关 ROS 包，以及 MapManager 现存地图目录和剩余磁盘空间。脚本不启停节点、不切换模式、不导出地图、不写 MapManager；回传前请删除主机名、地址、用户等敏感字段，并确认日志中没有凭据。

禁止在生产机器人试探未经确认的服务、任意 shell 命令、社区参数或地图写入路径；先在维护窗口和现场监护下，由机器人维护人员确认接口。不得覆盖现有地图。

## 接回产品代码的边界

- 把稳定接口封装为白名单后端适配器；Web API 仅允许受控 `start/status/stop/save`，不得接收任意 shell 字符串。
- 将输出交给 `src/mapPersistence.ts` 保存到 MapManager 根目录下全新、无冲突的数字 ID 目录；它验证 PNG chunks/CRC、8-bit 灰度数据可解压、图像尺寸与元数据一致性。它不验证 X2 对像素占用语义/世界坐标的实际解释；仍需机器人导航页面预览和定位闭环。失败只尝试清理本次创建的文件，不触碰其他地图。
- 采集/SLAM 状态、超时、取消、本机 ROS 进程异常和日志都由服务端托管；页面明确显示“准备、采集中、停止、地图验证、保存”阶段和可恢复错误。移动始终由外置遥控器负责。
- 先增加模拟接口与回归测试，再用目标机器人验证。实机闭环未完成前，`mapping/start` 与 `mapping/save` 必须继续拒绝写操作。

## 项目内导航地图契约

导航按 MapManager 下数字 ID 目录发现地图。每个地图至少需要 `occupancy_map.png` 与 `grid_map_info.txt`：

```text
resolution_pixels_per_meter
origin_u origin_v
width height
```

当前已验证导航发现逻辑不等于已验证地图导出接口。`/slam/lidar_odom` 只证明定位输出，不证明正在生成新地图。
