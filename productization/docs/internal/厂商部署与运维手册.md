# 灵犀导航产品化厂商部署与运维手册

文档级别：厂商内部保密  
版本日期：2026-08-26  
适用架构：智元 X2 ARM64 / Ubuntu 22.04 / Python 3.10

## 1. 产品部署原则

1. 客户只使用机器人本机网页，不接触终端、源码、部署工具或设备归档。
2. 厂商通过 SSH 采集设备指纹、签发单机许可证并实施安装。
3. 每个发布归档只绑定一台 ARM64 机器人，不能复制到另一台机器人运行。
4. 导航 Python 业务以 19 个 ARM64 CPython 3.10 原生模块发布；Java 自有类经过混淆。
5. 控制台、Node 22 ARM64 和 JRE 17 ARM64随产品发布，新机器人不依赖系统预装 Node 或 Java 17。
6. 归档不包含安装器。厂商部署工具在 SSH 临时目录中单独上传安装器，部署结束后清理。
7. 不修改独立的“灵犀直播 plus”项目及其语音配置。
8. 未经现场授权不得执行真实移动、动作或舞蹈测试。

## 2. 新机器人前置条件

部署前逐项确认：

- 机器人为 ARM64，系统可执行 `uname -m`、`python3 --version`、`openssl version`。
- Python 为 3.10，ROS2 Humble、AimDK 和机器人底层导航组件已随机器人系统安装。
- 主机器人 SSH 可用，存在 `agi` 和 `run` 用户，厂商掌握 SSH 与 sudo 权限。
- systemd、curl、ssh、ssh-keygen、tar 和 OpenSSL 可用。
- SOC2 地址默认可由主机器人访问，默认地址为 `10.0.1.42`；项目地址不同必须在部署时明确指定。
- 地图目录 `/agibot/data/var/MapManagerModule/` 可读。
- 机器人雷达、SLAM、导航、唤醒和音频底层服务没有硬件故障。
- 已取得该客户独立的灵心 AppId、AppKey、AppSecret 和豆包 API Key。

机器人系统默认只有 Java 11 不影响部署，产品归档已包含 JRE 17。

## 3. 厂商电脑准备

建议使用独立的厂商部署电脑和加密磁盘，安装：

- Python 3.10 或更高版本
- OpenSSL 3
- Node.js 20 或更高版本和 npm
- `paramiko`
- SSH 客户端

安装 Python SSH 依赖：

```powershell
python -m pip install paramiko
```

正式私钥目录必须位于代码仓库和云同步目录之外。以下命令中的路径均为示例，不得照抄为公共目录。

## 4. 采集设备指纹

机器人开机配网后，由厂商执行：

```powershell
python productization/vendor/collect_claim_remote.py `
  --host <机器人IP> `
  --user agi `
  --output D:\sparkrobot-secure\claims\<客户编号>-device-claim.json
```

工具会：

1. 通过 SSH 向机器人 `/tmp` 临时上传只读采集脚本。
2. 优先读取设备树序列号；硬件序列号缺失时才使用系统机器标识。
3. 生成产品设备指纹和 ARM64 环境信息。
4. 下载申请文件并删除机器人临时文件。

必须核对申请文件中的：

- `format=sparkrobot-device-claim-v1`
- `product_id=sparkrobot-lingxi-nav`
- `architecture=aarch64` 或 `arm64`
- `device_fingerprint` 非空

IP 地址不是许可证身份。机器人更换 Wi-Fi 或 IP 后，设备许可证仍然有效；更换机器人本体后必须重新采集和签发。

## 5. 准备独立业务密钥文件

在厂商电脑创建仅本次部署使用的临时文件，例如：

```text
LINGXI_APP_ID=<客户灵心应用ID>
LINGXI_APP_KEY=<客户灵心AppKey>
LINGXI_APP_SECRET=<客户灵心AppSecret>
DOUBAO_API_KEY=<客户豆包APIKey>
DOUBAO_MODEL=doubao-seed-2-0-mini-260428
```

要求：

- 每个客户或项目使用独立配置。
- 不复用“灵犀直播 plus”项目的配置文件。
- 不把该文件放入代码仓库、发布归档、聊天记录或客户文档。
- 部署完成后按公司密钥制度删除临时明文副本。

## 6. 签发设备许可证

正式密钥初始化和保管见《厂商密钥与许可证管理手册》。签发命令：

```powershell
python productization/vendor/issue_license.py `
  --claim D:\sparkrobot-secure\claims\<客户编号>-device-claim.json `
  --private-key D:\sparkrobot-secure\vendor-keys\license-signing-private.pem `
  --public-key D:\sparkrobot-secure\vendor-keys\license-signing-public.pem `
  --customer "<客户名称>" `
  --output-dir D:\sparkrobot-secure\licenses\<客户编号> `
  --days 0
```

`--days 0` 表示永久绑定该机器人；需要订阅期限时填写正整数。默认授权功能包括控制台、导航、语音、讲解和地图编辑。

## 7. 构建正式发布归档

发布前需准备：

- ARM64 CPython 3.10 原生导航目录。
- 受保护 Java 应用 JAR。
- LinkSoul AgentSDK 1.4.0 JAR。
- ARM64 Node 可执行文件。
- ARM64 JRE 17 根目录。
- 服务端生产依赖目录。

构建示例：

```powershell
python productization/vendor/build_release.py `
  --version 1.0.0 `
  --license-dir D:\sparkrobot-secure\licenses\<客户编号> `
  --private-key D:\sparkrobot-secure\vendor-keys\license-signing-private.pem `
  --public-key D:\sparkrobot-secure\vendor-keys\license-signing-public.pem `
  --native-navigation productization/build/navigation-native-aarch64 `
  --java-app-jar productization/build/robot-local-navigation-java-protected.jar `
  --java-sdk-jar productization/build/linksoul-agentsdk-1.4.0.jar `
  --java-runtime productization/build/jre17-arm64 `
  --node-runtime productization/build/node-arm64 `
  --node-modules server/node_modules `
  --server-dir server `
  --output-dir D:\sparkrobot-secure\releases
```

正式构建禁止使用：

- `--allow-non-arm64`
- `--allow-unprotected-java`
- 测试私钥
- 带 `test` 的版本号

构建器会拒绝业务 `.py`、TypeScript/Java 源码、非 ARM64 ELF、错误 Python ABI、未保护 JAR、私钥和常见令牌。

## 8. 独立审计发布归档

每个正式归档都必须独立审计：

```powershell
python productization/vendor/audit_release.py `
  --archive D:\sparkrobot-secure\releases\sparkrobot-lingxi-nav-1.0.0-<许可证前缀>.tar.gz `
  --report D:\sparkrobot-secure\reports\<客户编号>-1.0.0-audit.json
```

通过标准：

- RSA/SHA-256 清单和许可证签名有效。
- 逐文件哈希、大小、严格目录和归档权限通过。
- 19 个导航模块均为 ARM64 CPython 3.10。
- Node 和 JRE 17 均为 ARM64。
- Java 主类为 Java 17 字节码并具有混淆保护标记。
- 不存在业务源码、source map、mapping、私钥、口令、AppSecret 或 API Key。

审计不通过时禁止部署，不得手工删除文件后继续使用原签名。

## 9. ARM64 临时冒烟验证

正式安装前可在目标机器人临时目录验证，不启动导航：

```powershell
python productization/vendor/smoke_test_release.py `
  --archive <设备绑定归档> `
  --host <机器人IP> `
  --user agi
```

该工具只验证：

- Node ARM64 可执行。
- 自带 JRE 17 可执行。
- 受保护 Java 主类可通过 `-Xverify:all` 加载。
- 控制台能在随机回环端口启动并返回 `/health`。

工具完成或失败后都会清理 `/tmp/sparkrobot-release-smoke-*`，不会安装 systemd、启动导航或移动机器人。

## 10. 厂商 SSH 安装

```powershell
python productization/vendor/deploy_robot.py `
  --archive <设备绑定归档> `
  --host <机器人IP> `
  --user run `
  --secrets D:\sparkrobot-secure\temp\<客户编号>-secrets.env
```

默认流程：

1. 厂商电脑先离线验签和逐文件校验。
2. 建立随机 SSH 临时目录。
3. 上传设备归档、独立安装器和临时密钥文件。
4. 为 SOC2 配置仅用于产品运维的专用 SSH key。
5. 以 sudo 执行设备指纹、许可证、发布清单和 ARM64 校验。
6. 安装到版本目录并原子切换 `current`。
7. 迁移已有地图、点位、任务和独立导航配置。
8. 启动控制台并检查 `/health`。
9. 输出产品状态并清理机器人 `/tmp`。

SOC2 地址或用户不同：

```powershell
python productization/vendor/deploy_robot.py ... --soc2-host <地址> --soc2-user run
```

只有升级且机器人已经保存有效 SOC2 专用密钥时，才允许使用 `--skip-soc2`。相同版本修复安装必须显式增加 `--reinstall`。

## 11. 安装目录

| 路径 | 内容 |
|---|---|
| `/opt/sparkrobot/lingxi-nav/releases/<版本>` | 只读版本运行文件 |
| `/opt/sparkrobot/lingxi-nav/current` | 当前版本原子链接 |
| `/etc/sparkrobot/lingxi-nav` | 许可证、公钥、密钥配置和控制台环境 |
| `/var/lib/sparkrobot/lingxi-nav` | 地图、点位、任务、配置和版本历史 |
| `/var/log/sparkrobot/lingxi-nav` | 控制台、导航和语音日志 |

服务：

- `lingxi-nav-console.service`
- `lingxi-java-agent-robot.service`

## 12. 升级

1. 为同一设备许可证构建新版本归档。
2. 完成独立审计和 ARM64 冒烟验证。
3. 使用 `deploy_robot.py` 部署新版本。
4. 不传 `--secrets` 的升级当前工具仍要求显式密钥文件，因此应提供该客户安全保存的配置；安装器会备份旧配置。
5. 核对地图、点位、讲解任务和当前任务均保留。

安装健康检查失败时，安装器自动恢复上一版本链接和系统服务文件。

## 13. 状态、验签与回滚

```bash
sudo /usr/local/sbin/sparkrobot-lingxi-product status
sudo /usr/local/sbin/sparkrobot-lingxi-product verify
sudo /usr/local/sbin/sparkrobot-lingxi-product rollback
sudo /usr/local/sbin/sparkrobot-lingxi-product rollback <指定版本>
sudo /usr/local/sbin/sparkrobot-lingxi-product activate <指定版本>
```

回滚只切换已安装且验签通过的版本，不删除客户地图、点位、任务或日志。

## 14. 卸载运行服务

```bash
sudo /usr/local/sbin/sparkrobot-lingxi-product uninstall sparkrobot-lingxi-nav
```

卸载会停止并移除 systemd 运行入口，但保留许可证、版本文件、地图、点位、任务、配置备份和日志，便于厂商恢复。彻底删除客户数据必须取得书面确认后另行执行。

## 15. 故障恢复

### 控制台无法启动

```bash
systemctl status lingxi-nav-console.service --no-pager
journalctl -u lingxi-nav-console.service -n 150 --no-pager
sudo /usr/local/sbin/sparkrobot-lingxi-product verify
```

先处理许可证、发布文件或权限验签失败，不得直接注释 `ExecStartPre`。

### 语音服务无法启动

```bash
systemctl status lingxi-java-agent-robot.service --no-pager
tail -n 150 /var/log/sparkrobot/lingxi-nav/java-agent.log
```

确认自带 JRE 17、客户独立灵心配置、SOC2 专用密钥和机器人音频底层服务。

### 网站一键启动失败

确认控制台专用 SSH key、sudo 白名单、`agi`/`run` 用户以及 SOC2 网络。不得在网页后端开放任意 shell 命令。

### 地图或任务丢失

先停止操作并检查 `/var/lib/sparkrobot/lingxi-nav/backups`。不要重新初始化状态目录，不要覆盖客户现场地图。

## 16. 现场安全

- 部署与服务检查可以远程完成。
- 地图切换、重定位、导航、动作、表情和舞蹈必须在现场人员确认后测试。
- 首次移动测试应选择短距离点位，现场人员握有实体急停。
- 当前任务中的动作或舞蹈必须逐项确认机器人稳定站立和周围空间。
