# 灵犀导航产品保密与安全边界说明

文档级别：厂商内部保密  
版本日期：2026-08-26

## 1. 已实施的保护

- 导航 Python 业务编译为 ARM64 CPython 3.10 `.so`，正式归档不含业务 `.py`。
- Java 自有类经 ProGuard 混淆，mapping 只在厂商侧保存。
- TypeScript 后端和网页资源经 esbuild 打包压缩，不发布 TS、Java 或 source map。
- 发布归档使用 RSA 3072 / SHA-256 签名，逐文件校验哈希、大小和权限。
- 严格目录拒绝任何未签名文件，服务启动前持续验签。
- 许可证绑定单台机器人的稳定硬件指纹和功能授权。
- 归档不包含安装器，厂商 SSH 部署时临时上传并清理。
- 机器人只保存厂商公钥，不保存签名私钥和 Java mapping。
- 网页只提供白名单运维动作，不接受任意 shell 命令。
- 客户日常只访问本机网页，不获得机器人 SSH 账号和部署材料。

## 2. 客户不可获得的内容

- 原始导航 Python、Java 和 TypeScript 业务源码。
- Cython 构建输入、Java 混淆前 JAR和 mapping。
- 正式签名私钥、许可证签发工具和构建工具。
- 单机设备归档和厂商独立安装器。
- 灵心 AppSecret、豆包 API Key、SSH 密码和 SOC2 私钥。
- 厂商部署、密钥管理和安全边界内部文档。

## 3. 客户可获得的内容

- 机器人本机中文网页。
- 地图、点位和多套讲解任务的正常配置能力。
- 客户使用手册和项目售后联系方式。
- 合同约定的产品功能，不包含底层通用部署能力。

## 4. 客观安全边界

如果客户同时拥有机器人 root 权限、物理控制权和足够的逆向能力，纯本地软件无法做到绝对不可提取。root 用户理论上可以读取磁盘、调试进程或修改启动链路。

当前方案的目标是：

1. 不向正常客户暴露源码和部署入口。
2. 显著提高复制、篡改和跨设备运行成本。
3. 让普通 SSH 用户无法直接获得完整业务实现。
4. 通过签名和单机许可证发现文件替换和跨机器人复制。
5. 将正式签发权和通用部署能力保留在厂商侧。

不得向客户承诺“拥有 root 权限仍绝对无法提取”。

## 5. 更高安全等级选项

需要进一步提高保护时，可按项目预算增加：

- 禁止向客户提供 root/SSH，厂商使用独立售后通道。
- TPM/安全芯片密钥封装和设备远程证明。
- 安全启动、只读系统分区和磁盘加密。
- 在线许可证或短期运行令牌，支持远程撤销。
- 将关键算法迁移到厂商云端，只在机器人保留最小执行层。
- 专用硬件加密狗或可信执行环境。

在线授权会引入断网不可用、服务器成本和隐私合规问题；云端核心逻辑会增加导航实时性风险。现场导航核心不应依赖高延迟公网请求。

## 6. 交付控制

每次项目交付建立两份清单：

### 厂商内部清单

- 客户和机器人设备指纹
- 许可证 ID、版本和归档 SHA-256
- 审计报告
- 部署日期和实施人员
- 正式密钥公钥指纹
- 现场验收结果

### 客户清单

- 机器人和配套硬件
- 网页访问方式
- 客户使用手册
- 售后联系方式

客户清单中不得出现归档、安装器、签名工具、构建输入、内部路径和任何秘密。

## 7. 机器人账号策略

- 客户使用网页，不提供 `root`、`run` 或 `agi` 密码。
- 厂商部署账号和客户业务账号分离。
- SOC2 专用 key 只允许产品所需来源网段和 systemd 白名单动作。
- 不把通用 SSH 私钥写进网页前端或客户浏览器。
- 设备转售或退役时撤销厂商远程入口并按合同处理客户数据。

## 8. 发布前安全门禁

正式归档必须同时满足：

- `test_productization` 全部通过。
- 隔离安装、升级和回滚测试通过。
- 服务端测试和 TypeScript 构建通过。
- `deploy_robot.py --verify-only` 通过。
- `audit_release.py` 通过。
- ARM64 临时冒烟验证通过。
- 无业务源码、mapping、私钥、口令和平台密钥。
- 归档内无安装器。
- 现场移动测试仅在客户授权和安全条件满足后执行。
