# 灵犀导航厂商密钥与许可证管理手册

文档级别：厂商内部高度保密  
版本日期：2026-08-26

## 1. 密钥角色

| 材料 | 存放位置 | 能否进入机器人 | 能否交给客户 |
|---|---|---|---|
| RSA 3072 签名私钥 | 厂商离线加密介质 | 否 | 否 |
| RSA 签名公钥 | 发布包与机器人 `/etc` | 是 | 可公开 |
| 单机许可证与签名 | 对应机器人 | 是 | 不单独交付 |
| Java 混淆 mapping | 厂商离线故障档案 | 否 | 否 |
| 灵心 AppSecret / 豆包 Key | 机器人 root 配置 | 是 | 不显示给客户 |
| SOC2 专用 SSH 私钥 | 机器人受限配置目录 | 是 | 否 |
| 客户 SSH/sudo 密码 | 密码管理器或交互输入 | 不写入产品文件 | 否 |

## 2. 初始化正式签名密钥

在离线厂商电脑执行：

```powershell
python productization/vendor/init_vendor_keys.py `
  --output-dir D:\sparkrobot-secure\vendor-keys
```

要求：

- 不使用 `--unencrypted`。
- 私钥口令至少 16 位，存入公司密码管理器，不能与 SSH 密码相同。
- 私钥保存两份加密离线备份，分别由不同责任人保管。
- 公钥记录 SHA-256 指纹并纳入版本发布记录。
- 正式私钥目录不得位于仓库、桌面同步盘、聊天下载目录或机器人文件系统。

## 3. 签发规则

- 每台机器人一个独立 `license_id`。
- 许可证绑定设备指纹和 ARM64 架构，不绑定 IP。
- 客户名称、设备序列号、许可证 ID、版本和交付日期写入厂商台账。
- 永久许可证使用 `--days 0`；期限许可证必须在合同中说明到期行为。
- 不允许修改已签名 JSON。任何字段变化都必须重新签发。
- 不向客户提供 `issue_license.py`、私钥或可批量签发的服务。

## 4. 发布签名

同一正式私钥同时签署许可证和发布清单。发布清单包含：

- 产品 ID、版本、许可证 ID和设备指纹。
- 所有 rootfs 文件的 SHA-256、大小和权限。
- 严格保护目录。

机器人首次安装后固定信任该厂商公钥。后续归档公钥不同会被拒绝。

## 5. 测试密钥隔离

`productization/build/test-vendor-keys/` 仅供自动化测试。其公钥和私钥已经存在于开发工作区，不能用于客户许可证或正式发布。

以下任一情况均判定为测试制品：

- 版本号包含 `test`、`dev`、`local`。
- 使用 `--unencrypted` 生成的私钥。
- 使用 `--allow-non-arm64` 或 `--allow-unprotected-java`。
- 审计报告缺失或未通过。

## 6. 私钥使用流程

1. 核对设备申请文件来源和客户台账。
2. 在受控电脑挂载加密介质。
3. 签发许可证并构建发布归档。
4. 独立执行 `audit_release.py`。
5. 记录归档 SHA-256 和审计报告。
6. 卸载加密介质，清理临时明文文件。
7. 部署人员只获得目标设备归档，不获得签名私钥。

## 7. 私钥泄露处置

一旦怀疑私钥泄露：

1. 立即停止使用该私钥签发和发布。
2. 封存日志、构建机和介质，不自行删除证据。
3. 统计所有信任该公钥的机器人。
4. 生成新私钥并制定逐台受控换钥计划。
5. 由于机器人会拒绝不同公钥，换钥必须由厂商通过受控 SSH/现场维护实施，不能把新私钥或通用换钥包交给客户。
6. 换钥后重新签发每台设备许可证和当前版本归档，并完成验收。

当前工具不提供前端自助换钥，这是刻意的安全限制。

## 8. 许可证续期与设备更换

- 期限续期：使用原设备申请重新签发许可证并构建新设备归档。
- IP 变化：无需续签。
- 主板或机器人本体更换：重新采集设备申请并签发新许可证。
- 旧机器人报废：台账标记停用；如项目有在线授权层，应同时撤销在线授权。

## 9. 禁止事项

- 将私钥放入机器人、发布归档、网页或源代码。
- 将私钥口令写入批处理、环境模板或 CI 日志。
- 将测试私钥用于正式客户。
- 将一个客户的灵心或豆包密钥复制给另一个客户。
- 为方便售后把完整部署目录交给客户。
- 在客户可访问的网页接口中加入许可证签发、任意文件上传或任意 shell 命令。
