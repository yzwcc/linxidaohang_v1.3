# 灵犀机器人导航控制台完整部署文档

## 0. 2026.07.21-v140 版本要求

```text
AgentSDK: linksoul-agentsdk-1.4.0-SNAPSHOT.jar
Java: 17+
灵心网关: wss://open.agibot.com/api/V1/open-portal/app/wss/agent-sdk
必填凭证: appId + appKey + appSecret
导航版本: robot-local-navigation-v3-2026.07.21
网站后端: 0.2.0
```

v1.4.0 采用 HMAC-SHA256 验签，与 v1.3.0 及更早的 JWT 凭证不兼容。
必须在灵心开放平台的「应用」中获取新 `appKey` 和对应 `appSecret`，
不能只复用旧版 `appId/appSecret`。

本文档用于在新机器人或新现场部署“网页导航控制台 + 灵心语音导航 + 机器人本地导航服务”。

## 1. 系统架构

整体链路：

```text
客户手机浏览器
  -> https://daohang.sparkrobot.top/console/
  -> 公网服务器 Fastify 后端
  -> 现场网关反向 SSH 隧道
  -> 机器人导航 bridge 18080 / 地图服务 8002 / SSH 22
```

语音链路：

```text
灵心平台
  -> 机器人系统层 Java Agent（run 用户、Java 17）
  -> 机器人本机 127.0.0.1:18080
  -> 机器人导航 bridge
  -> 机器人本地 TTS / 导航 / 讲解任务
```

当前推荐部署方式是“公网服务器控制台 + 现场网关反向隧道 + 机器人本地 Java Agent”。客户手机不需要电脑，只需要和机器人在同一个现场网络，并能打开公网网址。

## 5. 机器人本地导航服务部署

### 5.1 上传机器人导航程序

把目录上传到机器人：

```text
robot_local_navigation_v3/robot_local_navigation_v3-new-auto-return-interaction-end
```

机器人上建议路径：

```text
/home/agi/robot_local_navigation_v3
```

示例：

```bash
scp -r robot_local_navigation_v3/robot_local_navigation_v3-new-auto-return-interaction-end agi@机器人IP:/home/agi/robot_local_navigation_v3
```

进入机器人：

```bash
ssh agi@机器人IP
cd /home/agi/robot_local_navigation_v3
chmod +x scripts/*.sh
```

### 5.2 检查 DDS 配置

确认导航目录下有：

```text
/home/agi/robot_local_navigation_v3/ros_dds_configuration.xml
```

确认脚本会使用本目录 DDS 配置：

```bash
grep -n "FASTRTPS_DEFAULT_PROFILES_FILE\|RMW_LIBRARY_PATH" scripts/robot_local_navigation_v3.sh
```

检查机器人当前定位 topic：

```bash
source /opt/ros/humble/setup.bash
ros2 topic list | grep -E 'slam.*/odometry|slam/lidar_odom'
```

旧版现场通常使用：

```text
/slam/lidar_odom
```

部分新机器人使用：

```text
/slam/localization/odometry
```

如果新机器人没有 `/slam/lidar_odom`，启动导航服务前需要设置：

```bash
export NAV_ODOM_TOPIC=/slam/localization/odometry
```

也可以把该环境变量写入开机启动脚本。未设置时默认使用 `/slam/lidar_odom`。

如果重定位失败且提示 `/slam/lidar_odom` 没有数据，需要检查：

```bash
ros2 topic list | grep slam
ros2 topic echo /slam/lidar_odom --once
```

### 5.3 启动机器人导航服务

```bash
cd /home/agi/robot_local_navigation_v3
./scripts/robot_local_navigation_v3.sh start
```

检查：

```bash
curl http://127.0.0.1:18080/nav/status
curl http://127.0.0.1:18080/points
curl "http://127.0.0.1:8002/api/discover_maps?map_root=%2Fagibot%2Fdata%2Fvar%2FMapManagerModule%2F"
```

停止：

```bash
./scripts/robot_local_navigation_v3.sh stop
```

重启：

```bash
./scripts/robot_local_navigation_v3.sh restart
```

## 6. 现场网关反向隧道部署

现场网关可以是机器人本机，也可以是和机器人同一局域网的一台 Linux 电脑。

推荐首版直接用机器人本机作为现场网关。

### 6.1 创建服务器隧道用户

在公网服务器执行：

```bash
sudo useradd -m -s /usr/sbin/nologin robot-tunnel || true
sudo mkdir -p /home/robot-tunnel/.ssh
sudo chown -R robot-tunnel:robot-tunnel /home/robot-tunnel/.ssh
sudo chmod 700 /home/robot-tunnel/.ssh
```

确保 SSHD 允许远程端口转发。编辑：

```bash
sudo nano /etc/ssh/sshd_config
```

确认或加入：

```text
AllowTcpForwarding yes
GatewayPorts no
```

重启 SSH：

```bash
sudo systemctl restart ssh
```

### 6.2 在机器人生成隧道密钥

机器人上执行：

```bash
su - agi
mkdir -p ~/.ssh
chmod 700 ~/.ssh
ssh-keygen -t ed25519 -N '' -f ~/.ssh/daohang_server_ed25519 -C 'daohang-robot-tunnel'
cat ~/.ssh/daohang_server_ed25519.pub
```

复制输出的公钥。

### 6.3 把机器人公钥加入服务器

公网服务器执行：

```bash
sudo -u robot-tunnel mkdir -p /home/robot-tunnel/.ssh
echo '这里粘贴机器人公钥' | sudo tee -a /home/robot-tunnel/.ssh/authorized_keys
sudo chown -R robot-tunnel:robot-tunnel /home/robot-tunnel/.ssh
sudo chmod 700 /home/robot-tunnel/.ssh
sudo chmod 600 /home/robot-tunnel/.ssh/authorized_keys
```

### 6.4 安装现场网关脚本

把脚本复制到机器人：

```text
deploy/daohang/field-gateway.sh
```

机器人上安装：

```bash
cp field-gateway.sh /home/agi/daohang_reverse_tunnel.sh
chmod 700 /home/agi/daohang_reverse_tunnel.sh
```

如果服务器不是默认 IP，编辑脚本或通过环境变量设置：

```bash
export CLOUD_SSH_HOST=公网服务器IP
export SERVER_BASE_URL=https://daohang.sparkrobot.top
```

启动：

```bash
nohup /home/agi/daohang_reverse_tunnel.sh >/dev/null 2>&1 &
```

设置开机自启：

```bash
(crontab -l 2>/dev/null | grep -v 'daohang_reverse_tunnel.sh' || true; echo '@reboot /home/agi/daohang_reverse_tunnel.sh >/dev/null 2>&1 &') | crontab -
```

查看日志：

```bash
tail -f /home/agi/daohang_reverse_tunnel.log
```

### 6.5 验证隧道

公网服务器执行：

```bash
ss -ltnp | grep -E '(:18080|:18002|:10022)'
curl http://127.0.0.1:18080/nav/status
curl "http://127.0.0.1:18002/api/discover_maps?map_root=%2Fagibot%2Fdata%2Fvar%2FMapManagerModule%2F"
```

如果网页里换了机器人 IP，现场网关会在约 10 秒内读取新 IP 并重建隧道。

## 7. 机器人本地 Java 语音 Agent 部署

### 7.1 配置灵心和豆包

配置文件：

```text
/home/run/lingxi_java_agent/config/lingxi-nav.properties
```

关键配置：

```properties
lingxi.url=wss://open.agibot.com/api/V1/open-portal/app/wss/agent-sdk
lingxi.appKey=灵心开放平台应用AppKey
lingxi.appId=你的AppId
lingxi.appSecret=你的AppSecret
lingxi.callbacks=asr2llm,audio2tts

doubao.url=https://ark.cn-beijing.volces.com/api/v3/chat/completions
doubao.apiKey=你的豆包Ark API Key
doubao.model=你的模型ID

nav.baseUrl=http://127.0.0.1:18080
nav.timeoutMs=5000

tts.mode=robot
tts.fixedDialogTest=false
tts.suppressLingxiText=true
tts.delayBeforeSpeakMs=800
```

注意：

- 导航产品使用 `tts.mode=robot` 时必须保持 `tts.suppressLingxiText=true`。普通问答仍由机器人本地 TTS 播放，但灵心平台不会再重复直出同一段文本，讲解任务运行时也不会绕过本地防打断策略。

```text
nav.baseUrl 必须是 http://127.0.0.1:18080
```

因为 Java Agent 与导航 bridge 都运行在机器人本机，不再绕行新加坡服务器。

### 7.2 安装 Java 17 和 Agent 文件

用系统层账号登录机器人：

```bash
ssh run@机器人IP
sudo apt update
sudo apt install -y openjdk-17-jre-headless
/usr/lib/jvm/java-17-openjdk-arm64/bin/java -version
```

不要修改系统默认 Java 11。systemd 服务会显式使用 Java 17 的绝对路径，避免影响机器人厂商程序。

建立目录并上传文件：

```bash
mkdir -p /home/run/lingxi_java_agent/{target,config,logs,install}
```

对应文件：

```text
target/robot-local-navigation-java-0.1.0-all.jar
linksoul-agentsdk-1.4.0-SNAPSHOT.jar
config/lingxi-nav.properties
lingxi_java_agent_control.sh
install/lingxi-java-agent-robot.service
install/lingxi-java-agent-sudoers
```

安装服务：

```bash
chmod 700 /home/run/lingxi_java_agent/lingxi_java_agent_control.sh
sudo visudo -cf /home/run/lingxi_java_agent/install/lingxi-java-agent-sudoers
sudo install -m 0440 /home/run/lingxi_java_agent/install/lingxi-java-agent-sudoers /etc/sudoers.d/lingxi-java-agent
sudo install -m 0644 /home/run/lingxi_java_agent/install/lingxi-java-agent-robot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable lingxi-java-agent-robot.service
```

只允许一个 Java Agent 实例。切换前必须停止公网服务器上的旧 `LingxiNavAgentApp`，不能让云端和机器人端同时连接灵心平台。

### 7.3 启动语音服务

推荐通过后端接口启动：

```bash
curl -X POST http://127.0.0.1:3000/api/robots/default/java-agent/start
```

查看状态：

```bash
curl http://127.0.0.1:3000/api/robots/default/java-agent/status
```

正常应看到：

```text
running=true
lingxiConnected=true
lastAuthState=code=0, msg=jwt auth success
navBaseUrl=http://127.0.0.1:18080
```

日志：

```text
/home/run/lingxi_java_agent/logs/java-agent-managed.log
```

完整启动顺序固定为：

```text
机器人导航 bridge -> Java Agent 灵心鉴权成功 -> 重载 soc2 语音/唤醒/音频服务
```

网页“一键开启全部服务”和服务器开机自动启动均按此顺序执行。

### 7.4 激活 AgentSDK v1.4.0

1. 在灵心开放平台的「应用」中获取 `appId`、`appKey`、`appSecret`。
2. 在 `/home/run/lingxi_java_agent/config/lingxi-nav.properties` 中配置这三项。
3. 使用 root 执行：

```bash
bash /home/run/lingxi_java_agent/releases/2026.07.21-v140/activate_lingxi_v140.sh
```

脚本会先验证 `appKey`，自动备份当前 JAR 和 systemd，并在 30 秒内检查新鉴权。
鉴权失败时会自动回滚，不会把机器人留在无语音服务状态。

## 10. 讲解任务配置

每张地图可以保存多个讲解任务。

任务结构：

```text
任务名称
是否启用
步骤列表
每个步骤绑定一个导航点
每个点可配置讲解内容
```

语音启动逻辑：

```text
用户说“开始讲解”
Java Agent 调用 /task/start
机器人按当前地图的 active_tour_task_id 对应任务执行
```

讲解控制接口和语音意图：

```text
开始讲解 -> start_task  -> POST /task/start
暂停讲解 -> pause_task  -> POST /task/pause
继续讲解 -> resume_task -> POST /task/resume
停止讲解 -> end_task    -> POST /task/stop
```

暂停会保留任务名称、步骤列表和当前步骤。导航或讲解结束后，中间没有用户交互达到 30 秒才会返回起点。

如果要换讲解任务：

```text
网页选择任务
点击保存/设为当前任务
再语音说“开始讲解”
```

## 12. 常见问题

### 12.1 网页显示机器人离线

检查：

```bash
现场网关是否运行
网页填写的机器人 IP 是否正确
机器人 18080 是否启动
公网服务器 18080/18002/10022 是否监听
```

命令：

```bash
tail -f /home/agi/daohang_reverse_tunnel.log
ss -ltnp | grep -E '(:18080|:18002|:10022)'
```

### 12.2 重定位超时

检查机器人是否退出建图模式，SLAM 定位是否启动：

```bash
ros2 topic echo /slam/lidar_odom --once
```

如果没有数据，先重启机器人底层导航/SLAM，再重定位。

### 12.3 地图切换后点位不对

确认三者一致：

```text
网页当前地图
/nav/status active_map_name
重定位 result map_id
```

切换地图后重新重定位。

### 12.4 语音说“没学会这个动作”

新版 Java Agent 已修复导航成功后的兜底回复问题。检查：

```bash
curl http://127.0.0.1:3000/api/robots/default/java-agent/status
```

确认：

```text
lingxiConnected=true
callbacks=[asr2llm,audio2tts]
tts.mode=robot
```

导航成功时应回复：

```text
收到，正在前往<点位>。
```

### 12.5 换机器人 IP

客户只需要在网页填写新 IP 并保存。现场网关会自动读取新 IP 并重建隧道。

如果换了现场网关机器，需要重新安装 `field-gateway.sh` 并重新加入 SSH 公钥。

## 13. 多机器人说明

当前版本首版按单机器人设计：

```text
robotId=default
云端固定端口：18080 / 18002 / 10022
```

同一时间只建议接入一台机器人。

如果要同时接入多台机器人，需要扩展：

```text
多个 robotId
多套云端端口
多条现场隧道
前端机器人选择
后端运行配置按 robotId 存储
```
