# V1.3.8 控制响应误报修复 1.0.1 验证记录

日期：2026-10-18。工作分支：`codex/lingxi-v1.3.8-special`。

## 代码检查结论

导航和讲解被本地控制器接受后，旧逻辑仍允许使用意图模型生成的回复，并且没有像动作请求一样保留“本地已接受”标志。结果可能出现否定确认语，或在后续 SDK 完成回调异常时发送 5001 错误。

旧版原生动作中断只覆盖明确的预设动作词及标准讲解词，没有覆盖导航、自定义讲解匹配和模型识别的灵活动作。控制请求的去重也没有统一覆盖这些类型。重复回调的完成事件发送失败还会进入错误处理。

结合用户提供的 `lingxi-log-20261018-1015-1027.zip` 进一步确认：
两次“比个心”的底层拒绝文本由 `/motion/play` 结果直接流入 `/tts/speak`。
1.0.0 仍会把这类回执翻译成“暂未被接受”，因此不能覆盖用户要求的
底层兜底播报静默。1.0.1 补充静默策略，并将“已接受”和
“该回执已经处理，不应再发 SDK 错误”分别记录，拒绝状态不被伪装成成功。

现场还出现 10 次模型 HTTP 超时。基线已有故障处理，本次保留并用真实
15 秒 HTTP 超时验证精确点位处理及问答服务不可用提示。
日志中的 Python 文件为空，且 Java 文件混合多个时间片段和活动地图，
不能证明物理动作回执异常的底层原因或所有原生播报来源。
详细证据见同目录 `日志核验说明.md`。

## 验证结果

- 10 组 Java 回归入口全部通过；真实 SDK 回调测试扩充为 566 条断言，包含两个回调模式、三类控制、完成回包错误、重复请求、并发请求、真实拒绝及中断发送异常。用日志中的 `motion=3004, area=3` 拒绝回执验证本机 TTS 和 SDK 文本两条通路静默；确认未知、超时及 HTTP 错误同样覆盖，完成回包异常不触发平台错误。
- 原有语音门控 1419 条、唤醒会话 28 条、SOC2 证据 8 条、SDK 中断协议 51 条、实际 Agent 门控 391 条、语音 47 条和功能控制 42 条断言通过；模型恢复与连接状态回归通过。
- 新增真实 HTTP 超时回归：两个生产 15 秒超时分别验证精确配置点位可正常提交一次、普通问答返回服务不可用，不触发额外机器人控制。
- Linux 安装事务 8 项测试通过：安装与重复安装、运行与停止状态保持、启动失败自动回滚、未知基线拒装、备份及后续现场改动保护、包损坏与 CRLF 拒绝、实际服务账号的 JAR 与祖先目录权限，以及上一版补丁的升级和按原字节回滚。
- 既有动作确认逻辑 4 项测试通过，保持“已接受不等于物理完成”、确认未知不重复提交及真实拒绝处理。
- 压缩包 36 个文件全部通过 SHA-256 校验；35 个文本文件为 LF；2 个脚本和 5 个部署文档 Bash 代码块语法通过。
- 应用源码以 Java 17 编译。交付 JAR 与编译 class 一致；除 `LingxiNavAgentApp` 及内部类外，所有 Java 类与基线逐字节一致。
