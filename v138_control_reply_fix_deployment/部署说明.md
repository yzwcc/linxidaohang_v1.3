# V1.3.8 语音控制响应修复 1.0.3 部署说明

交付日期：2026-10-18。

包名：`sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018.tar.gz`。

本包根据 `lingxi-control-diagnose-20261018-151223.tar.gz` 的现场日志修改，包含此前 1.0.0、1.0.1、1.0.2 的修复。安装本包即可，不需要逐个叠加旧增量包。

## 一、适用范围

适用于已安装本项目 V1.3.8 r11～r15 完整系统，且 JAR、AgentSDK 指纹符合交付基线的机器人。已安装控制响应修复 1.0.0～1.0.2 也可以直接更新。本包不能安装到 V1.3.9、V1.3.1、r10 或未知修改版本；安装器会检查，不会强行覆盖。

只替换当前 release 的 `java/robot-local-navigation-java-all.jar`，同步更新 `payload-manifest.json`。应用内修改限于 `LingxiNavAgentApp`、`PresetMotionCatalog`、`DoubaoArkClient` 及其内部类，其他类与第三方依赖按基线逐字节检查。

不需要重新编译 AIMDK，不需要重新输入灵心或豆包密钥。地图、点位、讲解任务、灵创资源、唤醒及降噪参数、`lingxi.callbacks` 均不改。安装只重启原先正在运行的 Java Agent，不重启其他业务服务。请在没有导航、讲解或动作任务时安装。

## 二、本次修复

| 现场现象 | 修改后的处理 |
| --- | --- |
| 带路或讲解已经执行，却先出现失败播报 | 本地 HTTP 执行的控制请求使用 SDK `chat` 响应通道，不再声明一个没有配套 `onSkill` 指令的 `action` 响应；确认语仅依据本地控制回执生成 |
| 说唱首歌，先报唱歌关闭，再正常唱歌 | 删除本地“唱歌功能暂时关闭”分支；原生唱歌由机器人原有功能执行，Java 不追加本地播放、重复技能或中断 |
| 已经跳舞，之后又说请给空间 | 普通语音跳舞保留机器人原生执行；不再追加本地 `/entertainment/dance` 请求，从源头避免这条链路的准备播报和重复资源提交 |
| 比心后莫名自我介绍 | “那你是”等明确残句在请求模型和唤醒讲解前忽略；普通问答中无关的“我是……现场服务/互动机器人”自我介绍被清理，用户明确问身份时仍能正常回答 |
| 打招呼被当成问答不可用，重复唤醒也不能做 | 模型提示明确“打招呼”对应 `preset_motion/wave`；动作目录接受 `greet/greeting/say_hello` 动作名别名；模型格式异常时，明确的“打个招呼”等请求可按现有挥手动作处理，不播问答故障 |

打招呼仍优先经过模型识别，保留自然说法；本地补偿只接受明确动作请求，不把“你会打招呼吗”“不要打招呼”“他说打招呼”变成动作。已有动作拒绝、确认未知、回执丢失等仍保留诊断，且不因回执异常重复提交动作。

原生唱歌和跳舞依赖机器人原有能力，本包不新增音乐文件或原生技能。网页/讲解步骤中的灵创执行链路不改。普通语音“跳个舞”不再自动调用本地随机灵创资源，符合本次要求的原生表演方式。

导航先失败的语音未出现在本次 Java `/tts/speak` 文本中，因此平台或原生分支是排查重点。此次修正了可以确认的 SDK 响应类型错误，并验证本地两条语音通路不生成失败内容；实际平台侧是否还有独立播报，需要按现场验收核对，不能仅凭本地测试声称所有固件语音都已关闭。

## 三、先上传两个文件

需要同时上传 `.tar.gz` 和同名 `.tar.gz.sha256` 到机器人 `/home/run`。电脑上的文件不会自动出现在机器人。

在 Windows PowerShell 执行，按提示填机器人当前 IP：

```powershell
$robotIp = Read-Host "输入机器人当前IP"
$pkg = "E:\1资料\0火花机器人资料\0二次开发\灵犀导航微信小程序开发-v1.3.8\v138_control_reply_fix_deployment\dist\sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018.tar.gz"
scp "$pkg" "${pkg}.sha256" "run@${robotIp}:/home/run/"
```

文件若已移动，请把 `$pkg` 改为电脑上的实际路径。等待两个文件上传成功后再执行下一节。

## 四、机器人安装命令

在机器人终端执行。命令用 `&&` 串联，任一步失败会停止，不继续执行错误目录中的脚本：

```bash
cd /home/run &&
sha256sum -c sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018.tar.gz.sha256 &&
tar -xzf sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018.tar.gz &&
cd sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018 &&
sudo bash ./install.sh --check &&
sudo bash ./install.sh
```

看到 `安装成功：1.0.3-20261018` 后执行：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018
sudo bash ./control.sh doctor
sudo systemctl show lingxi-java-agent-robot.service \
  -p ActiveState -p SubState -p MainPID -p ExecMainStatus -p NRestarts
sudo sparkrobot-lingxi-internal doctor
```

安装前 Java Agent 停止时，安装后保持停止。需要启动业务时执行：

```bash
sudo sparkrobot-lingxi-internal start
sudo bash /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018/control.sh doctor
```

出现“文件不存在”时先确认两个交付文件已上传，不能继续安装。出现版本、JAR、SDK、运行清单或启动命令不匹配时不要跳过校验。权限问题应使用当前完整包的 `repair-permissions` 修复。旧 systemd 覆盖配置需要先核实实际用途，不能批量删除；本包不会擅自删改。

## 五、现场验收

在单独的机器人终端持续监听：

```bash
sudo tail -n 100 -F /var/log/sparkrobot/lingxi-nav/java-agent.log
```

每项测试前唤醒机器人，结束上一项任务并等机器人停稳，再进行下一项：

1. “带我去【网页已保存的点位】”：正常执行并确认前往，不应先播失败。再测试网页保存的讲解命令词，任务只启动一次。
2. “唱首歌”：机器人原有唱歌正常执行，不说功能关闭；Java 日志出现 `Native performance retained`，不应追加 `/entertainment/sing request`。
3. “跳个舞”：原生舞蹈执行一次，Java 不再追加本地空间准备语或 `/entertainment/dance request`。机器人固件自身的独立安全提示不由本增量改写。
4. “比个心”：不追加底层拒绝播报；随后没有明确问题时不自我介绍。说完整问题“你是谁”时仍可正常回答。
5. “打个招呼”“跟大家打个招呼”：执行现有挥手动作；等待数秒后重新唤醒再试，应仍能提交，不播问答不可用。模型异常时可看到 `Explicit local control fallback`。
6. 测试“不要打招呼”“你会打招呼吗”、正常知识问答、讲解暂停/继续/停止和导航停止，确认没有误动作或丢失原有功能。

`Local control response claimed ... type=chat` 表示本地接管响应；`Native performance retained` 表示保留原生表演，不代表 Java 已确认表演物理完成。`incomplete_asr_fragment` 表示忽略残句。`Motion not accepted` 仍是原始诊断，静默不能当作动作成功；本包不会修改真实拒绝状态或关闭运动安全限制。

普通问答遇到真实网络/模型不可用仍可能提示服务异常；本包修复的是明确动作错误落入问答故障路径，不会虚构外部服务已经恢复。

## 六、回滚

安装器会输出本次事务备份路径。保留这条路径，用它回滚到安装前字节：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.3-20261018
sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-control-reply-fix/backups/实际备份目录
```

回滚保持当前 Java 服务原有的运行或停止状态。备份属于其他 release，或文件又被后续补丁改动时会拒绝覆盖。安装失败自动恢复本次事务，不需要再叠加旧补丁。

## 七、复现后打包日志

复现完成后执行，生成时间独立的日志包。仅收集日志、服务状态及程序指纹，不读取密钥配置：

```bash
sudo bash <<'SH'
set -euo pipefail
stamp="$(date +%Y%m%d-%H%M%S)"
work="$(mktemp -d "/tmp/lingxi-control-reply-${stamp}-XXXXXX")"
archive="/home/run/lingxi-control-reply-${stamp}.tar.gz"
journalctl -u lingxi-java-agent-robot.service --since "1 hour ago" \
  --no-pager -o short-iso > "$work/java-service.log"
systemctl show lingxi-java-agent-robot.service \
  -p ActiveState -p SubState -p MainPID -p NRestarts > "$work/state.txt"
readlink -f /opt/sparkrobot/lingxi-nav/current > "$work/release.txt"
sha256sum /opt/sparkrobot/lingxi-nav/current/java/robot-local-navigation-java-all.jar > "$work/java-sha256.txt"
date -Is > "$work/capture-time.txt"
for name in java-agent lingxi_nav_bridge map_label_server_v3 robot_lingxi_bridge voice_nav_gateway; do
  if [ -f "/var/log/sparkrobot/lingxi-nav/$name.log" ]; then
    cp -- "/var/log/sparkrobot/lingxi-nav/$name.log" "$work/$name.log"
  fi
done
tar -czf "$archive" -C "$work" .
chown "${SUDO_UID:-0}:${SUDO_GID:-0}" "$archive"
echo "日志包：$archive"
SH
```

日志可能含现场识别文本，请用于内部排查。复核时附上复现时间、用户原话和实际播报。
