# V1.3.8 控制指令重复响应与失败误报修复

包名：`sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.0-20261018.tar.gz`

## 适用范围

适用于本项目已交付的 V1.3.8 r11～r15、且 Java Agent 与本包验证基线一致的机器人，推荐当前完整包 r15。安装前会自动核验 release、现有 JAR 指纹、AgentSDK 1.4.0 指纹及运行清单，遇到其他版本或现场改动会停止，不会强行覆盖。不能安装到 V1.3.9、V1.3.1 或旧 r10。

这是现场增量包，需要机器人已经安装完整系统。只更新 Java Agent 应用中的 `LingxiNavAgentApp` 及其内部类，其他 Java 类和第三方依赖逐字节保持一致；同步更新当前 release 的 `payload-manifest.json`。

无需重新编译或安装 AIMDK，无需重新填写 APP ID、密钥或知识库。地图、点位、讲解任务、灵创资源、唤醒与降噪策略、`lingxi.callbacks` 不变。安装过程中只短暂停止 Java Agent；导航、地图、网页和机器人本机语音桥不重启。请在机器人空闲、没有运行导航或讲解任务时安装。

## 修复内容

1. 导航或讲解请求被本地服务接受后，确认语由实际控制结果生成，不再使用意图模型附带的“做不到”“任务执行失败”等矛盾回复。
2. 显式导航、讲解、普通动作在适当阶段发送不带播报内容的 SDK `action` 中断；自定义讲解命令和模型识别的灵活控制意图在执行前同样接管动作响应，减少原生动作与本地执行链路重复响应。
3. 同一句控制指令在 ASR2LLM、ASR2TTS 重复回调时，只允许一次控制提交；不同事件的同类指令短时间内去重，同一事件与文本的重复请求保留 60 秒去重记录。停止指令始终可以再次下发。
4. 控制服务已接受请求后，SDK 的迟到、重复完成或发送异常只记录日志，不再追加 5001“处理失败”响应。SDK 中断发送失败也不会阻止本地导航或急停。
5. 真正的服务拒绝、未知点位、未收到动作确认仍有准确提示，不把“请求已接受”等同于“物理动作已完成”。AIMDK 的安全限制和运动控制没有修改。

本包针对本地 Agent 可控制的响应链路。机器人固件、平台侧独立业务产生的语音需要通过现场日志另行识别；本包不声称可以关闭所有固件播报。

## 安装

将压缩包与同名 `.sha256` 文件放到机器人 `/home/run`，在机器人终端执行：

```bash
cd /home/run
sha256sum -c sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.0-20261018.tar.gz.sha256
tar -xzf sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.0-20261018.tar.gz
cd sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.0-20261018
sudo bash ./install.sh --check
sudo bash ./install.sh
```

校验文件、脚本、文档均以 UTF-8/LF 打包，直接执行即可；不要编辑文件或重新生成校验清单。

安装前运行中的 Java Agent 会恢复运行；安装前处于停止或 failed 状态则保持停止，随后用网页的一键启动或下列命令启动业务：

```bash
sudo sparkrobot-lingxi-internal start
sudo systemctl show lingxi-java-agent-robot.service \
  -p ActiveState -p SubState -p MainPID -p ExecMainStatus -p NRestarts
sudo bash ./control.sh doctor
sudo sparkrobot-lingxi-internal doctor
```

补丁 doctor 验证文件版本、运行清单、JAR 与服务用户读权限；系统 doctor 才检查业务服务。安装器确认 Java 进程启动稳定，但不以此替代灵心平台认证、网络及现场语音验收。

如果提示“不支持的版本”或“JAR 与验证基线不一致”，保留提示，不能跳过校验强装。如果服务用户无权限，先执行当前完整包的 `repair-permissions`，再重新运行 `--check`。

## 现场验收

打开日志后，分别测试三组操作，测试之间结束上一项任务：

```bash
sudo tail -n 100 -F /var/log/sparkrobot/lingxi-nav/java-agent.log
```

1. 唤醒后说“带我去【已配置点位】”，应只有正常的前往确认，不再先说“做不到”。
2. 唤醒后说网页已保存的讲解命令词，任务应启动一次，不再附带“任务执行失败”。
3. 机器人站稳、没有导航或讲解任务时，说“跟我握个手”或自然表达相同意思。动作接受时不再追加“动作被拒绝”；不应重复握手。
4. 测试不存在的点位、真实不可用的动作服务和普通问答，确认没有把实际错误伪装成成功，普通问答仍能继续。
5. 讲解和导航停止指令应仍然立即生效，灵创保护阶段及语音拒识仍沿用原有策略。

日志中的 `Native tour action interrupt sent` 是取消 SDK 原生重复动作响应，不是停止本地已接管的导航或讲解。`Duplicate control response completed without dispatch` 表示拦截重复提交。`Suppressing SDK error after local performance was accepted` 表示本地已接受，只抑制后续 SDK 回包误报。

本包已进行本地 SDK 回调、模拟 HTTP 控制链路和 Linux 安装事务测试；未在你的机器人或真实灵心云端进行此次实测，最终以这组现场验收为准。

## 回滚

安装成功会输出本次独立的备份目录，内容只有旧 JAR、旧运行清单及事务元数据，不包含密钥。使用安装器输出的实际路径：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.0-20261018
sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-control-reply-fix/backups/实际备份目录
```

回滚只恢复本次更新文件，并保持回滚前 Java 服务的运行或停止状态。若安装后又被其他补丁更改，会拒绝覆盖；不要手动跳过检查。安装过程中失败会自动恢复本次事务一次，并尝试恢复原 Java 服务状态。

## 日志打包

需要复核残留播报时，复现一次后执行。日志可能包含识别文本，请仅用于内部排查：

```bash
sudo bash <<'SH'
set -eu
work="$(mktemp -d /tmp/lingxi-control-reply-XXXXXX)"
journalctl -u lingxi-java-agent-robot.service --since "-10 min" --no-pager > "$work/java-service.log"
tail -n 1500 /var/log/sparkrobot/lingxi-nav/java-agent.log > "$work/java-agent.log"
systemctl show lingxi-java-agent-robot.service -p ActiveState -p SubState -p MainPID -p NRestarts > "$work/state.txt"
tar -czf /home/run/lingxi-control-reply-logs.tar.gz -C "$work" .
chown run:run /home/run/lingxi-control-reply-logs.tar.gz
echo /home/run/lingxi-control-reply-logs.tar.gz
SH
```
