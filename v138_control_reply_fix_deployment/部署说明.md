# V1.3.8 控制回复修复 1.0.4 部署说明

交付日期：2026-10-18。

包名：`sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018.tar.gz`。

本包修复“语音带路、开始讲解已经成功，却额外播报抱歉或执行失败”的回复回归，包含控制回复修复 1.0.0～1.0.3 的已有功能。直接安装本包，不必逐个安装旧增量。

## 1. 修复依据

已对照项目聊天“V1.3.8 灵犀导航特殊版本”中处理同一句“抱歉，暂时我还没学会这个动作”的历史修改。当时为导航和讲解控制保留了灵心文本回复，即使启用本机播报和 `tts.suppressLingxiText=true`，也不会把这些控制回复清空。

当前 1.0.3 遗漏了这项例外：只要本机 TTS 接受请求，就连导航、讲解回复一起屏蔽。此次现场 15:50:12、15:58:23 的日志均显示，控制已接受，本机提交正确确认语后，仍记录 `Lingxi LLM text suppressed`。

1.0.4 恢复历史逻辑，并保留新版本的异常处理：

- 导航、讲解开始/暂停/继续/结束、停止导航：向 SDK 返回与实际控制回执一致的有效文本，完成回复。
- 普通问答：保持现场既有播报配置；本机 TTS 不接受或不可用时，仍允许返回灵心文本。
- 回执不确定、重复回调、已静默的底层动作拒绝：不会因为这次修改伪造成功回复或重发物理动作。
- 唱歌、跳舞仍由既有原生能力执行，不追加“功能关闭”“请给空间”或第二次本地表演请求。
- 保留此前打招呼意图补偿、残句和无关自我介绍过滤、模型暂态恢复与控制去重。

此次没有再次切换 `chat/action` 中断类型，也没有改写原生技能表或关闭机器人安全提示。修复的是可以从历史源码和当前日志核对的“控制回复被清空”问题。

## 2. 适用版本与影响

适用于本项目 V1.3.8 r11～r15 完整部署，安装器校验已知 JAR 和 AgentSDK 指纹。已安装控制回复修复 1.0.0～1.0.3 的机器人也能直接安装。

不适用于 V1.3.1、V1.3.9、r10 或未知修改版本；不匹配时安装器会停止。

运行文件只替换当前 release 的 `java/robot-local-navigation-java-all.jar`，同步维护 `payload-manifest.json`。不重装 AIMDK，不输入密钥，不修改地图、点位、讲解任务、资源、回调或降噪配置。只重启安装前正在运行的 Java Agent，其他业务服务不重启。

请在机器人没有执行导航、讲解或动作任务时安装。安装前 Java Agent 已停止时，安装后保持停止。

## 3. 上传文件

把 `.tar.gz` 和同名 `.tar.gz.sha256` 两个文件都传到机器人 `/home/run`。电脑文件不会自动出现在机器人上。

在 Windows PowerShell 执行：

```powershell
$robotIp = Read-Host "输入机器人当前IP"
$pkg = "E:\1资料\0火花机器人资料\0二次开发\灵犀导航微信小程序开发-v1.3.8\v138_control_reply_fix_deployment\dist\sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018.tar.gz"
scp "$pkg" "${pkg}.sha256" "run@${robotIp}:/home/run/"
```

若交付文件已移动，只修改 `$pkg` 为实际路径。两个文件均上传成功后再安装。

## 4. 安装

在机器人终端执行：

```bash
cd /home/run &&
sha256sum -c sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018.tar.gz.sha256 &&
tar -xzf sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018.tar.gz &&
cd sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018 &&
sudo bash ./install.sh --check &&
sudo bash ./install.sh
```

看到 `安装成功：1.0.4-20261018` 后执行：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018
sudo bash ./control.sh doctor
sudo systemctl show lingxi-java-agent-robot.service \
  -p ActiveState -p SubState -p MainPID -p ExecMainStatus -p NRestarts
sudo sparkrobot-lingxi-internal doctor
```

如果安装前服务已停止，需要使用时再启动：

```bash
sudo sparkrobot-lingxi-internal start
sudo bash /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018/control.sh doctor
```

文件不存在时先完成上传，不继续执行。版本或指纹不匹配时，不跳过检查。安装器还会以实际服务用户检查 JAR、SDK、配置可读性，并检查 systemd 启动路径和运行进程实际 classpath，避免修改了文件却仍运行旧覆盖包。

## 5. 验收

在一个终端监听：

```bash
sudo tail -n 100 -F /var/log/sparkrobot/lingxi-nav/java-agent.log
```

依次唤醒后测试，每项结束、机器人停稳后再开始下一项：

1. “带我去【已保存点位】”：正常确认前往并执行；不应再附加“抱歉……没学会这个动作”。
2. “开始讲解任务”和网页保存的自定义开始命令：任务正常启动，不应附加执行失败；同一语音只提交一次任务。
3. 暂停、继续、结束讲解和停止导航：回复与真实状态一致。
4. 握手、比心、打招呼：保留此前修复，不追加底层拒绝文案或问答不可用。动作底层真实拒绝仍保留日志。
5. 唱歌、跳舞和正常问答：保持原生表演与问答；不新增功能关闭、准备空间或无关自我介绍。

本次新增的日志标记：

```text
Lingxi reply text returned: eventId=..., priority=NAVIGATION
Lingxi reply text returned: eventId=..., priority=URGENT
```

对照同一 `eventId`：`/nav/start` 或 `/task/start` 接受、`/tts/speak` 提交正确确认语后，应出现上述文本回传记录，而不是屏蔽该确认语的记录。普通问答在本机模式下仍出现文本屏蔽记录是既有配置行为。

`doctor` 证明安装指纹、权限和加载路径符合要求，不代表云端声音或动作物理完成已验收。现场若仍出现原生独立播报，请记录具体时间、原话和实际播报，保留对应日志，不以静默当作执行成功。

## 6. 回滚

安装会打印本次事务备份路径。需要恢复时，用输出的真实目录替换示例：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.4-20261018
sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-control-reply-fix/backups/实际备份目录
```

回滚恢复安装前 JAR 和清单原字节、属主及权限，保持回滚前 Java 服务的运行/停止状态。安装失败会自动恢复本次事务；备份属于其他 release 或文件又被后续修改时拒绝覆盖。

## 7. 复现后取日志

```bash
sudo bash <<'SH'
set -euo pipefail
stamp="$(date +%Y%m%d-%H%M%S)"
work="$(mktemp -d "/tmp/lingxi-control-reply-${stamp}-XXXXXX")"

  --no-pager -o short-iso > "$work/java-service.log"

  -p ActiveState -p SubState -p MainPID -p NRestarts > "$work/state.txt"
readlink -f /opt/sparkrobot/lingxi-nav/current > "$work/release.txt"

for name in java-agent lingxi_nav_bridge map_label_server_v3 robot_lingxi_bridge voice_nav_gateway; do

    cp -- "/var/log/sparkrobot/lingxi-nav/$name.log" "$work/$name.log"
  fi
done
tar -czf "$archive" -C "$work" .
chown "${SUDO_UID:-0}:${SUDO_GID:-0}" "$archive"
echo "日志包：$archive"
SH
```
