# V1.3.8 控制回复修复 1.0.5 部署说明

交付日期：2026-10-19。

包名：`sparkrobot-lingxi-v1.3.8-control-reply-fix-1.0.5-20261019.tar.gz`。

用于处理语音导航、开始讲解已经执行，却额外播报“抱歉……”或任务失败的问题。本包是累计增量，直接替代控制回复修复 1.0.0～1.0.4，不需要依次安装旧增量。

## 1. 本次改动

已检查用户提供的 `linxiV1.3.1.zip`，其中是 V1.3.1 r7 完整包。知识库附加包会替换应用 JAR，所以本次参考的是附加包安装后实际生效的 JAR，并非只参考主包内旧源码。

同一组 204 项协议检查直接运行两个实际 JAR：V1.3.1 参考包全部通过，1.0.4 有 70 项不同，涉及 SDK 中断、双通道文本回复、SDK 完成与本机播报的顺序。1.0.5 据此调整：

- 导航、讲解开始/暂停/继续/结束和停止导航，保留 HTTP 控制与防重复提交，不再发送额外 SDK `chat` 或 `action` 中断。
- 在现场既有 `tts.mode=robot`、`tts.suppressLingxiText=true` 配置下，先结束 SDK 的 LLM 回复，再提交本机确认播报，SDK 不再同时回传同一句控制文本。
- SDK 完成消息传输异常仍不重发导航/任务、不上报会触发另一套回复的 SDK 错误，并继续尝试本机确认播报。
- 本机 TTS 拒绝时记录结果，不在已经结束的 SDK 回复上重新发送控制文本。控制是否成功仍按真实回执判断。
- 普通问答的播报配置和本机 TTS 不可用时的文本回退保留。显式配置 `tts.suppressLingxiText=false` 或使用灵心播报时，仍遵从该配置。
- 保留已有动作拒绝静默、打招呼意图补偿、唱歌跳舞原生处理、残句过滤、无关自我介绍过滤、模型恢复和控制回执校验。

这不是把 V1.3.1 整体覆盖回 V1.3.8；旧版的动作、问答和部署逻辑不回退。当前日志未记录同一时段 SOC2/云端完整音频执行链，协议差异已经验证，真实“抱歉”声音的独立产生源仍不能仅由 Java 日志断定。

## 2. 适用范围

适用于本项目 V1.3.8 r11～r15 完整部署，以及这些版本上已安装的控制回复修复 1.0.0～1.0.4。安装器核对 release、应用 JAR、AgentSDK 指纹和启动路径。

V1.3.1、V1.3.9、r10 和未知改动版本不在本包兼容范围。检查不匹配时会在覆盖前停止。

运行文件只替换 `java/robot-local-navigation-java-all.jar`，同步更新 `payload-manifest.json`。不重装 AIMDK，不修改密钥、地图、点位、讲解任务、灵创资源、唤醒、降噪或回调配置。只重启安装前正在运行的 Java Agent，其他业务服务不重启；安装前 Java 停止则安装后保持停止。

安装前让机器人结束正在执行的业务任务。

## 5. 现场验收

先打开实时日志：

```bash
sudo tail -n 100 -F /var/log/sparkrobot/lingxi-nav/java-agent.log
```

每项测试前唤醒机器人，每项结束、机器人停稳后再测下一项：

1. “带我去【已保存点位】”：一次确认、一次导航；不应额外播报“抱歉……没学会”。
2. “开始讲解任务”以及已保存的自定义开始命令：任务只启动一次，不追加失败语。
3. 暂停、继续、结束讲解，停止导航：回复与真实回执一致。
4. 握手、比心、打招呼：确认此前动作修复仍有效，不追加底层拒绝文案。
5. 正常问答、唱歌、跳舞：确认问答正常，表演不被本包重复提交或插入准备播报。

在现场本机播报配置下，导航和讲解完成后应有：

```text
Local control reply completed: eventId=..., sdkTextSuppressed=true, sdkCompleted=true, localTtsAccepted=true
```

对照同一事件：真实控制回执之后，应用先发送 SDK 完成消息，再提交本机 `/tts/speak`，最后写上述完成记录。现场普通日志不一定逐条打印 SDK 完成消息，具体顺序另由协议回放验证。该事件不应再出现 `Local control response claimed ... type=chat`，也不应出现该控制确认语的 `Lingxi reply text returned`。普通动作仍可出现 `type=chat`，这是保留的动作策略。

`localTtsAccepted=true` 表示本机 TTS 接受请求，不等于声音已被现场听见。若是 `false`，检查本机语音链路；不要重试已经接受的物理控制来补一句播报。真实 `busy`、未知点位、未配置任务等业务状态仍保留合理提示，不把它们伪装成成功。

## 6. 回滚

安装时会打印本次事务备份路径。用实际目录执行：

```bash

sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-control-reply-fix/backups/实际备份目录
```

恢复安装前 JAR、清单原字节和属主权限，并保持回滚前 Java 服务运行/停止状态。安装失败自动回滚；其他 release 的备份或后续又被修改过的文件不会被强行覆盖。
