# 现场日志核验与补充修复

核验对象：用户提供的 `lingxi-log-20261018-1015-1027.zip`。
补丁：V1.3.8 control-reply-fix 1.0.1-20261018。

## 结论

需要更新上一版 1.0.0 补丁。上一版能覆盖导航和讲解接受后使用错误回复、
原生动作响应接管不完整、重复提交、完成回包异常触发 5001 等机制，
但仍会将动作接口的 `rejected` 翻译成“暂未被接受”播报。
这不满足本次不播报底层动作兜底内容的要求。

新包保留前述修复，并将普通动作底层回执作为日志诊断处理，
不通过本机 TTS 或 SDK 文本播报失败，也不把拒绝改成成功。
无需先安装 1.0.0。

## 证据边界

1. 日志包中四份 Python/语音桥日志是空文件，没有 AIMDK 原始响应头、
   运动遥测或原生播报记录。仅凭 Java 的 `rejected` 不能证明动作实际失败，
   也不能证明其底层响应为什么与用户观察的物理动作不一致。
   本次解决的是已确认的低层回执播报路径，不改 AIMDK 接受判定与安全逻辑。
2. 导航和讲解的本地成功接收记录可确认；“做不到”“任务执行失败”的
   原生语音本体没有包含在这份包中，不能将其唯一归因于某个底层模块。
   新包覆盖已通过 SDK 回调测试复现的重复响应与错误回包机制，
   仍需现场确认固件或平台是否有独立播报。
3. Java 文件含时间倒序的多个片段，涉及不同活动地图；系统日志里的
   网页进程工作目录是 r15，但不能据此证明每一段 Java 记录都来自同一
   运行 JAR。安装器会实查当前 release、JAR 和 SDK 指纹，不依赖日志猜版本。
4. 10:24 附近有 Agent offline，10:26:16 有 `agentCallbackType is null`，
   随后重新绑定并能继续匹配启动任务。该记录不足以判定网络或平台断连根因。
   本包不声称修复外部网络和模型可用性。

## 验收重点

- 先结束导航或讲解，再按部署说明安装新包并核验 doctor。
- 对同一已配置点位说一次带路请求，对已配置任务说一次命令词，
  确认正常启动且没有前置或追加的失败语音。
- 停稳后分别测试握手、比心；若仍有底层拒绝，
  `Motion not accepted` 应只存在日志中，不能送入 `/tts/speak` 或 SDK 文本。
- 普通问答、停止导航、结束讲解、讲解打断与恢复仍需现场验收。
- 如果有残留播报，按部署说明采集新日志，包含 release/JAR 指纹。
  本次未连接或部署机器人，也未进行真实云端与物理动作验证。
