```java
return priority == TtsPriority.NAVIGATION || priority == TtsPriority.URGENT;
```

这一条件只在本机模式且启用文本屏蔽时使用；其他模式本来就返回文本。四个回调均传入结果优先级。完成该修改、部署和认证检查后，用户回复“好的，全部总结下……”，转入新机部署整理。

这证明该项修改属于用户接受的历史版本。历史回合没有附带录音或完整原生声学追踪，不能把它扩大解释为所有固件底层播报均已得到物理验证。

## 2. 1.0.3 的实际回归

当前 1.0.3 的条件只检查播报模式和本机 TTS 是否接受，没有控制优先级：

```java
return shouldReturnLingxiText(config) || ttsResult == null || !ttsResult.accepted();
```

因此本机 TTS 成功后，正常控制回复也被屏蔽。它保留了 TTS 失败时的问答补偿，却遗漏了历史控制回复例外。此前回归关注“不输出错误内容”和“动作只执行一次”，未检查本机 TTS 成功时 SDK 必须收到非空控制确认。
