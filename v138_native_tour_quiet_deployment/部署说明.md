# V1.3.8 原生讲解重复映射修复 1.0.10

适用于已安装 V1.3.8 r15/r16 完整包，以及这些主包上的控制回复、到点/TTS、1.0.8 或 1.0.9 增量。不用于 V1.3.9，也不需要重装 AIMDK。

## 本次处理

针对“开始讲解”实际已经执行，但又播报“抱歉，任务执行失败……”的现象，补上历史版本中曾使用的原生技能重复映射处理：

- 在当前机器人 SOC1 和已配置的 SOC2 上检查两种历史 `skills.json` 路径，只禁用 `start_fixed_line_intro / exhibit_commentary` 对应条目。
- 保留本地讲解任务、自定义命令词、任务步骤和讲解内容；普通问答、预设动作、唱歌和跳舞的技能条目保持原值。
- Java JAR、导航 Python 载荷与已交付 1.0.8 完全一致，恢复其导航控制静音逻辑，舍弃 1.0.9 新增的讲解回调提前结束方案。
- 为两块控制板保存原文件、权限、所有者和指纹，检查后重载 SOC2 原生语音服务，并提供联合回滚。

此前交付主要处理 Java SDK 回调和本地 bridge；它们不能替代对原生技能配置的处理。由于本次没有新的现场原生日志，重复映射是依据历史修复补齐的明确缺口，不代表已经证实是当前声音的唯一来源。已完成离线回归和故障测试，仍须完成本文的现场声音验收。

## 安装前

1. 先在网页结束讲解、导航和自动返航，确认机器人停稳。安装会短暂重载 SOC2 语音服务。
2. 将下面两个文件一起传到机器人的 `/home/run`：

   `sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019.tar.gz`

   `sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019.tar.gz.sha256`
3. 机器人上已有有效的 `/etc/sparkrobot/lingxi-nav/runtime.env`、SOC2 SSH 密钥和主机密钥记录。目标地址严格读取该配置，不使用固定 IP。
4. 在交互终端安装；如果 SOC2 的 Python 配置操作需要 sudo 密码，安装器会通过 SSH 终端提示输入。密码不会写入脚本或日志。

## 安装命令

在 SOC1，也就是运行网页控制台的机器人终端执行。整个代码块一次执行，任一步失败都会停止：

```bash
bash <<'INSTALL'
set -Eeuo pipefail
cd /home/run
sha256sum -c sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019.tar.gz.sha256
tar -xzf sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019.tar.gz
INSTALL
```

随后执行预检查和安装，分开执行是为了允许 SOC2 正常提示 sudo 密码：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019
sudo bash ./install.sh --check
```

确认预检查通过后：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019
sudo bash ./install.sh
```

本包累计携带 1.0.8 的到点判定、TTS 确认和控制静音运行文件，可以在已回滚的受支持主包上直接安装，不需要重新叠装 1.0.9。

预检查只读取配置和状态，会在 SOC2 建立并清理临时辅助目录，不修改技能配置，不启停服务。

成功时会显示原生映射数量、已禁用数量、事务记录和完整回滚命令。没有发现目标映射、配置格式异常、未知现场代码、SSH 或权限异常，均不得视为修复成功。

如果显示“原生映射已经禁用且运行文件等同于 1.0.8”，本次没有重复修改或重启；如果这种情况下仍有错误声音，本包已无可补齐的目标映射，需要原生运行日志定位其他来源。

## 安装后验收

安装保持 Java Agent 和导航服务安装前的运行/停止状态。原来停止的业务服务需要从网页点击“一键启动”；也可手工执行：

```bash
sudo sparkrobot-lingxi-internal start
sudo sparkrobot-lingxi-internal doctor
```

按顺序测试：

1. “带我去【已保存地点】”：正确启动一次导航，不额外播报底层成功、失败或“没学会”。
2. “开始讲解”：启动一次任务，不额外播报“抱歉，任务执行失败……”。
3. 用网页配置的自定义开始命令词重复上一项。
4. 到达讲解点后正常播放配置的讲解内容；暂停、继续、结束任务正常。
5. 唤醒后问普通问题；握手等预设动作正常，唱歌和跳舞保持原有行为。

“收到”是允许的中性确认；本包保留 1.0.8 现有回复行为，没有额外增加确认语音。安装器不会启动导航或讲解来做自动验收。

## 回滚

使用安装成功时打印的完整命令。参数是本包的事务记录 JSON 文件，例如：

```bash
cd /home/run/sparkrobot-lingxi-v1.3.8-native-tour-quiet-1.0.10-20261019
sudo bash ./install.sh --rollback /var/lib/sparkrobot/lingxi-native-tour-quiet/transactions/实际事务编号.json
```

回滚会校验原文件指纹，恢复两块控制板的技能配置及本次改动过的运行文件，并按需要重新加载 SOC2 语音服务。若安装后文件又被其他补丁修改，会拒绝覆盖，保护后续变更。

安装失败会尝试联合恢复；如果显示“自动恢复未完成”，保留事务记录和屏幕报错，不要反复叠装。已损坏的 SSH 通道需要恢复后才能完成远端回滚。

## 异常信息

- “未找到历史原生讲解映射”：本机配置不符合此历史问题，安装未修改运行文件或停止服务。
- “SOC2 需要 sudo 密码”：请在普通 SSH 交互终端运行本文命令，不要通过没有终端的网页脚本安装。
- “无法确认机器人语音 bridge 状态”：先检查已有服务和运行清单，勿绕过检查。
- “服务状态不稳定”或“仍有导航、讲解或自动返航任务”：等服务稳定、结束任务后再预检查。
- “Python 文件不是已验证版本”：该机器人存在不同补丁或现场改动，需要先核对版本，不能强制覆盖。

现场声音仍异常时，下面命令可实时核对应用侧行为；这份日志不等同于原生声音源日志：

```bash
sudo tail -n 100 -F /var/log/sparkrobot/lingxi-nav/java-agent.log /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log
```
