# 1.0.10 修复与验证范围

## 事实和边界

用户确认 1.0.8 已屏蔽语音导航的底层播报，讲解启动仍有“抱歉，任务执行失败……”；1.0.9 现场反馈无效并使导航播报回归，已回滚。本次用户说明上传的 1.0.6 ZIP 发错，授权在没有新现场日志的情况下继续处理。

因此本次不把 1.0.9 的 SDK 回调顺序试验作为修复基线，也不宣称已经根据 1.0.8 现场日志确认声音来源。

## 修复依据

历史部署脚本曾对两个原生映射标记 `enabled=false`：

- `skill_name` 或 `skillName` 为 `start_fixed_line_intro`；
- `value` 为 `exhibit_commentary`。

1.0.8/1.0.9 的安装器没有检查、禁用或重载这层配置。本次补齐这一缺口，同时保持 1.0.8 Java JAR 和导航 Python 载荷逐字节不变。不会将全局 TTS 静音，不会按句子关键字删除用户正常讲解，也不伪造任务成功响应。

安装器读取 SOC1 和 SOC2 两个历史路径，按实际解析的文件去重；有目标才处理。只更改匹配条目的 `enabled` 字段，其余 JSON 值保持一致。配置已禁用时不会重复改写。

## 验证内容

交付验证程序实际运行以下检查，数量与结果以同目录 `交付验证结果.json` 为准：

- 校验不可变 1.0.8 包指纹，确认全部运行载荷与其逐字节一致。
- 从包内原始 1.0.8 Java 源码重新编译，逐 class 比对交付 JAR，执行 1.0.8 的 17 组 Java 回归。
- 执行包内导航 Python 回归，覆盖静音会话、到点和 TTS 确认行为。
- 在 Linux 临时文件系统执行原生映射测试、原安装事务测试和新增双板协调事务测试。
- 模拟两个配置路径、路径别名、既有禁用状态、无匹配、错误 JSON、文件过大、权限元数据、并发变更、写入失败、备份损坏、SSH 回执丢失、原生服务重载失败，以及联合恢复和回滚。
- 确认导航、唱歌、跳舞、握手、普通问答的其他技能条目保持原值。
- 校验最终压缩包内外 SHA-256、LF 换行、Python 语法、Shell 脚本和部署命令语法。

测试不会连接机器人，没有做真实原生声音、云端模型或物理动作验收。新安装器会检查并重载实际 SOC2 配置，但“额外错误声音已消失”必须由部署后现场验收确认；如果两板目标映射均不存在或已经禁用而错误声音仍在，不能据此推断问题已解决。
