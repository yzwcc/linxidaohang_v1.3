# 灵犀 v1.3.1 完整部署教程

版本：v1.3.1-complete-20261023-r14
适用对象：内部部署、售后和现场验收人员  
适用系统：Ubuntu 22.04 ARM64、ROS 2 Humble、智元 X2 系列机器人

本文档对应同目录的完整部署包。命令中的版本号必须与包文件名一致，不能把旧的 r5、r6 或单独 PNC 包混用。整个过程不会修改直播项目目录，也不会把任何真实密钥写入部署包。

## 1. 部署结果

完成后，机器人本机提供以下能力：

| 能力 | 主要位置或服务 | 说明 |
| --- | --- | --- |
| 网页控制台 | http://机器人IP:3000/console/ | 手机和机器人同一局域网即可访问 |
| 导航 bridge | 18080 | 接收网页导航、停止、重定位和任务请求 |
| 地图服务 | 8002 | 地图列表、地图图片、点位和任务数据 |
| 语音兼容网关 | 18082、18083 | 导航与机器人本机语音之间的桥接 |
| 知识库代理 | 127.0.0.1:18084 | 调用灵心 Retriever Proxy，不对局域网开放 |
| Java Agent | lingxi-java-agent-robot.service | 灵心连接、语音问答和知识库答案回传 |

机器人服务部署在机器人本机，客户不需要打开电脑或公网服务器。机器人 IP 不是固定值，网页地址和现场记录都应使用本次机器人实际 IP。

## 2. 组件和安装顺序

完整包内的组件版本如下：

| 组件 | 文件或版本 | 安装阶段 |
| --- | --- | --- |
| AIMDK | aimdk-aarch64-1bde262f-artifacts.7z，v0.0.0-g1bde262 | prepare 后由 agi 替换 |
| 导航主包 | sparkrobot-lingxi-nav-internal-1.0.7-20260901 | install-navigation |
| 灵创 | sparkrobot-lingxi-linkcraft-addon-1.0.3-20260902 | install-addons 的第一步 |
| 知识库和语音接入 | sparkrobot-lingxi-kb-1.0.9-20261023 | install-addons 的中间步骤 |
| 连续导航修复 | sparkrobot-lingxi-consecutive-nav-fix-1.0.5-20261023 | install-addons 的最后覆盖步骤 |

连续导航修复必须最后安装，因为它需要覆盖灵创包可能修改过的导航 bridge、动作控制和导航客户端文件。安装结束后安装器会重启网页控制台，使灵创资源列表和新后端代码立即生效。

## 3. 账号和权限边界

| 账号 | 用途 | 是否需要 sudo |
| --- | --- | --- |
| Windows 用户 | 校验和上传文件 | 不适用 |
| 机器人 run | 外层安装器、系统依赖、导航、附加包和运维 | 是 |
| 机器人 agi | AIMDK 解压、编译、验证和替换 | 否，且不要给它额外 sudo |

run 不能通过 newgrp 刷新组权限不是安装失败。安装器用绝对路径、sudo 和 runuser 处理权限，不要用 newgrp 代替安装步骤。若 run 没有 sudo，必须让设备管理员执行安装；安装包不能绕过系统 sudoers。

## 4. 安全和现场前提

部署前确认：

1. 机器人已开机、联网、电量充足，实体急停可用。
2. 可以用 agi 和 run 登录机器人。
3. 机器人为 ARM64，ROS 2 Humble 已安装。
4. /agibot/data/var/MapManagerModule 存在，根分区和 /home 至少预留 5 GB。
5. 机器人可以访问 Ubuntu 软件源和 https://open.agibot.com。
6. 已准备与灵心应用匹配的 App ID、AppKey、AppSecret、豆包 Key，以及正确的 Retriever 智能体 Code。
7. 真实重定位、导航、动作和讲解任务只在现场有人看护并可急停时执行。

本包不包含以下敏感内容：灵心密钥、豆包 Key、SOC2 私钥、知识库密钥、SSH 密码和直播项目配置。安装时的密钥只应在机器人终端交互输入。

## 6. 机器人端校验和解压

以下命令在机器人 run 终端逐行执行：

~~~bash
cd /home/run
sha256sum -c lingxi-v1.3.1-complete-20261023-r14-deployment.tar.gz.sha256
tar -xzf lingxi-v1.3.1-complete-20261023-r14-deployment.tar.gz
cd /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment
chmod +x install_all.sh control_all.sh
~~~

校验文件必须显示：

~~~text
lingxi-v1.3.1-complete-20261023-r14-deployment.tar.gz: OK
~~~

如果出现文件名末尾带 $'\r'、FAILED 或 No such file，通常是校验文件被 Windows 编辑器改成了 CRLF，或两个文件不是同一批生成的。不要继续安装；优先重新上传原始 tar.gz 和 sha256。若确认只是在传输中增加了 CR，可在机器人上执行以下恢复，再重新校验：

~~~bash
sed -i 's/\r$//' /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment.tar.gz.sha256
sha256sum -c /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment.tar.gz.sha256
~~~

解压后根目录必须包含：

~~~text
README.md
VERSION
bundle-manifest.json
SHA256SUMS.txt
install_all.sh
control_all.sh
docs/
components/
~~~

## 7. 阶段一：安装环境并准备 AIMDK

仍在 run 用户、完整包目录执行：

~~~bash
cd /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment
bash ./install_all.sh prepare
~~~

该阶段会：

- 检查当前系统为 ARM64；
- 校验完整包内所有组件；
- 安装 p7zip-full、colcon、CMake、编译器和导航所需 ROS 包；
- 将 AIMDK 压缩包复制到 /home/agi/；
- 将 AIMDK 替换脚本和定位检查脚本复制到 /home/agi/；
- 将导航包和后续脚本复制到 /home/run/。

成功提示类似：

~~~text
[通过] 文件已准备。请切换 agi 用户执行：cd /home/agi && bash ./01-replace-aimdk.sh
~~~

如果 apt-get update 失败，先修复机器人 DNS、路由或软件源。不要在缺少 7z、colcon 或 ROS 依赖时强行编译。

## 8. 阶段二：由 agi 替换 AIMDK

run 和 agi 在部分固件上使用不同的系统视图，建议开新的 SSH 会话：

~~~powershell
ssh ("agi@" + $RobotIp)
~~~

在 agi 终端执行：

~~~bash
cd /home/agi
bash ./01-replace-aimdk.sh
~~~

脚本内部会：

1. 校验 AIMDK SHA-256。
2. 解压到 /home/agi/aimdk-staging-v131。
3. 读取版本并执行 colcon build。
4. 在替换前导入 ROS 和新 AIMDK，检查 rclpy、aimdk_msgs、导航示例和 ROS 话题查询。
5. 只有上述验证成功后，才删除旧 /home/agi/aimdk，随后将新目录移动为该路径。
6. 在干净 shell 中再次验证，避免当前会话残留环境变量造成假成功。

正常输出应包含：

~~~text
AIMDK_IMPORT_OK
AIMDK_OK
aimdk_msgs
[通过] AIMDK 替换完成
~~~

本版本明确不要求以下两个可选模块：

~~~text
aimdk.protocol.mm.relocalization_pb2
ros2_plugin_proto.srv
~~~

如果旧 AIMDK 已不存在，脚本仍会在新版本编译和验证成功后直接安装。若编译失败，脚本不会删除已有可用 AIMDK；请保留错误输出。

完成后退出 agi SSH：

~~~bash
exit
~~~

## 9. 阶段三：安装导航主包

回到 run SSH 会话：

~~~bash
cd /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment
~~~

该阶段首先确认 /home/agi/aimdk/install/setup.bash 可导入 rclpy 和 aimdk_msgs。如果出现 ModuleNotFoundError: No module named rclpy 或 aimdk_msgs，先回到第 8 节，不要安装附加包。

| 提示 | 填写原则 |
| --- | --- |
| 灵心 APP ID | 导航项目实际使用的 App ID |

## 10. 阶段四：安装全部附加能力

先确认导航配置存在：

~~~bash
sudo test -f /etc/sparkrobot/lingxi-nav/lingxi-nav.properties && echo "导航配置存在"
~~~

用灵心平台中与知识库绑定的智能体 Code 安装：

~~~bash
cd /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment
bash ./install_all.sh install-addons --agent-code AI_AGENT_xxxxxxxx
~~~

把 AI_AGENT_xxxxxxxx 替换为灵心平台中与知识库绑定的实际智能体 Code。智能体 Code 必须符合 AI_AGENT_ 开头的格式；安装器会拒绝空值、带空格或不匹配格式的输入。

### 10.1 安装顺序和副作用

1. 灵创：备份并更新讲解任务的动作、表情、资源扫描和网页资源读取代码，使用 --no-restart 暂不重启 bridge。
2. 知识库服务：复用现有导航配置中的灵心三项参数，写入受保护的 /etc/sparkrobot/lingxi-kb/retriever.env，安装本机 127.0.0.1:18084 服务并设为开机启动。
3. Java Agent：备份旧 JAR，安装含 V1.3.8 交互拒识策略的知识库语音接入版本，只重启 lingxi-java-agent-robot.service。
4. 连续导航修复：最后覆盖 9 个导航 Python 文件（含语音预置动作白名单、活动地图歧义别名查询、TTS 流代次协议和服务派发适配），修复有限动作收尾、连续点位不走、PNC 回验重试、ROS 环境加载和运行目录权限问题；默认重启导航 bridge。
5. 网页控制台：最后重启 lingxi-nav-console.service 并检查 127.0.0.1:3000/health，确保新灵创资源选项已经加载。

该阶段不会发送真实导航、重定位、动作、舞蹈或语音指令。安装中断后可以在同一目录重新执行，安装器会清理固定的临时目录并保留各组件自己的备份。

### 10.2 语音交互拒识策略

Java Agent 现在会过滤无信息填充词、重复 ASR 片段、播报回声和静音窗口内未唤醒的输入。唤醒门控默认为 `enforce`，要求 SDK KWS/唤醒状态回调或可核验的新鲜 SOC2 唤醒证据；唤醒证据时效和连续对话窗口均默认为 8 秒。仅在识别文本中说出唤醒词，不算真实唤醒证据。

质量门控默认兼容 SDK 缺失质量元数据；元数据存在时按 DOA 正前方半角 60°、SNR >= 6 dB、AEC 残余回声 RMS <= 0.12、VAD 语音概率 >= 0.70、ASR 置信度 >= 0.65 拒识。仅在厂商前端确实提供且已标定这些字段后，才可将 `voice.gate.metadataRequired` 设为 `true`，否则合法语音也可能因缺字段被拒绝。

低 ASR 置信度会拒绝普通指令；在机器人 TTS 模式下，Java Agent 会请求播报“刚才没有听清，请再说一遍。”开始/继续讲解不会绕过该门控。明确停止导航和停止讲解文本会优先处理；原始音频仍需先完成现有转写，不能将此行为理解为端侧离线 ASR。

这是软件输入质量/唤醒策略，不会修改 PCM 音频，也未接入端侧 RNNoise、AEC、DOA 麦克风处理。其离线回归测试不等于真实环境声学验收。日志可用以下命令按拒识原因筛查：

~~~bash
sudo journalctl -u lingxi-java-agent-robot.service --since "30 min ago" --no-pager \
  | grep -E 'Text ignored by quality gate|Text ignored by wake gate|Wake state|SOC2 wake evidence'
~~~

变更策略属性前先确认 Agent 服务的 `WorkingDirectory`，再修改其 `config/lingxi-nav.properties` 或使用对应 `VOICE_GATE_*` 环境变量。拒识影响正常交流时，可通过 KB 包 `install_voice_agent.sh --rollback <备份JAR>` 仅回滚 Java Agent，不卸载知识库服务。

### 10.3 语音预置动作

预置动作由 Java Agent 识别口令，导航 bridge 二次核验原始语音与运行状态。仅导航空闲、且没有进行或暂停中的讲解任务时才会提交；直播弹幕不触发。

支持：挥手、握手、举手、飞吻、比心、击掌、敬礼、平举、拥抱、加油、鼓掌、双手打叉、胸前挥手、鞠躬、拜拜、动感光波、挠头、抓屁股。示例：“请和我握个手”“请双手比心”“用左手挥手”“麻烦你鞠躬”。

问句、否定、引用/转述和条件表达会拒识，不根据动作名称猜测意图。回复“已受理/已提交”只说明请求进入动作服务，不代表动作已完成。现场测试任何动作前都要确认机器人周边安全并备好实体急停。

### 10.4 回答速度与事实约束

- 导航点位名称缓存 10 秒，减少每轮对 bridge 的重复查询；点位变更可能最多延迟 10 秒反映到语音识别上下文。
- 普通文本问答复用首轮意图解析返回的 `reply`，避免意图识别后再串行发起第二次模型请求；只有首轮 `reply` 为空才触发聊天兜底。身份、日期、时间和简单文本寒暄使用确定性短答。
- 只有机器人/场馆/企业/地点等本地事实或时间、价格、开放状态等实时事实才查询知识库；关闭 rerank 和 QA 前置检查，客户端最多等待 1200 ms，并要求相关度分数至少 0.60。命中时使用资料答案，未命中、低分或超时则明确表示无法核实，不把模型猜测当事实。
- r14 对需要事实依据的文本问题并行启动知识检索和意图解析。检索池固定为 2 个线程、4 个排队位；队列满时记录回退，并在意图解析完成后串行检索。该策略只重叠等待，不保证固定端到端提速。
- 普通开放式聊天和一般常识不额外串行查询知识库；首轮提示要求简短回答、不要编造，并在不确定时澄清。历史模糊问答缓存不再参与答案选择。
- 上述门控降低无依据回答的风险，但不能证明模型对所有常识回答都绝无错误。知识库内容需保持准确、更新；重要现场信息以工作人员确认为准。

原始音频路径仍需调用当前模型完成识别、意图和回答；文本路径的一般聊天通常为一次模型请求。r14 增加可选的模型流式输出和有序 TTS 分段能力，但 `doubao.streamingReplies` 默认关闭，不改变原有 800 ms 播报等待。它不覆盖端侧 ASR，也不代表机器人已通过 AIMDK PlayTts 连续队列验收。排查实际延迟时按同一 `eventId` 查看第 15 节的分段耗时日志。

### 10.5 已知点位导航快速路径

文本回调拿到识别结果后，会先读取当前活动地图的语音点位名称列表。对于“带我去正门”“导航到大门”这类明确命令，只有目标与列表中的完整名称或别名精确匹配时，才直接创建导航意图并跳过一次意图模型请求。名称匹配会忽略大小写和空白，但不做部分匹配。导航 bridge 仍会再次按活动地图解析目标并校验，因此未知、失效或歧义点位不会被当作成功导航。

否定、条件、引用文本、问句标点/疑问尾词、未知地点和部分点位名不会命中该快速路径，继续交由既有意图模型处理。该路径仍执行交互状态登记和 `/nav/start` 提交；它只减少文本识别之后的一次模型往返，不改变导航执行、播报等待或直播入口。

原始音频回调仍先调用当前配置的 Doubao 转写/意图模型，再对模型返回的最终识别文本尝试相同的精确点位匹配。因此，r14 仍未实现端侧离线 ASR，也不提供“原始音频不经过灵心/云端”的保证。要实现这一点，需要另外接入并验证端侧 ASR 和音频路由。

如果当前地图中多个点位使用同一归一化语音名称/别名，Java Agent 会请求澄清并且不调用导航提交接口。导航 bridge 仍会独立校验活动地图和目标，避免缓存或状态变化造成错误导航。

### 10.6 命令路由与并行检索

- 明确的文本“停止导航”“停止讲解”等命令在意图模型请求前本地匹配并进入现有停止处理。音频输入须先经当前转写模型；拿到识别文本后再走同一停止命令路径。
- 本地导航别名发生歧义时只澄清，不提交导航。该检查同时用于文本输入和音频转写完成后的文本。
- ASR 置信度低于门槛时，普通导航/任务命令不执行；机器人 TTS 模式会提示用户重说。停止命令优先处理，开始/继续讲解不绕过低置信度门控。
- 本地事实问题会在意图解析期间并行启动 Retriever 请求。执行器上限为 2 个工作线程和 4 个等待任务；队列满时不丢弃事实查询，而是回退到意图解析后的串行检索。
- 并行检索不能消除模型、云端转写、TTS 或网络延迟；原始音频依旧使用配置的转写模型。流式回复默认关闭，800 ms 播报等待未改变。

### 10.7 可选流式回复

- KB Java Agent 带有 Doubao SSE 解析和分句 TTS 能力，但 `doubao.streamingReplies=false` 是默认值。新部署和已有 AIMDK 路径都不会自动开启它。
- 仅普通文本闲聊、`tts.mode=robot` 且非固定对话测试可进入流式路径。知识库/事实核实、身份/日期/时间问题、停止与导航命令、讲解任务控制、预置动作及原始音频不走该路径。
- 启用前，在安全维护窗口确认 Java Agent 工作目录：`sudo systemctl show -p WorkingDirectory --value lingxi-java-agent-robot.service`。备份并编辑该工作目录下的 `config/lingxi-nav.properties`，设置 `doubao.streamingReplies=true`，随后重启 `lingxi-java-agent-robot.service`。不得修改直播项目配置。
- 第一段只在模型明确给出 `chat` intent 后提交，并使用 interrupt；后续段按序号提交且不打断前段。首段播报前发生流式请求错误时回退普通请求；已播出部分内容后模型中断会播报简短中断提示。TTS 续段失败后，只有仍持有播报权的会话才回退完整最终答复；已停止或被新播报抢占的旧会话会抑制该回退。
- 升级不会覆盖 Java Agent 工作目录中的现有 properties；若旧配置曾手动将 `doubao.streamingReplies` 设为 `true`，该值会保留。未完成目标机器人验收时应恢复 `false`。
- 流式协议测试使用本机假 HTTP 模型/bridge，不能证明目标 AIMDK 的 PlayTts 服务会按预期排队、打断或恢复。启用前逐项验收普通聊天、503 回退、模型流中断、第二段拒绝、下一轮语音、导航、讲解和硬件急停。发现错序、重叠、截断或错误抢占，立即恢复 `false` 并重启 Java Agent。
- 本功能不调整 `tts.delayBeforeSpeakMs`，默认关闭状态下既有非流式行为保持不变。当前没有实体机器人声学或 AIMDK 队列验收结论。

### 10.8 流式会话所有权保护

R14 为每条流使用唯一 `stream ID`。停止请求会封存对应 ID，阻止迟到的首段重新创建已停止会话；新流或新 TTS owner（包括普通回复）会递增派发代次，使旧流尚未提交的续段失效。导航 bridge 在等待 PlayTts 服务后、调用 `call_async` 前，会在同一协议锁内重新核验流 ID 和代次，避免停止或抢占先到时旧请求在服务恢复后补发。

Java Agent 为每个 TTS 决策分配 `owner token`。新的普通回复也可取得 owner 并抢占旧流的软件会话；旧回调不能清除新请求状态、继续提交后续段或回放完整旧答复。有效 owner 下的续段失败仍保留完整答复回退。

若 `call_async` 已提交 PlayTts 请求，本桥接层不具备撤回或停止能力：已提交的请求不能由该层撤回，已排队/正在播放的语音也不能由 `stream_action=end` 停止。上述保护只约束软件会话和后续派发，不代表 AIMDK 队列行为已在目标机器人验证。

## 13. 地图、定位和点位验收

新机器人还没有录入地图或点位时，网页显示 point_names=[] 是正常状态，不代表部署失败。

### 13.1 选择地图

1. 在网页刷新地图列表。
2. 选择底层当前实际使用的地图名称，地图名称必须与机器人导航层一致。
3. 若刚新建地图，先确认地图服务已经保存并重新加载；不要用旧地图名称做重定位。

### 13.2 录入点位

在地图配置中：

1. 添加一个起点并明确标记为起点。
2. 添加至少两个安全导航点。
3. 为点位填写中文显示名、语音别名和到达播报文本。
4. 保存后刷新，确认点位仍在当前地图下。

### 13.3 检查实际定位

用 agi 用户执行：

~~~bash
source /opt/ros/humble/setup.bash
source /home/agi/aimdk/install/setup.bash
ros2 topic info /slam/lidar_odom
timeout 10 ros2 topic hz /slam/lidar_odom
~~~

必须先看到持续的 /slam/lidar_odom 数据，再在网页执行自动重定位。重定位依据机器人当前实际位置和朝向，不需要设置人为参考点；地图必须与当前环境一致。没有持续定位数据时不要反复点击重定位，先退出建图状态、启动定位模式或按现场流程恢复底层导航。

## 14. 真实导航和讲解任务验收

这一步会移动机器人，必须由现场人员授权、清空周边障碍并准备急停。

推荐顺序：

1. 先用单个短距离点位测试“去这里”和“停止导航”。
2. 再建立只含两个点位的讲解任务。
3. 第一个点配置短语音和普通有限动作，例如挥手；第二个点暂时不配置灵创舞蹈。
4. 启动任务，确认第一个点到达、讲解完成后能继续前往第二点。
5. 再单独配置一个灵创动作或舞蹈，确认网页资源列表能选择实际存在的资源。
6. 最后验证完整路线、起点返航和语音指令。

连续导航修复的关键验收信号：第一个点普通动作结束后不应无条件发送 motion=0, area=0；第二个点提交后目标距离应持续下降。持续动作 6001 或明确暂停/停止场景仍允许发送空动作中断。

讲解阶段支持：

- “开始讲解”；
- “暂停讲解”；
- “继续讲解”；
- “停止讲解”。

行进中可以进行普通语音问答；唤醒后讲解会按策略暂停。灵创动作阶段不会被普通聊天抢占，明确停止或结束任务仍可中断。

语音预置动作只在导航和讲解任务空闲时执行。讲解中的问答与动作请求分开处理；如果机器人正在导航或讲解，动作请求会被拒绝。

## 16. 常见故障处理

### 16.1 ./install.sh: command not found

说明当前目录不是组件目录，或外层包尚未解压。检查：

~~~bash
pwd
ls -lh
cd /home/run/lingxi-v1.3.1-complete-20261023-r14-deployment
~~~

完整包只执行 bash ./install_all.sh ...，不要在 /home/run 根目录直接执行 ./install.sh。

### 16.2 AMENT_TRACE_SETUP_FILES: unbound variable

这是旧脚本在 set -u 下直接加载 ROS 环境造成的。当前完整包内 AIMDK 脚本和连续导航控制脚本已在加载厂商环境时临时关闭 nounset。确认使用的是本包 r14，然后重新执行对应阶段，不要手工删掉其它保护。

### 16.3 No module named rclpy 或 aimdk_msgs

先以 agi 身份确认：

~~~bash
source /opt/ros/humble/setup.bash
source /home/agi/aimdk/install/setup.bash
python3 -c "import rclpy; import aimdk_msgs.msg; print('AIMDK_IMPORT_OK')"
~~~

失败时回到 prepare 和 AIMDK 替换阶段。不要只设置临时 PYTHONPATH 后继续安装，因为服务启动需要干净 shell 也能导入。

### 16.4 网页显示日志目录 Permission denied

先执行：

~~~bash
sudo sparkrobot-lingxi-complete repair-permissions
sudo sparkrobot-lingxi-complete restart-navigation
~~~

再刷新网页并点击“一键开启全部服务”。当前修复包安装和每次 bridge 重启都会校正 /var/log/sparkrobot/lingxi-nav、ROS 日志和 PID 目录的共享组权限。

### 16.5 网页没有灵创舞蹈选项

确认附加安装已经完成并重启网页控制台：

~~~bash
sudo sparkrobot-lingxi-linkcraft resources
sudo systemctl is-active lingxi-nav-console.service
sudo systemctl restart lingxi-nav-console.service
~~~

资源列表为空通常表示机器人资源目录尚未下载灵创资源，不是网页故障。本包不会伪造或自动下载舞蹈资源。

### 16.6 知识库返回 data=[]

code=0 且 data=[] 表示接口调用成功但没有命中内容。确认知识库已完成索引、已绑定安装时使用的 Agent Code，且测试问题与内容相关。检查：

~~~bash
curl -fsS http://127.0.0.1:18084/health
kb-search "与知识库明确相关的问题" --top-k 5
~~~

### 16.7 灵心或机器人语音未上线

~~~bash
sudo systemctl is-active lingxi-java-agent-robot.service
sudo journalctl -u lingxi-java-agent-robot.service -n 200 --no-pager
sudo sparkrobot-lingxi-complete logs voice
~~~

确认 App ID、AppKey、AppSecret 属于同一应用，机器人能访问 open.agibot.com，并在网页重新执行“一键开启全部服务”。不要修改直播项目配置来排查本产品。

### 16.8 第二个点位不走或到点后超时

不要连续重复下发导航。先收集：

~~~bash
sudo sparkrobot-lingxi-complete doctor | tee /home/run/complete-doctor.txt
sudo tail -n 1500 /var/log/sparkrobot/lingxi-nav/lingxi_nav_bridge.log > /home/run/lingxi-nav-last-1500.log
sudo sparkrobot-lingxi-consecutive-nav-fix status
~~~

确认当前安装的是 1.0.5-20261023，并检查第二个目标距离是否变化、MC 输入源是否仍被 interaction 占用。若仍异常，把上述文件和复现时间交给开发人员，不要先回滚或删除日志。
