# 灵心知识库独立部署教程

版本：`sparkrobot-lingxi-kb-1.0.10-20261023`

本包用于给已经部署灵犀基础语音的机器人增加知识库问答能力，包含独立 Retriever Proxy 服务和已验证的 Java Agent 接入更新。不包含导航、地图、AIMDK 或直播项目配置。安装知识库服务不会修改原灵犀配置；安装语音接入只替换 Java Agent JAR，并自动备份旧版本。

## 一、准备条件

机器人需要满足：

- Ubuntu 22.04 ARM64，Python 3.10 或更高版本。
- 已有 `run` 账号并可以执行 `sudo`。
- 机器人能够访问 `https://open.agibot.com`。
- 已在灵心平台创建智能体，并将知识库关联到该智能体。

在已部署灵犀导航的机器人上，最简单的方式是复用现有灵心配置。安装器只读取以下三个配置项，不会改写原文件：

```text
/etc/sparkrobot/lingxi-nav/lingxi-nav.properties
lingxi.appId
lingxi.appKey
lingxi.appSecret
```

智能体 Code 可以由安装器从现有 Java 日志自动识别；也可以手动从灵心平台复制，格式通常为 `AI_AGENT_...`。

## 二、Windows 上传

将以下文件放在同一个 Windows 目录：

```text
sparkrobot-lingxi-kb-1.0.10-20261023.zip
sparkrobot-lingxi-kb-1.0.10-20261023.zip.sha256
```

在 PowerShell 进入该目录，上传到机器人：

```powershell
scp .\sparkrobot-lingxi-kb-1.0.10-20261023.zip run@机器人IP:/home/run/
scp .\sparkrobot-lingxi-kb-1.0.10-20261023.zip.sha256 run@机器人IP:/home/run/
```

例如：

```powershell
scp .\sparkrobot-lingxi-kb-1.0.10-20261023.zip run@172.20.10.2:/home/run/
scp .\sparkrobot-lingxi-kb-1.0.10-20261023.zip.sha256 run@172.20.10.2:/home/run/
```

## 三、机器人解包和校验

登录机器人：

```powershell
ssh run@机器人IP
```

在机器人终端执行：

```bash
cd /home/run
sha256sum -c sparkrobot-lingxi-kb-1.0.10-20261023.zip.sha256
rm -rf sparkrobot-lingxi-kb-1.0.10-20261023
python3 -m zipfile -e sparkrobot-lingxi-kb-1.0.10-20261023.zip /home/run
chmod +x install.sh install_voice_agent.sh control.sh service/*
```

看到 `OK` 才继续安装。如果校验失败，不要继续执行安装，重新上传 ZIP 和 SHA-256 文件。

## 四、安装并复用现有灵心配置

在安装包目录执行：

```bash
cd /home/run/sparkrobot-lingxi-kb-1.0.10-20261023
sudo ./install.sh --from-lingxi
sudo ./install_voice_agent.sh
```

如果安装器无法自动识别智能体 Code，手动指定：

```bash
sudo ./install.sh --from-lingxi --agent-code AI_AGENT_你的智能体Code
```

第一条安装命令会完成以下工作：

1. 将程序安装到 `/opt/sparkrobot/lingxi-kb/`。
2. 将独立知识库配置写入 `/etc/sparkrobot/lingxi-kb/retriever.env`。
3. 创建 `sparkrobot-lingxi-kb.service`。
4. 设置开机自启动。
5. 启动本机 `127.0.0.1:18084` 服务。

第二条命令会完成以下工作：

1. 校验包内 Java Agent JAR。
2. 备份当前 `/opt/sparkrobot/lingxi-nav/current/java/robot-local-navigation-java-all.jar`。
3. 安装包含知识库检索逻辑的新 Java Agent。
4. 只重启 `lingxi-java-agent-robot.service`。

知识库密钥不会写入安装包和日志，配置权限为 `run:run 0600`。语音接入不会修改 `/etc/sparkrobot/lingxi-nav/lingxi-nav.properties`。

## 五、语音交互降噪与拒识策略

1.0.9-20261023 的 Java Agent 集成 V1.3.8 输入门控，并增加流式 TTS 会话所有权保护。它过滤填充词、重复 ASR 片段、播报回声及静音窗口中未唤醒的输入；常见短控制词不会因长度短而统一丢弃。

唤醒门控默认为 `enforce`：需由 SDK KWS 元数据、SDK listening/wakeup 状态回调，或 event ID 与新鲜度均核验通过的 SOC2 记录提供真实唤醒证据。唤醒证据有效期默认 8 秒，接受请求后会开启/延长 8 秒连续对话窗口；纯 ASR 文本包含唤醒词不算真实唤醒证据。识别到的急停文本在普通拒识之前处理，但这不替代机器人实体急停按钮。

SDK 可提供声学质量元数据时，默认阈值为：DOA 正前方半角 60°、SNR 至少 6 dB、AEC 残余回声 RMS 不高于 0.12、VAD 语音概率至少 0.70、ASR 置信度至少 0.65。默认 `voice.gate.metadataRequired=false`，缺失元数据兼容放行，但已提供的异常、冲突或不达标字段仍会拒识。只有确认 SDK 确实提供并完成现场标定后，才设置 `voice.gate.metadataRequired=true`；严格模式会拒绝缺失必要质量字段的输入。

可选参数写入 Java Agent 工作目录中的 `config/lingxi-nav.properties`，或使用同名 `VOICE_GATE_*` 环境变量。修改前先确认服务工作目录：

```bash
sudo systemctl show -p WorkingDirectory --value lingxi-java-agent-robot.service
```

不要因为属性名称中有 DOA、AEC、RNNoise 或 VAD，就认为已启用硬件算法。此版本只消费 SDK 上报的元数据并实施文本/会话门控；没有把 RNNoise、AEC、DOA 处理链或 PCM 降噪器接入音频链路。验收需由现场人员在安全条件下完成，离线 Java 测试不代表真实麦克风声学效果。

排查策略决定时查看 `lingxi-java-agent-robot.service` 日志中的 `Text ignored by quality gate`、`Text ignored by wake gate`、`Wake state` 和 `SOC2 wake evidence`。若升级后需要回滚，只恢复旧 Java Agent JAR：

```bash
sudo ./install_voice_agent.sh --rollback /var/lib/sparkrobot/lingxi-kb/agent-backups/robot-local-navigation-java-all.实际备份文件名.jar
```

## 六、回答速度与事实约束

1.0.10-20261023 修正了普通问答提示边界。文本 ASR 普通聊天复用首轮大模型意图解析的最终 `reply`，仅在首轮答复为空时调用聊天兜底。身份、日期、时间和简单文本寒暄仍走确定性答复。

普通常识、科学原理、语言、历史、观点和开放问题使用模型已有知识正常回答；不要因为当前上下文或知识库没有提供常识答案而拒答。“为什么天空是蓝色的？”和“什么是机器人？”等普通问题不因宽泛主题词自动要求知识库。

只有本机机器人专属状态/能力、具体场馆/企业/地点资料和实时信息才要求知识库依据。关闭 rerank/QA 前置检查，超时为 1.2 秒，最低相关度分数为 0.60。命中时使用检索答案；未命中、低分或超时则明确说无法核实，不猜测现场事实。使用模型已有知识回答常识，不代表联网搜索或实时核验。

文本识别结果中的明确导航命令，会尝试与当前活动地图的完整语音点位名称/别名精确匹配；命中时跳过一次意图模型请求，并仍由导航 bridge 复核目标。未知地点、部分匹配、问句、否定、条件或引用表达回到既有模型路径。同一语音别名映射到多个活动地图点位时，机器人只追问具体目标，不会提交导航。

明确的文本停止导航/停止讲解命令会在意图模型调用前本地分流；语音输入仍必须先走现有音频转写回调，不能据此认为原始音频不再发送到已配置的模型端点。转写得到的停止命令随后走同一停止分流。

本地/实时事实问题在意图解析期间并行启动知识库检索。检索执行器最多使用 2 个线程和 4 个排队位；队列满时记录回退并在意图解析完成后串行检索，线程数不会随请求量无限增长。并行只重叠两段等待，不保证固定的端到端提速。

若 ASR 质量门控报告置信度过低，普通命令（包括开始/继续讲解）不会执行；当 Java Agent 配置为机器人 TTS 时会请求重说提示。明确停止命令优先通过该拒识门控。此机制仅消费现有 SDK/ASR 元数据，不会在端侧重新识别原始音频。

原始音频仍先调用当前配置的转写/意图模型，随后才尝试同一精确点位匹配。本版不包含端侧离线 ASR，不保证原始音频不发送到云端，也没有改动现有 800 ms TTS 等待。

流式模型回复和有序 TTS 分段已作为可选能力加入，但 `doubao.streamingReplies` 默认 `false`，不改变现有行为或 800 ms 播报等待。只有普通文本闲聊、机器人 TTS 模式且非固定对话测试时才可能进入该路径；事实核实、身份/日期/时间问题、导航、任务控制、动作和原始音频不使用流式回复。默认保持关闭，直到目标机器人完成 AIMDK PlayTts 连续分段排队、打断和恢复验收。

若现场明确选择试用，先用 `sudo systemctl show -p WorkingDirectory --value lingxi-java-agent-robot.service` 确认 Java Agent 工作目录，再备份并编辑该目录下 `config/lingxi-nav.properties`，增加 `doubao.streamingReplies=true`，然后重启 `lingxi-java-agent-robot.service`。先在安全环境测试普通闲聊、模型 503、流中断、TTS 第二段拒绝、下一轮语音输入和既有导航/讲解；出现队列错序、重复播报或打断异常时恢复 `false` 并重启服务。构建机假 HTTP 服务测试不能替代机器人实机声学与 AIMDK 队列验收。

开启后首段采用 interrupt，其余分段按序提交且不打断前段；模型在首段播报前失败时回退到非流式请求，首段播出后模型流中断则播报简短中断提示。续段失败时只有会话仍拥有 TTS 决策权，才会用完整最终答复替换部分播报；新的普通回复也可取得 owner 并抢占旧流的软件会话，旧会话随后不会再提交后续段或回退完整答复。

机器人桥在 PlayTts 服务等待结束后、调用 `call_async` 前会再次原子校验流代次。停止或抢占先于提交时，旧段会被拦截；已调用 `call_async` 提交到 PlayTts 的请求，本桥接层不具备撤回或停止能力。`stream_action=end` 仅关闭软件流状态，不代表取消已排队或正在播放的机器人语音。Java 决策 token 保护收尾状态，避免旧会话释放或覆盖新播报状态。以上是软件并发验证，不能替代目标机器人 AIMDK PlayTts 队列与声学验收。

排查延迟时，用同一 `eventId` 对齐 Java Agent 日志中的 `audio task started`、`Audio request parsed by Doubao`、`Doubao request completed`、`Knowledge lookup finished`、`Text chat answer source` 和 `Robot TTS dispatch timing`。队列等待、模型往返、知识检索或 TTS 桥接各自的耗时可据此区分。

### 语音预置动作

Java Agent 支持挥手、握手、举手、飞吻、比心、击掌、敬礼、平举、拥抱、加油、鼓掌、双手打叉、胸前挥手、鞠躬、拜拜、动感光波、挠头和抓屁股。示例口令：“请和我握个手”“请双手比心”。只有导航空闲且没有进行或暂停中的讲解任务时才会提交；问句、否定、引用/转述、条件表达和直播弹幕不触发。

回复“已受理/已提交”只说明请求进入动作服务，不代表动作执行完成。要启用完整动作链路，还需安装导航增量包 `sparkrobot-lingxi-consecutive-nav-fix-1.0.5-20261023`；完整包会按既定顺序同时安装两端组件。单独安装本知识库包不会改动导航服务。

检查知识库服务：

```bash
sudo systemctl is-active sparkrobot-lingxi-kb.service
curl -fsS http://127.0.0.1:18084/health
sudo /usr/local/sbin/sparkrobot-lingxi-kb doctor

```

正常健康检查类似：

```json
{"ok": true, "service": "sparkrobot-lingxi-kb", "agent_code_configured": true}
```

```bash
systemctl is-active lingxi-nav-console.service
systemctl is-active lingxi-java-agent-robot.service
```

## 七、执行知识库检索

### 方式一：命令行

```bash
kb-search "机器人介绍" --top-k 5
```

返回 `code=0`、`success=true` 表示灵心接口调用成功。`data=[]` 表示请求成功但当前问题没有命中知识库内容，不是服务故障。

### 方式二：本机 HTTP 接口

```bash
curl -X POST http://127.0.0.1:18084/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"机器人介绍","top_k":5}'
```

请求字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `query` | 是 | 检索问题，不能为空 |
| `top_k` | 否 | 返回数量，范围 1 到 50，默认 10 |
| `rerank` | 否 | 是否重排，默认 `true` |
| `check_qa_first` | 否 | 是否优先检索问答，默认 `true` |
| `score_threshold` | 否 | 分数阈值，默认 `0` |

服务端始终使用安装时配置的 Agent Code，不接受客户端覆盖，避免检索到其他智能体的知识库。

## 八、返回结果说明

灵心返回结果中通常包含：

- `doc_id`：文档 ID。
- `filename`：文件名。
- `question`、`answer`：问答型知识内容。
- `content`：知识切片正文。
- `content_type`：`qa` 或 `knowledge`。
- `score`：匹配分数。
- `metadata`：安全性、语言、标签等元数据。

独立服务只负责检索和返回结果。完成 `install_voice_agent.sh` 后，Java Agent 会在普通问答中按“本地问答 -> 灵心知识库 -> 大模型”顺序处理，并将命中的知识库答案提交到机器人 TTS。导航和讲解任务流程不改变。

## 十、故障排查

### 1. `./install.sh: Permission denied` 或找不到命令

ZIP 解包后先执行：

```bash
cd /home/run/sparkrobot-lingxi-kb-1.0.10-20261023
chmod +x install.sh control.sh service/*
```

### 2. `无法从现有灵犀配置得到`

确认原配置存在：

```bash
sudo test -f /etc/sparkrobot/lingxi-nav/lingxi-nav.properties && echo 配置存在
sudo grep -E '^(lingxi\.appId|lingxi\.appKey|lingxi\.appSecret)=' /etc/sparkrobot/lingxi-nav/lingxi-nav.properties
```

如果只是缺少智能体 Code，可手动指定：

```bash
sudo ./install.sh --from-lingxi --agent-code AI_AGENT_你的智能体Code
```

### 3. 健康检查正常，但检索返回 `502`

检查机器人是否可以访问灵心平台：

```bash
python3 -c "import urllib.request; print(urllib.request.urlopen('https://open.agibot.com', timeout=10).status)"
```

再查看服务日志：

```bash
sudo journalctl -u sparkrobot-lingxi-kb.service -n 100 --no-pager
```

### 4. 返回 `code` 非 0

通常是 AppId、AppKey、AppSecret、智能体 Code 不匹配，或灵心平台应用没有访问该智能体知识库的权限。不要修改导航语音配置，重新确认灵心平台配置后重新安装：

```bash
sudo ./install.sh --from-lingxi --agent-code AI_AGENT_正确的智能体Code
```

### 5. 返回 `code=0` 但 `data=[]`

这是接口成功但没有命中内容。请确认：

- 知识库已经上传并完成索引。
- 知识库已经关联到当前 Agent Code。
- 查询词与知识库内容相关。
- `score_threshold` 没有设置得过高。

### 6. 知识库接口成功，但机器人仍只回答普通大模型内容

确认已经安装包内的语音接入更新，而不只是安装知识库服务：

```bash
sudo systemctl is-active sparkrobot-lingxi-kb.service
sudo systemctl is-active lingxi-java-agent-robot.service
sudo journalctl -u sparkrobot-lingxi-kb.service -u lingxi-java-agent-robot.service -f
```

现场提问后应同时看到 `POST /search 200`、`Knowledge base answer selected` 和 `Audio2Tts final`。如果没有 `POST /search`，说明 Java Agent 仍是旧版本，需要重新执行：

```bash
cd /home/run/sparkrobot-lingxi-kb-1.0.10-20261023
sudo ./install_voice_agent.sh
```

## 十一、卸载

卸载服务和程序，但保留配置和日志：

```bash
sudo systemctl disable --now sparkrobot-lingxi-kb.service
sudo rm -f /etc/systemd/system/sparkrobot-lingxi-kb.service
sudo rm -f /usr/local/sbin/sparkrobot-lingxi-kb /usr/local/bin/kb-search
sudo systemctl daemon-reload
sudo rm -rf /opt/sparkrobot/lingxi-kb
```

也可以使用包内控制命令：

```bash
sudo /usr/local/sbin/sparkrobot-lingxi-kb uninstall
```

如需同时删除知识库密钥和日志，确认后再执行：

```bash
sudo rm -rf /etc/sparkrobot/lingxi-kb /var/lib/sparkrobot/lingxi-kb /var/log/sparkrobot/lingxi-kb
```
