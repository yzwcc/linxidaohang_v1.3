# 20 秒无人交互自动回起点设计

本文档描述当前实现后的逻辑：用户导航完成或中途停止后，如果没有新的有效用户交互，机器人会在合适时机自动回到当前地图的 `is_start=true` 点位。

## 当前实现结论

1. 自动回起点状态机放在 PythonBridge 的 `robot_local_navigation_v3/lingxi_nav_bridge.py`。
2. Java 只负责在确认真实用户 ASR 后调用 `POST /interaction/mark`，以及继续调用 `/nav/start`、`/nav/stop`、`/tts/speak`。
3. 机器人自己的 `/tts/speak` 不算有效交互，不会刷新 20 秒计时。
4. 用户导航到达目标点后不会立刻开始 20 秒计时，而是先进入 `arrival_action`，等待到点动作/TTS 的配置或估算时长结束，再进入 `waiting_auto_return`。
5. 导航失败或超时不会自动回起点，会本地 TTS 提醒用户检查通道、定位或重新指定目标。

## 状态机

PythonBridge 维护这些状态：

```text
idle
  当前没有用户导航、到点动作等待或自动回起点任务。

navigating_user_target
  正在执行用户发起的导航任务。

arrival_action
  用户目标已经到达，正在执行或等待到点动作/TTS 完成。

waiting_auto_return
  到点动作/TTS 已结束，正在等待 20 秒无人交互窗口。

returning_home
  20 秒无人交互已满足，正在自动导航回当前地图的 is_start 点。
```

核心流转：

```text
/nav/start 用户目标
  -> navigating_user_target

用户目标 completed
  -> arrival_action
  -> 到点动作/TTS 等待结束
  -> waiting_auto_return
  -> 20 秒内无有效交互
  -> returning_home
  -> 回起点 completed
  -> idle

/nav/stop 用户停止
  -> waiting_auto_return
  -> 20 秒内无有效交互
  -> returning_home
  -> 回起点 completed
  -> idle

/interaction/mark 新交互
  -> 取消 arrival_action 或 waiting_auto_return
  -> 如果正在 returning_home，则取消回起点导航
  -> idle 或进入新的用户导航
```

## 到点 TTS 和 20 秒计时

到点 TTS 属于机器人输出，不属于用户交互。

当前实现不会把到点 TTS 播报时间算进用户的 20 秒等待窗口。用户目标完成后，PythonBridge 会：

```text
NavigationEventType.COMPLETED
-> Auto return state: arrival_action
-> 执行 business.on_arrival 动作
-> 等待动作/TTS 的配置或估算时长
-> Auto return wait started ... idle_sec=20.0
```

到点动作的等待时长按以下字段读取，优先级相同，取动作里的显式配置：

```json
{
  "type": "tts",
  "text": "已到达A点",
  "auto_return_wait_sec": 5
}
```

支持字段：

```text
auto_return_wait_sec
wait_sec
duration_sec
expected_duration_sec
```

如果 TTS 没有配置等待时间，PythonBridge 会按文本长度估算，范围是 2 到 45 秒：

```python
min(45.0, max(2.0, compact_len / 4.0 + 0.8))
```

## 有效交互定义

有效交互只代表用户主动输入：

1. Java 收到真实用户 ASR final，并且没有被 TTS 静默窗口过滤。
2. 用户发起新导航。
3. 用户停止导航。
4. 用户普通闲聊，但确认是用户主动说话。

这些不会算作有效交互：

```text
/tts/speak
到点 TTS
导航失败提示 TTS
自动回起点失败提示 TTS
机器人自己播报被 ASR 回收的回声
```

Java 在确认用户输入后调用：

```text
POST /interaction/mark
```

请求示例：

```json
{
  "event_id": "event_xxx",
  "source": "audio_asr_final",
  "intent": "chat|navigate|stop_navigation"
}
```

PythonBridge 收到后：

```text
更新 last_valid_interaction_at
如果当前是 arrival_action 或 waiting_auto_return，取消本次自动回起点流程
如果当前是 returning_home，取消回起点导航
```

## 不自动回起点的情况

这些情况会跳过自动回起点：

1. 当前地图没有 `is_start=true` 点位。
2. 当前目标点本身就是 `is_start=true`。
3. 当前还在执行用户导航。
4. 当前已经在执行自动回起点。
5. 用户导航失败或超时。
6. 20 秒内用户又说了新的有效指令。
7. 等待期间切换地图或重载点位。

失败和超时不自动回起点，是因为这通常意味着通道、定位、地图或底盘状态有问题，继续自动发导航命令不安全。

## 失败和超时播报

用户导航失败或超时时，PythonBridge 会通过本地 TTS 播报：

```text
当前路线暂时无法到达，我先停止导航，请帮我清理通道或重新指定目标。
```

自动回起点过程中失败或超时时，会播报：

```text
自动回起点失败，请检查通道、定位或底盘状态。
```

这些 TTS 仍然是机器人输出，不会调用 `/interaction/mark`，也不会刷新 20 秒计时。
